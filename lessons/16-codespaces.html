Codespaces: компьютер в облаке

github.dev — редактор без терминала. Codespaces — тот же редактор плюс настоящий компьютер, который GitHub выдаёт вам на время работы: с терминалом, возможностью запускать код и устанавливать что угодно — внутри него, а не у вас. Через десять минут вы сделаете коммит из терминала и выключите машину.

Что это и зачем

Codespace — виртуальная машина (компьютер, живущий на серверах GitHub) с уже установленным VS Code, терминалом и копией вашего репозитория. Вы открываете её во вкладке браузера, работаете, закрываете. На вашем компьютере не остаётся ничего: ни программ, ни файлов.

Зачем это не-программисту? Во-первых, инструменты, которые напишут для вас агенты, иногда нужно запустить и посмотреть, — для этого нужен терминал. Во-вторых, когда агент из модуля 6 скажет «выполните команду», у вас будет где её выполнить, не ставя ничего на рабочий ноутбук. В-третьих, внутри Codespaces уже есть ИИ-помощник, который может делать правки за вас, — об этом ниже.

На главной странице репозитория hello-ai нажмите зелёную кнопку Code. В выпавшей панели перейдите на вкладку Codespaces (вторая вкладка панели — для работы на своём компьютере, она нам не нужна).

Create codespace on main

Нажмите Create codespace on main — «создать codespace на ветке main». Появится экран подготовки: GitHub создаёт виртуальную машину, ставит на неё VS Code и копирует репозиторий. Это занимает 1–2 минуты; не закрывайте страницу.

Интерфейс — тот же VS Code из урока 15, с одним важным дополнением: внизу панель с вкладкой TERMINAL. Это командная строка виртуальной машины. В ней мигает курсор после приглашения, которое заканчивается знаком $.

EXPLORER
HELLO-AI
  README.md
  index.html
  notes.md

Редактор: откройте файл слева

TERMINAL

$ ▌

Если панели с терминалом нет — откройте её через меню редактора: Terminal → New Terminal.

Щёлкните в терминал, введите ls и нажмите Enter. Команда показывает содержимое текущей папки — а это ваш репозиторий.

$ ls
README.md index.html notes.md
# те же файлы, что на github.com: это копия репозитория внутри машины

В Explorer откройте index.html, добавьте в список строку <li>Сделал(а) коммит из облачного терминала</li> и сохраните: Ctrl+S. В терминале введите git status — git перечислит изменённые файлы.

$ git status
On branch main
Changes not staged for commit:
modified: index.html
# «изменён, но ещё не подготовлен к коммиту»

Два равноценных способа. Выберите любой — результат один.

Как в уроке 15: иконка Source Control слева → + у index.html → сообщение Добавить пункт про облачный терминал → кнопка Commit. В Codespaces коммит не уходит на GitHub сам: после коммита на месте кнопки появится кнопка синхронизации (Sync Changes) — нажмите её, чтобы отправить коммит в репозиторий.

Три команды, по одной на строку, после каждой — Enter:

$ git add .
# подготовить все изменённые файлы (точка — «всё в этой папке»)
$ git commit -m "Добавить пункт про облачный терминал"
# создать коммит с сообщением в кавычках
$ git push
# отправить коммит на GitHub

Если git push напечатал несколько строк и вернул приглашение $ без слова error — всё получилось.

Откройте github.com/ваш-username/hello-ai в другой вкладке: счётчик коммитов вырос, у index.html — ваше сообщение. Через несколько минут строка появится на сайте.

Машина работает и тратит ваши бесплатные часы, пока запущена. Закрыть вкладку недостаточно — сама она остановится только через 30 минут простоя. Остановите вручную: откройте github.com/codespaces, найдите свой codespace, нажмите … справа от него → Stop codespace.

Delete — когда codespace больше не нужен

Остановленный codespace сохраняет ваши файлы, и его можно запустить снова через ту же кнопку Code → Codespaces. Когда он точно не нужен — удалите (Delete), чтобы не занимать хранилище. Репозиторий на GitHub от этого не пострадает.

Лимиты и деньги

Бесплатный личный аккаунт включает 120 core-часов Codespaces в месяц и 15 ГБ хранилища. Core-час — час работы одного ядра процессора; стандартная машина двухъядерная, поэтому 120 core-часов — это 60 часов работы в месяц. На курс уйдёт часа три, на регулярную работу с агентами — 10–20 часов в месяц. Лимита хватает, если соблюдать два правила.

Часы тратятся, пока машина запущена

Не пока вы печатаете, а пока codespace работает. Ушли на обед — остановите его. Забыли — он выключится сам через 30 минут без активности, но эти полчаса будут потрачены.

Хранилище тратится, пока codespace существует

Остановленный codespace часов не ест, но занимает место из 15 ГБ. Закончили проект — удалите его (Delete). Всё, что закоммичено и отправлено на GitHub, останется в репозитории.

Три команды терминала, которых достаточно

Терминал — тот же проводник, только текстом: вы пишете, что сделать, он отвечает. Запомнить нужно три команды. Остальные за вас напишет ИИ, когда понадобятся.

КомандаЧто делаетКогда нужна
lsПоказывает файлы и папки там, где вы сейчас находитесьУбедиться, что файл на месте и называется правильно
cat index.htmlПечатает содержимое файла прямо в терминалБыстро заглянуть в файл, не открывая его в редакторе; скопировать текст в чат с ИИ
git statusПоказывает, какие файлы изменены и что ещё не закоммиченоПеред коммитом и когда непонятно, «а сохранилось ли»

Всё остальное — установить программу, запустить инструмент, который написал агент, заменить текст во всех файлах — попросите написать ИИ. Хороший запрос выглядит так:

Запрос к ИИ
Я работаю в терминале GitHub Codespaces (Linux), в папке своего репозитория с файлами index.html, README.md и notes.md. Я не программист.
Задача: найти во всех файлах репозитория название «ООО Ромашка» и заменить его на «ООО Василёк».
Дай команду или несколько команд, по одной на строку, и к каждой пояснение в одну строку: что она делает и что я увижу на экране. Если команда что-то удаляет или перезаписывает — предупреди отдельно, до самой команды.

Правило безопасности. Не вставляйте в терминал команды, смысла которых не понимаете, — сначала попросите ИИ объяснить. Сломать свой компьютер из Codespaces невозможно, но можно потерять незакоммиченные правки. Что закоммичено и отправлено на GitHub — в безопасности.

Внутри уже есть Copilot. В Codespaces встроен GitHub Copilot. На бесплатном Copilot Free доступны чат с ИИ по вашим файлам и agent mode — режим, в котором ИИ сам правит файлы и запускает команды, спрашивая вашего подтверждения. Это ваш первый ИИ-агент, и он уже здесь. Подробно — в модуле 6.

Проверьте себя

Чем Codespaces отличается от github.dev?

  • Только оформлением: это один и тот же редактор
  • В Codespaces есть виртуальная машина с терминалом — можно запускать код и устанавливать программы внутри неё
  • Codespaces работает без интернета, а github.dev — нет

Редактор одинаковый. Разница — в компьютере за ним: у github.dev его нет, у Codespaces есть, поэтому там работает терминал.

Сколько часов работы на двухъядерной машине даёт бесплатный лимит 120 core-часов в месяц?

  • 120 часов
  • 240 часов
  • 60 часов

Core-час — час одного ядра. Два ядра тратят два core-часа за час работы: 120 / 2 = 60.

Вы закрыли вкладку с codespace и ушли. Что происходит с бесплатными часами?

  • Машина продолжает работать до 30 минут простоя, затем остановится сама; надёжнее остановить её вручную
  • Машина остановилась мгновенно при закрытии вкладки
  • Машина будет работать до конца месяца

Закрытие вкладки не останавливает машину. Привычка: закончили — github.com/codespaces → … → Stop codespace.

Вы выполнили в терминале git add . и git commit -m "…", но на github.com изменений нет. Что забыли?

  • Выполнить git status
  • Выполнить git push — отправить коммит на GitHub
  • Перезапустить codespace

Коммит в Codespaces создаётся внутри виртуальной машины. На GitHub он попадает только после git push (или кнопки синхронизации в Source Control).

Практика

Пройдите цикл целиком: создать, поработать в терминале, закоммитить, остановить.

  • Создал(а) codespace для hello-ai, вижу редактор и панель TERMINAL.
  • Команда ls показала файлы репозитория, cat README.md напечатала текст README.
  • Изменил(а) index.html и отправил(а) коммит на GitHub — из терминала (git add ., git commit -m, git push) или через Source Control с синхронизацией.
  • На github.com в истории есть этот коммит с моим сообщением.
  • Остановил(а) codespace на github.com/codespaces и знаю, где кнопка Delete.

У вас есть компьютер в облаке. Редактор, терминал и место, где можно запускать всё, что напишут агенты, — и ничего на вашем ноутбуке. Следующий урок — ветки и pull request на симуляторе: без риска для настоящего репозитория.

Проверить PR и оставить замечания

Агент прислал pull request с новым README. Код читать не нужно — нужно принять работу как у помощника: сверить с первоисточником, отметить ошибки, утвердить или вернуть. Разберём на PR из урока 15.

Что вы проверяете на самом деле

Ревью отвечает на три вопроса: сделано ли то, что просили; не задето ли лишнее; нет ли опасного. Для PR по контенту все три решаются без программирования: результат — таблица в README, которую вы читаете как маркетолог; «лишнее» видно по списку файлов; «опасное» — по красным флагам ниже. Ваше преимущество — вы знаете свои посты; агент не знает, что «29 октября» в тексте письма — дата выхода статьи в блоге, а не дата рассылки.

Как замечание дойдёт до агента

Вернитесь в сессию на claude.ai/code — она живёт и после создания PR — и напишите замечание в чат. Агент внесёт правку новым коммитом в ту же ветку, PR обновится сам; заснувшая сессия проснётся от сообщения.

Откройте ту же задачу на chatgpt.com/codex, напишите замечание в ней и попросите внести правку в pull request: в старой задаче уже есть весь контекст.

Облачный агент Copilot читает комментарии PR сам: оставьте замечания к строкам или в Conversation и ждите новых коммитов в том же PR.

Три готовых запроса

Запрос к агенту — откуда значения
Объясни, что ты изменил в этом pull request и откуда взял каждое значение: для каждой строки таблицы в README — файл поста и строка шапки или цитата, из которых взяты площадка, дата, цель и отметка про UTM-метку. Где в файле данных нет — так и напиши.
Запрос к агенту — самопроверка
Проверь сам свой pull request как придирчивый редактор: где ты додумал, обобщил или взял значение не из файла? Для каждого такого места укажи строку таблицы, что написано и что в посте на самом деле. Исправь и перечисли, что исправил.
Запрос к агенту — точечная правка
Исправь только строку про анонс вебинара (posts/anons-vebinara.md): площадка и дата — дословно из шапки поста; если в шапке их нет — «не указано». Остальные строки таблицы и другие файлы не трогай.

Чеклист ревью

Шесть пунктов на любой PR по контенту.

  • Ничего из posts/ не изменено: в Files changed только файлы, разрешённые в ТЗ.
  • Данные только из файлов: площадки, даты и отметки про UTM сверены минимум по двум постам; где в файле пусто — «не указано».
  • Нет названий клиентов, бюджетов и цифр, которых не было в файлах.
  • Нет внешних сервисов и отправки текстов куда-либо — ни в описании PR, ни в ответах агента.
  • Описание PR понятное: что прочитано, что непонятно, что изменилось.
  • Есть, как проверить: агент написал, как убедиться в результате за несколько минут, и я это сделал.

Красные флаги

Не сливайте, пока агент не уберёт причину; настаивает — Close pull request и новое ТЗ.

  • Агент предлагает отправить тексты во внешний сервис — «прогоним посты через онлайн-проверку уникальности». Посты и выгрузки не покидают репозиторий и машину агента.
  • Агент удаляет или переименовывает файлы, которых не было в ТЗ, — особенно в posts/.
  • Агент пишет: «файлы открыть не удалось, таблицу заполнил по названиям». Это выдумка: имя вроде anons-vebinara.md подсказывает тему, но не площадку, дату и цель — пусть прочитает каждый пост, либо ставит «не указано» по всем полям.

Проверьте себя

В Files changed кроме README.md тронут posts/post-keis.md: агент «поправил опечатку». Что делать?

  • Не сливать: попросить вернуть пост в исходный вид — posts/ агент не трогает
  • Слить: опечатка исправлена, это полезно
  • Слить, но написать агенту замечание на будущее

Посты — первоисточник: текст согласован, его меняет только человек. Любое изменение в posts/ — замечание до слияния.

В таблице у поста стоит дата, а в шапке поста даты нет. Какое замечание верное?

  • «Проверь дату»
  • «В шапке даты нет — поставь „не указано“. Данные только из файлов»
  • «Возьми дату вебинара из текста поста»

Замечание говорит, что не так и как должно быть. Дата события из текста — тоже додумка: это не дата публикации.

PR сделал Claude Code. Как доставить агенту замечание, чтобы он исправил?

  • Нажать Merge pull request — агент сам увидит и исправит
  • Только новой задачей в новой сессии
  • Написать в чат той же сессии на claude.ai/code — правка придёт в тот же PR

Сессия живёт после создания PR. Merge ничего не исправляет, новая сессия не знает контекста.

В описании PR: «Файлы в posts/ открыть не удалось, таблица заполнена по названиям файлов». Что делать?

  • Слить: названия файлов обычно отражают содержание
  • Не сливать: данные выдуманы; попросить агента прочитать посты по-настоящему и заполнить таблицу из файлов
  • Удалить посты из репозитория и загрузить заново

Правдоподобная таблица без источника — красный флаг. Посты — обычные текстовые файлы, агент может их прочитать и взять данные из шапок.

Практика

Откройте PR из урока 15 или 16 — слитый тоже подойдёт. Проведите ревью по чеклисту и отправьте агенту хотя бы одно замечание или один из трёх запросов.

  • Files changed открыт: в списке только README.md — либо лишние файлы записаны как замечание.
  • Таблица сверена минимум с двумя постами; каждое расхождение — замечание к строке.
  • Все шесть пунктов чеклиста ревью пройдены по этому PR.
  • Агенту отправлено хотя бы одно замечание или запрос «откуда значения» — и ответ понятен.
  • Решение принято: Merge pull request → Confirm merge → Delete branch, либо Close pull request с понятной причиной.

Вы приняли первую работу агента как заказчик. Пять минут по чеклисту закрывают основные риски. Следующий урок — что делать, когда агент сделал не то.

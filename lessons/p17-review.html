Проверить PR и оставить замечания

Агент прислал pull request с новым README. Код читать не нужно — нужно принять работу как у помощника: сверить с первоисточником, отметить ошибки, утвердить или вернуть. Разберём на PR из урока 15.

Что вы проверяете на самом деле

Ревью отвечает на три вопроса: сделано ли то, что просили; не задето ли лишнее; нет ли опасного. Для PR по карточкам товаров все три решаются без программирования: результат — таблица в README, которую вы читаете как менеджер маркетплейса; «лишнее» видно по списку файлов; «опасное» — по красным флагам ниже. Ваше преимущество — вы знаете свои товары: агент не знает, что пустая строка «Остаток» означает «не указано», а зачёркнутая цена в карточке — это цена до скидки, а не цена.

Как замечание дойдёт до агента

Вернитесь в сессию на claude.ai/code — она живёт и после создания PR — и напишите замечание в чат. Агент внесёт правку новым коммитом в ту же ветку, PR обновится сам; заснувшая сессия проснётся от сообщения.

Откройте ту же задачу на chatgpt.com/codex, напишите замечание в ней и попросите внести правку в pull request: в старой задаче уже есть весь контекст.

Облачный агент Copilot читает комментарии PR сам: оставьте замечания к строкам или в Conversation и ждите новых коммитов в том же PR.

Три готовых запроса

Запрос к агенту — откуда значения
Объясни, что ты изменил в этом pull request и откуда взял каждое значение: для каждой строки таблицы в README — файл карточки и цитата, из которой взяты название, цена и остаток, и строки otzyvy.csv, по которым посчитаны число отзывов и средняя оценка. Где в файлах данных нет — так и напиши.
Запрос к агенту — самопроверка
Проверь сам свой pull request как придирчивый владелец магазина: где ты додумал, округлил или взял значение не из файлов репозитория? Для каждого такого места укажи строку таблицы, что написано и что в карточке или в otzyvy.csv на самом деле. Исправь и перечисли, что исправил.
Запрос к агенту — точечная правка
Исправь только строку про термокружку (tovary/termokruzhka.md): цена и остаток — дословно из карточки; число отзывов и среднюю оценку пересчитай по строкам otzyvy/otzyvy.csv про этот товар; чего в файлах нет — «не указано». Остальные строки таблицы и другие файлы не трогай.

Чеклист ревью

Шесть пунктов на любой PR по карточкам и отзывам.

  • Ничего из tovary/ и otzyvy/ не изменено: в Files changed только файлы, разрешённые в ТЗ.
  • Данные только из файлов: цены и остатки сверены минимум по двум карточкам, отзывы и оценки — по otzyvy.csv; где в файлах пусто — «не указано».
  • Нет свойств и обещаний, которых нет в карточках: ни «держит тепло 12 часов», ни гарантий и сроков возврата из ниоткуда.
  • Нет внешних сервисов и отправки файлов куда-либо — ни в описании PR, ни в ответах агента.
  • Описание PR понятное: что прочитано, что непонятно, что изменилось.
  • Есть, как проверить: агент написал, как убедиться в результате за несколько минут, и я это сделал.

Красные флаги

Не сливайте, пока агент не уберёт причину; настаивает — Close pull request и новое ТЗ.

  • Агент предлагает отправить файлы во внешний сервис — «загрузим отзывы в онлайн-таблицу». Карточки и отзывы не покидают репозиторий и машину агента.
  • Агент удаляет или переименовывает файлы, которых не было в ТЗ, — особенно в tovary/.
  • Агент пишет данные без источника: приписал термокружке «держит тепло 12 часов», хотя в карточке этого нет, или «otzyvy.csv разобрать не удалось, оценки проставил примерно». Это выдумка: пусть прочитает файлы по-настоящему и пересчитает по строкам — либо ставит «не указано».

Проверьте себя

В Files changed кроме README.md тронут tovary/termokruzhka.md: агент «поправил опечатку». Что делать?

  • Слить: опечатка исправлена, это полезно
  • Слить, но написать агенту замечание на будущее
  • Не сливать: попросить вернуть карточку в исходный вид — tovary/ агент не трогает

Карточки — первоисточник: их текст вы переносите в кабинет площадки, поэтому меняет их только человек. Любое изменение в tovary/ — замечание до слияния.

В таблице у лампы стоит остаток 42, а в карточке остаток не указан вовсе. Какое замечание верное?

  • «Остатка в карточке лампы нет — поставь „не указано“. Данные только из файлов репозитория»
  • «Проверь остаток»
  • «Возьми остаток из кабинета маркетплейса»

Замечание говорит, что не так и как должно быть. Кабинет площадки агент не видит — у него есть только файлы репозитория.

PR сделал Claude Code. Как доставить агенту замечание, чтобы он исправил?

  • Нажать Merge pull request — агент сам увидит и исправит
  • Написать в чат той же сессии на claude.ai/code — правка придёт в тот же PR
  • Только новой задачей в новой сессии

Сессия живёт после создания PR. Merge ничего не исправляет, новая сессия не знает контекста.

В описании PR: «Разобрать otzyvy.csv не удалось, число отзывов и оценки проставил примерно по текстам карточек». Что делать?

  • Слить: примерные оценки лучше, чем пустые столбцы
  • Не сливать: данные выдуманы; попросить агента прочитать otzyvy.csv по-настоящему и пересчитать по строкам
  • Удалить otzyvy.csv из репозитория

Правдоподобные числа без источника — красный флаг. CSV — обычный текстовый файл, агент умеет его читать; пусть пересчитает.

Практика

Откройте PR из урока 15 или 16 — слитый тоже подойдёт. Проведите ревью по чеклисту и отправьте агенту хотя бы одно замечание или один из трёх запросов.

  • Files changed открыт: в списке только README.md — либо лишние файлы записаны как замечание.
  • Таблица сверена минимум с двумя карточками и с otzyvy.csv; каждое расхождение — замечание к строке.
  • Все шесть пунктов чеклиста ревью пройдены по этому PR.
  • Агенту отправлено хотя бы одно замечание или запрос «откуда значения» — и ответ понятен.
  • Решение принято: Merge pull request → Confirm merge → Delete branch, либо Close pull request с понятной причиной.

Вы приняли первую работу агента как заказчик. Пять минут по чеклисту закрывают основные риски. Следующий урок — что делать, когда агент сделал не то.

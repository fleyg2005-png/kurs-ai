Контрольная 5: два PR от ИИ и один откат

Без подсказок и степперов — полный цикл приёмки: две задачи агенту по очереди, два ревью с замечаниями, два слитых PR и один откат. Всё это вы делали в уроках 15–18.

Задание

  1. Выберите агента: Claude Code в браузере, Codex или облачный агент Copilot. Репозиторий — ваш приватный contracts.
  2. Поставьте первую задачу (текст ниже; расчётную дату замените на свою) и дождитесь pull request.
  3. Проведите ревью по чеклисту урока 17, оставьте минимум одно замечание — ошибка или доработка — и добейтесь исправления в том же PR. Слейте PR.
  4. Только после этого — вторая задача: ревью, минимум одно замечание, исправление, слияние.
  5. Один из PR откатите: Revert у слитого PR → обратный PR → слить. Убедитесь, что файлы вернулись к прежнему виду.
Задача 1 — таблица сроков
Прочитай все договоры в папке contracts/. Создай файл deadlines.md с таблицей всех сроков из договоров: договор (имя файла) — что за срок — дата или формулировка дословно из текста — сколько дней осталось до неё от расчётной даты (если дата не названа — «не указано»). Данные только из текста договоров. Файлы в contracts/ и README не менять. Открой pull request и в описании напиши, как проверить таблицу за 5 минут.
Расчётная дата: 1 ноября 2026.
Задача 2 — глоссарий
Прочитай все договоры в папке contracts/ и добавь в конец README.md раздел «Глоссарий»: термины из договоров (пеня, претензионный порядок, форс-мажор и другие), к каждому — определение в одно предложение и имя файла, где термин встречается; если договор определяет термин сам — цитируй договор. Остальные разделы README, файлы в contracts/ и другие файлы не менять. Открой pull request и в описании перечисли термины и файлы.

Критерии приёмки

Отмечайте только то, что проверили своими глазами. Чеклист и квиз ниже засчитывают контрольную автоматически.

  • В обоих ТЗ есть «файлы в contracts/ не менять» и «данные только из текста договоров».
  • По каждой задаче — отдельный PR; в Files changed только разрешённые файлы: deadlines.md в первом, README.md во втором, ничего из contracts/.
  • В каждом PR минимум одно моё замечание — к строке или в Conversation — и коммит агента, где оно учтено.
  • Минимум три значения из таблицы сроков сверены с текстом договоров; где даты в договоре нет — «не указано».
  • Оба PR слиты: Merge pull request → Confirm merge → Delete branch; deadlines.md и глоссарий видны в репозитории.
  • Один PR откачен: Revert у слитого PR, обратный PR слит; deadlines.md исчез из репозитория (или глоссарий пропал из README).
  • В истории коммитов видны коммиты агента, два слияния и запись, начинающаяся с Revert.

Проверка понимания

Что такое pull request от агента?

  • Готовое изменение, которое уже применено к файлам репозитория
  • Предложение изменений в отдельной ветке: в main ничего не меняется, пока вы не нажмёте Merge
  • Отчёт агента о проделанной работе без изменений в файлах

PR — контрольная точка: diff, обсуждение, ваше решение. Файлы в main меняются только после слияния.

Где увидеть, какие файлы тронул агент, и как оставить замечание к конкретной строке?

  • Во вкладке Conversation; замечание — ответом на описание PR
  • Во вкладке Files changed; навести на строку и нажать «+»
  • В истории коммитов; замечание — новым issue

Files changed — список файлов и diff; «+» у строки — комментарий именно к ней. Conversation — для общих замечаний.

Вы нажали Merge pull request. Что дальше?

  • Confirm merge, затем Delete branch — и файлы в main изменились
  • Ничего: изменения уже в main
  • Revert, чтобы подтвердить слияние

Слияние требует подтверждения. Ветка после него не нужна — история останется.

Слитый PR оказался плохим. Как вернуть прежнее состояние файлов?

  • Удалить файлы руками и загрузить старые версии через Upload files
  • Попросить агента «сделай как было»
  • Нажать Revert у слитого PR и слить обратный PR

Revert — точная отмена каждой строки. Ручная загрузка и память агента — новые ошибки.

Два агента правили README одновременно; второй PR показывает конфликт. Что делать?

  • Нажать Resolve conflicts и разобрать строки вручную
  • Закрыть второй PR и повторить его задачу после слияния первого; дальше ставить задачи по одной
  • Слить оба PR одновременно

«Одна задача за раз» снимает конфликты вообще. Ручной разбор — не ваша работа.

Какая ситуация — красный флаг, при котором PR сливать нельзя?

  • Агент назвал столбец «Срок» вместо «Срок действия»
  • Агент добавил в описание PR список прочитанных файлов
  • Агент пишет, что не смог открыть .docx, и заполнил таблицу по названиям файлов

Данные без источника — выдумка. Первые два — повод для замечания, но не опасность.

Если не получается

Агент не видит репозиторий или не делает PR

Claude Code: нужен Pro, Max или Team, для приватного репозитория — Claude GitHub App. Codex: GitHub не подключён или окружение не опубликовано. Copilot: нет Copilot Pro. Проверьте по урокам 14–16.

Второй PR показывает конфликт

Вы поставили вторую задачу, не слив первую. Закройте второй PR, слейте первый и поставьте вторую задачу заново новой сессией.

Не нахожу кнопку Revert

Она есть только у слитого PR — внизу вкладки Conversation; слитые PR лежат среди закрытых во вкладке Pull requests. Запасной путь: история коммитов → коммит слияния → «…» → Revert.

Причина непонятна — спросите ИИ. Готовый запрос:

Запрос к ИИ
Я юрист, не программист. Ставлю задачи ИИ-агенту в приватном репозитории contracts на GitHub; git руками не делаю, только проверяю pull request и нажимаю Merge.
Агент: [Claude Code / Codex / Copilot cloud agent].
Моё ТЗ: [текст ТЗ целиком].
Что сделал агент: [какие файлы изменены, что написано в описании PR].
Что не так: [что вижу и что ожидал; если на экране есть надпись — её точный текст].
Назови 3 самые вероятные причины в порядке вероятности, для каждой — как проверить за минуту, и предложи текст замечания агенту или кнопку на GitHub, которую нажать.

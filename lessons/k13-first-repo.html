Репозиторий с контентом и отчётами для ИИ

Восемь минут — и у вас есть приватный репозиторий marketing: чеклист поста, несколько постов, обезличенная выгрузка рекламных кампаний и шаблон отчёта. В следующем уроке к нему подключится ИИ, в модуле 5 — начнёт в нём работать. Войдите на github.com в соседней вкладке и идите по шагам.

Что получится

Это сквозной проект курса: все задачи агентам в следующих модулях — про этот репозиторий. К концу урока он выглядит так:

README.md checklist.md — чеклист поста (10 пунктов проверки) posts/ — 4–6 постов (.md): anons-vebinara.md, post-keis.md, post-rassylka.md… в каждом — шапка (дата, площадка, цель) и текст campaigns/campaigns.csv — обезличенная выгрузка кампаний: кампания; показы; клики; расход templates/otchet.md — шаблон отчёта за месяц с полями {месяц}, {кампания}, {показы}, {клики}, {CTR}, {расход}, {цена клика}, {вывод}

В чеклисте и в постах не раз встретится UTM-метка — хвост ссылки вида ?utm_source=…, по которому в статистике видно, откуда пришёл человек: из поста в Telegram, из письма или из рекламы. Пока достаточно знать, что ссылка в посте должна нести метку; проверять это будет инструмент в модуле 6.

Папку reports/ и сводную таблицу summary.md позже создаст агент — в модуле 6: в reports/ ляжет отчёт по каждому посту, в summary.md — сводная таблица постов и кампаний. Сейчас нужны только посты, чеклист, выгрузка и шаблон.

Commit changes — это просто «сохранить»

Каждое нажатие Commit changes создавало коммит — сохранённую порцию изменений с подписью, которую вы видите в истории. Ничего больше за этим словом нет: «сохранить файлы и подписать, что сделано». Подпись годится любая понятная.

Это единственное место в курсе, где вы коммитите сами. С модуля 5 коммиты в marketing делает агент: получает задачу, пишет программу, запускает её на постах и выгрузке и сохраняет результат с подписью и ссылкой на свою сессию. Ваши кнопки с этого момента — Merge pull request и, если что-то пошло не так, Revert.

Почему Private и что это значит для агента

Приватный репозиторий видят только вы и те, кого вы добавили. Для рабочих файлов — несогласованных постов и клиентских выгрузок — единственный разумный выбор. Следствие: ИИ-агенту он тоже не виден, пока вы не дадите доступ. Публичные репозитории Claude Code видит сразу после входа через GitHub, а для приватного нужно установить приложение Claude GitHub App и выбрать в нём ваш аккаунт и репозиторий marketing; у Codex для этого своё приложение. Как это сделать — в следующем уроке.

Private не отменяет обезличивания. Файлы будет читать агент на своей облачной машине, поэтому правило урока 09 действует и здесь: без названий клиентов, реальных бюджетов и персональных данных подписчиков — имён, почт и телефонов из CRM. Перед загрузкой пройдитесь поиском по каждому файлу.

Проверьте себя

Почему репозиторий marketing сделан приватным?

  • Приватные репозитории агент обрабатывает быстрее
  • В нём рабочие файлы — несогласованные посты и выгрузки: приватный репозиторий видят только вы и те, кого вы добавили, а агенту доступ даётся отдельно через приложение
  • Публичные репозитории на бесплатном тарифе недоступны

И публичные, и приватные репозитории бесплатны. Разница — кто видит файлы: публичный — все, приватный — только вы и те, кому открыт доступ.

Что делает кнопка Commit changes при загрузке постов?

  • Отправляет посты ИИ-агенту на проверку
  • Публикует посты на площадке
  • Сохраняет файлы в репозиторий и записывает это в историю как коммит с подписью

Здесь коммит — просто «сохранить с подписью». Публиковать посты из репозитория никто не будет: это ваша работа за его пределами.

Зачем в чеклисте пункт «Ссылка с UTM-меткой»?

  • По метке в ссылке в статистике видно, откуда пришёл человек; без неё переходы из поста не отличить от остальных
  • Метка делает ссылку короче и аккуратнее
  • Без метки ссылка не откроется у части подписчиков

UTM-метка — хвост ссылки вида ?utm_source=…. Ссылка работает и без неё, но статистика перестаёт отвечать на вопрос «откуда пришли люди».

Как в репозитории появилась папка templates?

  • Через кнопку New folder в меню Add file
  • В имени файла при создании был указан путь templates/otchet.md — косая черта создала папку
  • Папки в репозитории может создавать только ИИ-агент

Папка появляется вместе с первым файлом, у которого в имени указан путь. Второй способ — перетащить папку целиком в Upload files; разложить файлы по папкам можно и поручить агенту.

Практика

Если шли по степперу — почти всё сделано. Проверьте результат по списку и добавьте то, чего не хватает.

  • Репозиторий marketing существует, рядом с именем значок Private, адрес — github.com/мой-username/marketing.
  • В корне есть README.md и checklist.md с 10–12 пунктами проверки поста.
  • В папке posts/ не меньше четырёх постов с шапкой «дата, площадка, цель»; один из них — post-rassylka.md со ссылкой без UTM-метки.
  • В папке campaigns/ лежит campaigns.csv с колонками «кампания; показы; клики; расход», в templates/ — otchet.md с полями в фигурных скобках.
  • Ни в одном файле нет названий клиентов, реальных бюджетов и персональных данных из CRM — я проверил поиском по каждому файлу.

Рабочая папка готова: посты, чеклист, выгрузка и шаблон отчёта. В следующем уроке вы подключите репозиторий к Claude и ChatGPT — и дадите ИИ его прочитать.

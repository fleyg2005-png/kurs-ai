Первый репозиторий и первый коммит

Десять минут — и у вас есть репозиторий hello-ai с тремя коммитами и файлом о себе. В уроке 14 он станет сайтом, а в модуле 6 в нём будут работать ИИ-агенты. Войдите на github.com в соседней вкладке и идите по шагам.

Что получится

Репозиторий — папка проекта с историей. Коммит — сохранённая версия с подписью. Сейчас вы сделаете и то и другое, не написав ни одной команды: всё через кнопки на сайте. По дороге запомните, где в репозитории что лежит, — это пригодится в каждом следующем уроке.

Справа вверху на любой странице GitHub есть кнопка ＋ (плюс со стрелкой). Нажмите её и выберите New repository (новый репозиторий).

🐙 GitHub🔍 Search or jump to…＋ ▾1👤

Откроется страница Create a new repository. Заполните три вещи, остальное оставьте как есть:

  1. В поле Repository name введите hello-ai. Имя пишется латиницей, без пробелов; дефис можно.
  2. Выберите Public (публичный). Это нужно для бесплатного сайта в следующем уроке.
  3. Поставьте галочку Add a README file. README — «титульный лист» проекта; GitHub создаст его сам, и репозиторий не будет пустым.

Нажмите на README.md в списке файлов. Откроется страница файла. Справа над его содержимым — иконка карандаша (подсказка при наведении: Edit this file, редактировать файл). Нажмите её.

README.md✎Edit this file
# hello-ai Учебный репозиторий курса по ИИ

Сотрите то, что есть, и напишите три строки: заголовок с именем (решётка и пробел в начале строки делают её заголовком), кто вы и зачем вам ИИ. Например:

# Анна Петрова Бухгалтер, 12 лет веду учёт малого бизнеса. Учусь работать с ИИ, чтобы сверка актов и ответы на требования налоговой занимали минуты, а не вечера.

Пустые строки между абзацами — не случайность: без них Markdown склеит строки в одну. О разметке — врезка после степпера.

Справа вверху — зелёная кнопка Commit changes… (с многоточием). Нажмите. Появится окно: GitHub просит подписать изменение.

В поле Commit message GitHub уже подставил стандартный текст вроде Update README.md. Замените его на понятный: Добавить рассказ о себе в README. Остальные поля не трогайте. Нажмите Commit changes.

Вы снова на странице файла — уже с новым текстом. Вернитесь на главную страницу репозитория (нажмите hello-ai в заголовке над файлом) и найдите над списком файлов ссылку 2 commits с иконкой часов. Нажмите её.

Это и есть история. Каждая строка — коммит: подпись, автор, время и короткий код-идентификатор. Нажмите на подпись верхнего — увидите, что именно изменилось: удалённые строки красным, добавленные зелёным.

Вернитесь на главную страницу репозитория. Справа над списком файлов — кнопка Add file ▾. Нажмите и выберите Create new file (создать новый файл). Вверху появится поле для имени — введите notes.md. Ниже — пустой редактор; напишите в нём список из трёх дел, которые хотите поручить ИИ:

hello-ai /
notes.md
# Что хочу поручить ИИ - Сверять акты сверки с выпиской банка - Писать первые черновики ответов на требования ИФНС - Готовить памятки для сотрудников по авансовым отчётам
Commit changes…

Нажмите Commit changes…, в поле Commit message напишите Добавить список задач для ИИ и подтвердите кнопкой Commit changes. GitHub откроет новый файл. Вернитесь на главную страницу репозитория: в списке два файла — README.md и notes.md, над ними 3 commits.

Привычка на всю жизнь. Один коммит — одно законченное изменение с понятной подписью. Не «поправил всё», а «добавить список задач». Через месяц, листая историю, вы скажете себе спасибо.

Как писать сообщения коммитов

Сообщение коммита — ответ на вопрос «что здесь изменилось и зачем?» для человека, который откроет историю через полгода. Чаще всего этим человеком будете вы. Формула: глагол + что изменили + зачем, если «зачем» не очевидно. Первая строка — до 50–70 знаков, можно по-русски.

Так не надо

Update README.md
правки
asdf
финальная версия 2

Через неделю невозможно понять, что менялось. Чтобы разобраться, придётся открывать каждый коммит.

Так надо

Добавить рассказ о себе в README
Исправить ставку НДС в примере расчёта
Убрать устаревший раздел про бумажные акты
Переименовать notes.md в plan.md для единообразия

Каждая строка читается как пункт отчёта: понятно, что сделано, без заглядывания внутрь.

Ещё два правила. Один коммит — одно смысловое изменение: правка опечатки и новый раздел — это два коммита, а не один. И не бойтесь коммитить часто: маленькие коммиты легко откатывать, большие — нет.

Markdown: вся разметка в одной врезке

Файлы .md пишутся на Markdown — простой разметке, которую GitHub превращает в оформленный текст. Хватит четырёх приёмов: строка, начатая с # , — заголовок (## — заголовок поменьше); строка с - в начале — пункт списка; текст в двойных звёздочках **важно** — жирный; абзацы разделяются пустой строкой. Этого достаточно для README, заметок и технических заданий агентам. Остальное попросите у ИИ: «оформи этот текст в Markdown».

Проверьте себя

Зачем при создании репозитория ставить галочку Add a README file?

  • Без неё GitHub не даст создать репозиторий
  • Чтобы репозиторий не был пустым и сразу получил «обложку», которую видят на главной странице
  • Без README нельзя опубликовать сайт

README — описание проекта, которое GitHub показывает под списком файлов. Для сайта нужен index.html, а не README; но пустой репозиторий без первого файла неудобен для работы.

Где посмотреть, кто и когда менял файлы в репозитории?

  • Во вкладке Settings
  • Во вкладке Issues
  • По ссылке с числом коммитов над списком файлов (рядом иконка часов)

Это история репозитория: каждый коммит с подписью, автором и временем. Нажав на коммит, увидите точные изменения — красным и зелёным.

Какое сообщение коммита лучше?

  • «Исправить дату начала отпуска в примере расчёта»
  • «Update README.md»
  • «правки по замечаниям»

Глагол + что изменено + зачем. Первое сообщение понятно без открытия коммита; два других через неделю не скажут ничего.

Практика

Если шли по степперу — почти всё уже сделано. Проверьте результат по списку и добавьте то, чего не хватает.

  • Репозиторий hello-ai существует, он Public и открывается по адресу github.com/мой-username/hello-ai.
  • В README — заголовок с моим именем и минимум две строки о себе; текст показывается под списком файлов.
  • В репозитории два файла: README.md и notes.md.
  • В истории три коммита, у каждого понятное сообщение по формуле «глагол + что + зачем».
  • Я открыл(а) один из коммитов и увидел(а), какие строки добавлены (зелёные).

Есть репозиторий и история. Вы умеете создавать файлы, менять их и подписывать изменения — это 80% ежедневной работы с GitHub. В следующем уроке репозиторий станет сайтом с собственным адресом.

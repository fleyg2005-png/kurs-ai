Какие инструменты для маркетплейса может сделать ИИ

До сих пор агент делал разовую работу: прочитал карточки и отзывы — переписал README. Инструмент — следующий шаг: программа, которая лежит в репозитории и запускается снова на новых карточках и свежих выгрузках. Что реально сделать для магазина на маркетплейсе, где граница и как написать ТЗ.

Чем инструмент отличается от ответа в чате

Спросить в чате «какая средняя оценка у термокружки по этой выгрузке» — быстро и годится для одного раза. Но через месяц приходит новая выгрузка отзывов и десяток новых карточек, и всё повторяется; ответ живёт в переписке, коллеги его не видят, а проверить, не пропущен ли товар, нечем.

Инструмент устроен иначе: правила записаны один раз в программе, программа лежит рядом с карточками и запускается снова на новых файлах, а результат — отчёты и таблицы, которые открываются прямо на GitHub и проверяются по одному чеклисту.

Что агент может построить

В облачной машине агента есть Python, и для файлов маркетплейса этого достаточно: карточки — обычный текст (.md), выгрузка отзывов — таблица (.csv). Всё, что сводится к «прочитать файлы из папки по правилам и записать результат в новые файлы», — его работа:

  • Проверка карточек по чеклисту: отчёт по каждой карточке — пункт, выполнено или нет, цитата.
  • Свод цен и остатков по всем карточкам одной таблицей: видно, что заканчивается и где нет цены до скидки.
  • Черновики ответов на отзывы по шаблону — на каждый отзыв с низкой оценкой.
  • Отчёт по жалобам: какие товары чаще всего ругают и за что, с цитатами из отзывов.
  • Таблица «товар — вопросы покупателей без ответа»: вопросы из отзывов, на которые в карточке ответа нет.
  • Проверка перед акцией: у всех ли карточек заполнены цена до скидки, остаток и разделы, по которым придут вопросы.
  • Переименование и раскладка файлов карточек по единому шаблону.

Менеджер маркетплейса

Проверка всех карточек по чеклисту перед акцией — отчёт с цитатами по каждой. Черновики ответов на все отзывы с оценкой 1–3 по шаблону магазина.

Владелец магазина

Свод цен и остатков одной таблицей: что заканчивается и где перепутаны цена и цена до скидки. Отчёт «какие товары чаще всего ругают и за что» по выгрузке отзывов.

Контент-менеджер

Сравнение каждой карточки с чеклистом площадки: чего не хватает до заполненной. Таблица вопросов покупателей без ответа — готовый план, что дописать в описания.

Аналитик продаж

Сводная таблица по отзывам: число, средняя оценка и доля низких оценок по каждому товару. Три самые частые жалобы на товар с дословными цитатами.

Обезличивание — по-прежнему обязательно. Инструмент видит только то, что лежит в репозитории, а туда кладутся файлы без реальных артикулов, брендов-клиентов, имён покупателей и закупочных цен (урок 09). Карточки и обезличенные отзывы — да, финансовые отчёты магазина — нет.

Где это работает — и где граница

Схема та же, что в модуле 5, только вместо README агент приносит программу и результат:

ТЗ→ Агент пишет программу→ Запускает на файлах→ PR: программа + отчёты→ Ваше ревью, Merge→ Новые карточки — «запусти снова»

Программа выполняется в машине агента, не на вашем компьютере, и только по вашей просьбе: «добавил три карточки, запусти проверку снова» — и приходит новый PR с новыми отчётами. Файлы никуда не уходят, кроме машины агента и репозитория.

Агент не трогает сам маркетплейс. Ни Claude, ни Codex не подключены к кабинету Wildberries или Ozon: они не меняют цены на витрине, не публикуют описания и не отправляют ответы покупателям. Репозиторий — подготовительная кухня: тексты и таблицы готовятся здесь, а в кабинет вы переносите их сами — открыть файл, скопировать, вставить. Работе с кабинетами площадок курс не учит.

Вторая граница — расписание. «Каждый понедельник собирать свод остатков» программа сама не сможет: для запуска по расписанию нужна дополнительная настройка (на GitHub — GitHub Actions), следующий уровень за рамками курса. Нужен свежий свод — попросите агента.

Владельцу магазина к созвону через час нужно свести цены и остатки по четырём товарам — карточки под рукой. Менеджеру маркетплейса перед каждой акцией надо проверять 40 карточек по чеклисту, и отчёт читают ещё два коллеги. Где инструмент, а где хватит чата?

Владельцу — чат: четыре файла, один раз, результат нужен сейчас и только ему. Менеджеру — инструмент: повторяется перед каждой акцией, карточек десятки, результат читают коллеги. Три признака инструмента: повторяется, файлов больше десятка, результат нужен не только вам.

Структура ТЗ для инструмента

Четыре части: первые две определяют, что агент построит; третья защищает файлы; четвёртая даёт способ проверить результат за пять минут.

  1. Что есть — папки и файлы: где карточки, где выгрузка отзывов, в каких форматах, где правила (чеклист, шаблон ответа).
  2. Что сделать — написать программу и назвать файл; запустить на всех файлах; положить результат в названные файлы; добавить в README раздел «Как пользоваться».
  3. Ограничения — данные только из файлов; карточки, чеклист и выгрузку не менять; никуда не отправлять.
  4. Критерии готовности — проверяемый пример по конкретной карточке, ответ на который вы знаете заранее: «в отчёте по tovary/termokruzhka.md пункт „Ключевые слова“ помечен „не выполнено“».
Шаблон ТЗ для инструмента
Сделай инструмент «НАЗВАНИЕ».

Что есть: папка с карточками товаров и её формат (.md), выгрузка отзывов (.csv), файлы с правилами (чеклист, шаблон ответа) и что в них.

Что сделать:
1. Напиши программу на Python (назовите файл, например check_cards.py), которая для каждой карточки из папки … — опишите результат одного прогона: какой файл появляется, что в нём и в каком виде (таблица с такими столбцами).
2. Собери сводный файл по всем товарам: имя файла и столбцы таблицы.
3. Запусти программу у себя на всех файлах и положи готовые результаты в репозиторий вместе с программой.
4. В README добавь раздел «Как пользоваться»: как добавить новую карточку и как попросить тебя запустить инструмент снова.

Ограничения: данные брать только из файлов репозитория, ничего не додумывать — если в карточке чего-то нет, писать «не выполнено». Файлы никуда не отправлять, кроме твоей рабочей машины. Карточки, чеклист и выгрузку отзывов не менять.

Критерии готовности: для каждой карточки есть результат; в сводной таблице столько строк, сколько карточек; один проверяемый пример по конкретной карточке — в таком-то файле должно быть написано то-то (вы знаете это заранее). В описании PR перечисли, что сделано, что не получилось и как мне проверить результат за 5 минут.

Заполненный пример — ТЗ проекта «Проверка карточек товаров по чеклисту» — в следующем уроке; по нему вы получите первый инструмент.

Так не надо

«Сделай программу, которая проверяет карточки и находит все проблемы, чтобы товары продавались лучше».

Нет файлов и вида результата, «проблема» не определена, а «продавались лучше» по файлам не проверить — агент решит сам, что считать проблемой, и принять работу будет нечем.

Так надо

«Что есть: tovary/ (четыре карточки .md), checklist.md (11 пунктов), otzyvy/otzyvy.csv. Что сделать: программа check_cards.py; для каждой карточки — отчёт в reports/ с таблицей пункт — выполнено/не выполнено — цитата; сводная summary.md; запусти на всех. Ограничения: данные только из файлов; карточки не менять; никуда не отправлять. Критерий: в отчёте по termokruzhka.md пункт „Ключевые слова“ — „не выполнено“».

Проверьте себя

Чем инструмент отличается от ответа ИИ в чате?

  • Инструмент использует более мощную модель
  • Программа лежит в репозитории, запускается снова на новых файлах, а результат — файлы, которые видят коллеги
  • Инструмент работает без файлов в репозитории

Модель может быть той же. Разница — в повторяемости и в результате-файле вместо текста в переписке.

Где выполняется программа, которую написал агент?

  • На вашем компьютере, после установки Python
  • На серверах маркетплейса рядом с карточками
  • В облачной машине агента, по вашей просьбе; результат приходит как pull request

Вы ничего не устанавливаете. Агент запускает программу у себя; файлы не покидают его машину и репозиторий.

Инструмент подготовил новые тексты карточек. Как они попадут на витрину маркетплейса?

  • Никак сами: вы открываете файл в репозитории и переносите текст в кабинет площадки руками
  • Агент обновит карточки на площадке из своей облачной машины
  • После Merge изменения уйдут на маркетплейс автоматически

Агент работает только с файлами репозитория, к кабинету площадки он не подключён. Merge лишь принимает файлы в main.

Что обязательно должно быть в критериях готовности ТЗ?

  • Название библиотеки для чтения .csv
  • Срок выполнения в минутах
  • Проверяемый пример по конкретной карточке, ответ на который вы знаете заранее

По примеру агент проверит себя, а вы — его. Библиотеки выбирает агент, а время работы ни о чём не говорит.

Практика

Выберите инструмент для своего магазина — из списка выше или свой — и заполните по нему шаблон ТЗ в заметках или в чате с ИИ. Оно понадобится в контрольной 6.

  • В ТЗ четыре части: что есть, что сделать, ограничения, критерии готовности.
  • Названы папки, форматы файлов и файлы с правилами; названы файлы, которые появятся в репозитории.
  • В ограничениях есть все три: данные только из файлов, карточки и выгрузку не менять, никуда не отправлять.
  • Критерий готовности — проверяемый пример по конкретной карточке с ответом, который я знаю заранее.
  • ТЗ сохранено там, где я найду его в контрольной 6.

Вы знаете, что заказывать и как. В следующем уроке агент построит первый инструмент — проверку карточек товаров по чеклисту — а вы примете его как заказчик.

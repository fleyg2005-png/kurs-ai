Публикуем сайт за 10 минут

В репозитории hello-ai появится файл index.html, а у вас — сайт по адресу https://ваш-username.github.io/hello-ai/, который откроет любой человек в мире. Без хостинга, домена и оплаты. Откройте репозиторий в соседней вкладке.

Что мы делаем

GitHub Pages — встроенный в GitHub хостинг: вы указываете, из какой ветки брать файлы, и GitHub показывает их как сайт. Главный файл сайта — index.html в корне репозитория; именно его браузер откроет по адресу сайта. Сейчас вы создадите этот файл из готового шаблона, включите Pages и проверите, что правки доходят до сайта.

На главной странице репозитория нажмите Add file ▾ → Create new file. В поле имени введите index.html — строго маленькими буквами и с расширением .html.

index.html
in main

Регистр важен. Index.html, INDEX.HTML и index.html.txt — другие файлы, и сайт с ними не откроется. Только index.html.

Скопируйте шаблон ниже кнопкой «Копировать» и вставьте в редактор целиком. Затем замените имя, подпись и три пункта списка на свои. Меняйте только текст между тегами — сами теги (слова в угловых скобках) не трогайте.

Шаблон страницы — скопируйте целиком
<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Анна Петрова — о себе</title>
  <style>
    body { font-family: Arial, sans-serif; max-width: 640px; margin: 40px auto; padding: 0 20px; line-height: 1.6; color: #222; }
    h1 { color: #1f6feb; }

  </style>
</head>
<body>
  <h1>Анна Петрова</h1>
  <p>Бухгалтер. Учусь работать с ИИ и публиковать свои инструменты.</p>
  <ul>
    <li>Веду учёт малого бизнеса 12 лет</li>
    <li>Автоматизирую сверку актов с помощью ИИ</li>
    <li>Этот сайт сделан без единой установленной программы</li>
  </ul>
</body>
</html>

Что здесь что: строка с charset="utf-8" отвечает за русские буквы, блок style — за внешний вид, h1 — заголовок, ul и li — список и его пункты.

Нажмите Commit changes…, в поле Commit message напишите Добавить главную страницу сайта и нажмите Commit changes. Файл теперь в репозитории, но сайта пока нет — его нужно включить.

Нажмите вкладку Settings (справа в верхнем ряду вкладок репозитория). В левом меню найдите раздел Code and automation и в нём пункт Pages.

Если видите 404 — ещё рано. Подождите две-три минуты и обновите страницу. Если 404 держится дольше десяти минут — смотрите раздел «Типовые ошибки» ниже.

Вернитесь в репозиторий, откройте index.html, нажмите карандаш Edit this file и добавьте четвёртый пункт списка — ещё одну строку <li>…</li> перед </ul>. Нажмите Commit changes… → сообщение Добавить четвёртый пункт в список → Commit changes. Через 1–10 минут обновите сайт: пункт появился. Так теперь будет работать любое изменение: коммит в main — и сайт обновился.

Не хочется писать HTML? Попросите ИИ

Шаблон выше намеренно простой. Если хотите страницу поинтереснее — с разделами, контактами, цветами, — её напишет ИИ. Главное требование в запросе: один файл, без внешних библиотек, иначе страница будет зависеть от чужих серверов. Запрос ниже заполнен примером — подставьте свои данные.

Запрос к ИИ
Напиши одностраничный сайт-визитку. Один файл index.html, без внешних библиотек и шрифтов, весь CSS внутри тега style. Кодировка utf-8, язык страницы русский, вёрстка должна нормально выглядеть на телефоне.
Обо мне: Анна Петрова, бухгалтер, 12 лет веду учёт малого бизнеса (ООО и ИП на УСН), помогаю предпринимателям проходить проверки без штрафов.
Разделы: короткое приветствие; «Чем помогаю» — 4 пункта; «Опыт» — 3 пункта; «Контакты» — почта anna.petrova@example.com и Telegram @anna_petrova_buh.
Стиль: спокойный, деловой, светлый фон, один акцентный цвет. Без анимаций и картинок.
Выдай только код файла целиком, без пояснений до и после.

Результат вставьте в index.html вместо шаблона целиком — от первой строки до последней. Если ИИ всё же добавил пояснения до или после кода, в файл их копировать не нужно.

Почему это работает

Сайт, который вы опубликовали, — статический: это просто файлы, которые браузер показывает как есть. Ему не нужны база данных, программа на сервере и администратор. Поэтому GitHub может раздавать такие сайты бесплатно: он просто отдаёт содержимое ветки main по адресу username.github.io/имя-репозитория.

Коммит в main→ GitHub Pages берёт файлы из ветки→ username.github.io/hello-ai/

Отсюда два практических вывода. Первый: что в main — то и на сайте, с задержкой в несколько минут; черновики держите в ветках (модуль 5). Второй: всё, что умеет браузер, — страницы, стили, калькуляторы на JavaScript — на таком сайте работает. Именно такие инструменты будут писать для вас агенты в модулях 6–7.

Проверьте себя

Какой файл GitHub Pages покажет, когда кто-то откроет адрес вашего сайта?

  • README.md — он же главный файл репозитория
  • index.html из корня репозитория
  • Любой первый по алфавиту файл с расширением .html

Главный файл сайта — всегда index.html в корне (или в папке, выбранной в настройках Pages). README показывается на странице репозитория, но не на сайте.

Вы сделали коммит в main. Когда изменение появится на сайте?

  • Сразу же, при обновлении страницы
  • Только после повторного нажатия Save в Settings → Pages
  • Автоматически, через 1–10 минут

Pages пересобирает сайт после каждого коммита в выбранную ветку. Настройки трогать не нужно — нужно подождать.

Что означает «статический сайт»?

  • Набор готовых файлов, которые браузер показывает как есть, без программы на сервере
  • Сайт, который нельзя менять после публикации
  • Сайт без картинок и стилей

Статический сайт может быть красивым и интерактивным — калькуляторы на JavaScript работают. Нет только серверной части, поэтому хостинг бесплатный.

Вы просите ИИ написать страницу для GitHub Pages. Какое требование в запросе обязательно?

  • Написать страницу на Python
  • Один файл index.html, без внешних библиотек
  • Сделать страницу доступной только мне

Один файл проще положить в репозиторий и проверить, а без внешних библиотек страница не зависит от чужих серверов. Python на Pages не запускается — это статический хостинг.

Практика

Доведите сайт до состояния, которым не стыдно поделиться, и проверьте его чужими глазами.

  • В корне репозитория есть index.html, имя маленькими буквами.
  • В Settings → Pages: Source — Deploy from a branch, Branch — main, папка /(root); на странице показан адрес сайта.
  • Сайт открывается по адресу https://мой-username.github.io/hello-ai/ в режиме инкогнито.
  • После правки index.html изменение появилось на сайте (пришлось подождать от 1 до 10 минут).
  • Я отправил(а) адрес сайта коллеге или другу, и у него страница открылась.

У вас есть сайт. Собственный адрес в интернете, который вы меняете одним коммитом, — это основа для всех инструментов, которые дальше будут писать для вас агенты. Следующий шаг — контрольная: повторите путь без подсказок.

Проект: проверка договоров по чеклисту

За час-полтора у вас появится первый инструмент: программа, которая проверяет каждый договор по вашему чеклисту и собирает сводную таблицу сроков и штрафов. Пишет и запускает её агент; вы ставите задачу, читаете отчёты и принимаете pull request.

Что понадобится. Аккаунт Claude на Pro, Max или Team; приватный репозиторий contracts, к которому подключено Claude GitHub App (урок d14); 3–5 обезличенных договоров в папке contracts/, файл checklist.md и шаблон templates/pretenziya.md. В Codex (chatgpt.com/codex) то же ТЗ отправляют через Start a new task (урок d16).

От ТЗ до работающего инструмента

По одному шагу, в соседней вкладке. Имена договоров в примерах условные.

Программа check_contracts.py лежит в репозитории и стала частью инструмента: в новой сессии агент получает свежую машину, забирает документы и программу, запускает её и присылает результат. Вы ничего не устанавливали: Python и библиотеки живут в машине агента, которая засыпает при простое и просыпается от нового сообщения.

Данные никуда не уходили: договоры попали из приватного репозитория в машину агента и вернулись отчётами. Сетевой доступ окружения Default — только к GitHub и типовым хранилищам пакетов. Приватный репозиторий видите вы и Claude GitHub App. Обезличивание всё равно обязательно.

Сколько это стоит

Сессия агента расходует лимиты тарифа — те же скользящие 5-часовые окна и недельный лимит, что и чат; одна такая задача — десятки обращений к модели, то есть заметно больше вопроса в чате (точных чисел курс не называет). Виртуальная машина отдельно не оплачивается. Для нескольких задач в неделю достаточно Pro ($20/мес); Max — если инструментов много.

Если агент говорит, что не смог прочитать .docx

Причины разные: старый формат, картинка вместо текста, редкая кодировка. Не чините сами. Два пути: попросить агента выбрать другую библиотеку или сохранить проблемные договоры как обычный текст (.md или .txt) и загрузить через Upload files. Скан без текстового слоя агент не прочитает — и должен прямо сказать об этом, а не написать отчёт «по памяти».

Контрольная 4: репозиторий и сайт

Без подсказок и степперов: создайте с нуля публичный репозиторий, опубликуйте в нём страницу о себе и внесите в неё изменения так, чтобы они появились в интернете. Всё, что нужно, вы уже делали в уроках 12–14.

Задание

  1. Создайте новый публичный репозиторий с именем my-ai-notes и файлом README.
  2. Добавьте файл index.html со страницей, где есть: ваше имя, заголовок «Что я узнал(а) о работе с ИИ» и список минимум из трёх пунктов. Можно взять шаблон страницы из урока 14 или попросить ИИ написать его.
  3. Включите GitHub Pages для ветки main. Дождитесь, пока сайт откроется по адресу вида https://username.github.io/my-ai-notes/.
  4. Откройте адрес в режиме инкогнито (или с телефона), чтобы убедиться: сайт виден всем, а не только вам.
  5. Измените страницу через карандаш (Edit) — добавьте четвёртый пункт в список — и сделайте коммит с осмысленным сообщением. Проверьте, что через несколько минут изменение появилось на сайте.
  6. Откройте историю коммитов репозитория. Там должно быть не меньше трёх записей: создание README, добавление index.html, правка списка.

Критерии приёмки

Отмечайте только то, что проверили своими глазами. Чеклист и квиз ниже засчитывают контрольную автоматически.

  • Репозиторий my-ai-notes существует, он Public, в нём есть README.md и index.html.
  • В Settings → Pages стоит «Deploy from a branch», ветка main, и показан адрес сайта.
  • Сайт открывается в режиме инкогнито и показывает моё имя и список.
  • После правки index.html изменение видно на сайте (пришлось подождать от 1 до 10 минут).
  • В истории коммитов не меньше трёх записей, и у каждой — понятное сообщение, а не «update» или «asdf».
  • Я могу объяснить коллеге одной фразой, что такое репозиторий, коммит и GitHub Pages.

Проверка понимания

Сайт на GitHub Pages показывает старую версию страницы через минуту после коммита. Что делать?

  • Сделать ещё один коммит — первый не сработал
  • Подождать: публикация занимает от минуты до десяти; затем обновить страницу с очисткой кеша
  • Пересоздать репозиторий

Pages пересобирает сайт после каждого коммита, но не мгновенно. Повторные коммиты только ставят в очередь новые сборки.

По какому адресу откроется сайт из репозитория my-ai-notes пользователя anna-hr?

  • https://github.com/anna-hr/my-ai-notes
  • https://anna-hr.github.io/my-ai-notes/
  • https://my-ai-notes.github.io/anna-hr

Первый адрес — страница репозитория с кодом. Сайт живёт на домене username.github.io, а имя репозитория идёт после косой черты. Исключение — репозиторий с именем username.github.io: он открывается по корню домена.

Что такое коммит?

  • Отправка файла на сервер GitHub по почте
  • Сохранённый снимок файлов с подписью, что и зачем изменилось; к нему можно вернуться
  • Разрешение другому человеку редактировать репозиторий

История коммитов — это и есть главная ценность git: можно увидеть, кто, что и когда менял, и откатиться.

Почему репозиторий для сайта должен быть публичным?

  • На бесплатном тарифе GitHub Pages работает только для публичных репозиториев
  • Публичные репозитории быстрее загружаются
  • Иначе ИИ-агент не сможет его прочитать

Приватные репозитории публиковать через Pages можно только на платных тарифах. И помните: публичный репозиторий видят все — не кладите туда личные данные.

Вы нажали карандаш, изменили текст и закрыли вкладку, не нажав «Commit changes». Что произошло?

  • Изменения сохранились автоматически
  • Ничего не сохранилось: без коммита правка не попадает в репозиторий
  • Изменения сохранились в черновик, который виден в истории

В веб-редакторе GitHub правка существует только до коммита. Привычка: изменил — сразу коммит.

Если не получается

Сайт отдаёт 404

Чаще всего: Pages ещё не включён, выбрана не та ветка, или файл называется не index.html (например, Index.html или index.html.txt). Проверьте Settings → Pages и точное имя файла.

Страница открывается, но пустая или «кракозябры»

В начале файла должна быть строка <meta charset="utf-8">. Скопируйте шаблон из урока 14 целиком.

Нет вкладки Pages в настройках

Вы не владелец репозитория или он приватный. Создайте свой публичный.

Если причина непонятна — не угадывайте, спросите ИИ. Готовый запрос:

Запрос к ИИ
Я публикую сайт через GitHub Pages и он не открывается.
Репозиторий: https://github.com/USERNAME/my-ai-notes (публичный).
В Settings → Pages: Source = Deploy from a branch, Branch = main, папка /(root).
Файлы в корне репозитория: README.md, index.html.
По адресу https://USERNAME.github.io/my-ai-notes/ вижу: [опишите: 404 / пустая страница / старая версия].
С момента последнего коммита прошло [N] минут.
Назови 3 самые вероятные причины в порядке вероятности и для каждой — как проверить за минуту.

Сдали? Значит, у вас есть то, чего нет у большинства коллег: собственный адрес в интернете, который вы контролируете и можете менять за минуту. Дальше — git в браузере: редактор, терминал и работа с ветками.

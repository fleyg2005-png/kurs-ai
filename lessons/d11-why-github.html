Зачем GitHub, если код пишет ИИ

Ответ короткий: GitHub — рабочая папка для ИИ-агента. Без неё агенту негде читать ваши документы и некуда класть результат. Шесть минут — чтобы пять слов из мира программистов перестали мешать.

Рабочая папка для агента

В модуле 3 вы отдавали ИИ документ прямо в чат и получали ответ там же. Для одного договора этого достаточно. Но проверить двадцать договоров по одному чеклисту и свести сроки и штрафы в таблицу — значит вставлять документы по одному и собирать ответы руками. Та же рутина, только с ИИ.

Эту работу делает агент: он пишет небольшую программу, запускает её на всех документах сразу и складывает отчёты в папку. Для этого ему нужно место, где документы лежат и куда можно положить результат. В чате такого места нет. Это место —репозиторий на GitHub.

Документы в репозитории→ Задача ИИ→ ИИ пишет и запускает программу→ Pull request с результатом→ Ваша проверка→ Merge

Так будет выглядеть каждая задача до конца курса. Вы положили в репозиторий пять обезличенных договоров и чеклист и написали агенту: «проверь каждый договор по чеклисту, сведи сроки и штрафы в таблицу». Агент написал программу, запустил её на своей облачной машине, сложил отчёты в папку reports/ и прислал результат на проверку. Вы прочитали отчёты и нажали Merge. Код вы не видели — и не должны.

Пять слов: что вы увидите, когда ИИ поработал

Термины GitHub описывают не ваши действия, а то, что появится на экране после работы агента. Наведите на подчёркнутое слово, если потом забудете.

  • Репозиторий (repository) — ваша папка на GitHub: файлы и подпапки, как в проводнике, плюс полная история изменений. Один проект — один репозиторий.
  • Коммит (commit) — одна сохранённая порция изменений с подписью. После работы агента в истории появятся его записи вроде «Добавить отчёты по пяти договорам» — с датой и ссылкой на сессию.
  • Ветка (branch) — черновик рядом с основной версией. Основная называется main; агент пишет в свою ветку, поэтому, пока вы не приняли результат, в main ничего не меняется.
  • Pull request (PR) — страница «посмотрите, что я сделал»: описание работы, список изменённых файлов, разница построчно (зелёное добавлено, красное удалено) и место для замечаний. Ваш главный экран.
  • Merge (слияние) — кнопка «принять»: результат из ветки агента становится основной версией. Единственное в этом списке, что делаете вы. Передумали — у слитого PR есть кнопка Revert.

Коммиты, ветки и pull request создаёт агент; вы их читаете и принимаете.

Чего вы делать не будете

Программисты работают с GitHub через программу Git на компьютере, сами создают ветки и открывают pull request. Здесь всё это делает агент. Границу полезно провести сразу.

Не ваша работа

Ставить Git и писать команды. Создавать ветки. Открывать pull request. Писать и читать код. Делать сайты — в этом пути GitHub хранит документы, а не страницы.

Ваша работа

Положить документы в репозиторий кнопкой Upload files — это «перетащить файлы в папку». Поставить задачу текстом. Открыть pull request, прочитать результат, оставить замечания. Нажать Merge pull request — или попросить переделать, или закрыть PR.

Один раз, загружая файлы в уроке «Репозиторий с документами для ИИ», вы нажмёте кнопку Commit changes. Там она означает просто «сохранить»; все остальные коммиты в вашем репозитории будут подписаны агентом.

Почему именно репозиторий, а не папка в облаке

Документы уже лежат в общей папке отдела — на сетевом диске или в облаке. Почему не дать агенту её? Папка умеет только хранить файлы; репозиторий умеет ещё четыре вещи, без которых работа с агентом превращается в лотерею.

Общая папкаРепозиторий
ИсторияВерсии файла, если сервис их хранитКаждое изменение — коммит с подписью и датой, навсегда

Последняя строка — главная. Если агент ошибся — перепутал стороны договора, не так понял пункт чеклиста, — ошибка остаётся в его ветке: вы видите её в PR и не принимаете. В папке файл был бы уже перезаписан.

Юридический отдел хранит шаблоны договоров и регламент согласования в общей папке на сервере. Раз в месяц выясняется, что кто-то поправил шаблон, и никто не помнит, что и когда. Руководитель хочет поручить ИИ проверять новые договоры по регламенту. Что изменится, если перенести файлы в репозиторий?

Четыре вещи. Каждая правка шаблона станет коммитом с подписью — видно, кто, когда и какие строки поменял. Любую прошлую версию можно вернуть одной кнопкой, не разыскивая её по почте. У агента появится рабочее место: он прочитает регламент и договоры из репозитория и положит отчёты туда же. И появится приёмка: в основной версии ничего не изменится, пока руководитель не посмотрит pull request и не нажмёт Merge.

Что бесплатно, а что нет

Бесплатный личный аккаунт GitHub — не пробная версия: приватные репозитории без ограничений по количеству, история, pull request и слияние. Платный GitHub вам не нужен.

Платным будет только ИИ-агент. На октябрь 2026 достаточно одной подписки из трёх:

Облачная машина, на которой агент запускает программы, входит в подписку и отдельно не оплачивается. Если подписка на Claude или ChatGPT уже есть, в этом модуле вы не потратите ничего.

Безопасность — два правила. Первое: в репозиторий кладём только обезличенные документы — роль вместо имени, без ИНН, адресов и паспортных данных, как в уроке 09: агент будет эти файлы читать. Второе: репозиторий с документами делаем Private — его видите только вы и те, кого вы добавили, а агенту доступ даёте отдельно, через приложение. Как именно — в следующих уроках модуля.

Проверьте себя

Зачем ИИ-агенту репозиторий, если документ можно просто вставить в чат?

  • Репозиторий ускоряет ответы агента
  • Это его рабочая папка: оттуда он читает документы, туда кладёт программу и результат, там вы видите изменения
  • Без репозитория агент не может выйти в интернет

Чтобы запустить программу на двадцати договорах и сохранить двадцать отчётов, нужны файлы и папка с историей и приёмкой — в чате их нет.

Что такое pull request для вас как для приёмщика?

  • Запрос агента на доступ к репозиторию
  • Заявка на платный тариф GitHub
  • Страница «посмотрите, что я сделал»: описание, список изменённых файлов, разница построчно и место для замечаний — до того как изменения попадут в основную версию

Pull request — ваш главный экран. Пока вы не нажали Merge, в основной версии ничего не меняется.

Что из этого вы будете делать руками в этом пути?

  • Загружать документы через Upload files, ставить задачу текстом и нажимать Merge pull request
  • Создавать ветку перед каждой задачей агента
  • Писать команды git в терминале

Ветки, коммиты и pull request делает агент. Ваша часть — положить документы, поставить задачу, проверить и принять.

За что придётся платить?

  • За приватные репозитории на GitHub
  • За подписку на ИИ-агента — Claude Pro, ChatGPT Plus или Copilot Pro; GitHub при этом бесплатный
  • За каждый час работы облачной машины агента отдельно

Приватные репозитории входят в бесплатный тариф GitHub. Облачная машина агента отдельно не оплачивается — только подписка, на октябрь 2026 от $10 до $20 в месяц.

Практика

Посмотрите на живой репозиторий, в котором каждый день работают люди, — документацию самого GitHub. Аккаунт не нужен, репозиторий публичный. Откройте github.com/github/docs и найдите четыре вещи.

  1. Под списком файлов — README, «обложка» проекта.
  2. Над списком файлов — ссылка с числом коммитов и иконкой часов: история с подписями, авторами и датами.
  3. Вкладка Pull requests: откройте любой открытый PR и прочитайте описание.
  4. В нём вкладка Files changed: разница построчно — зелёное добавлено, красное удалено. Так будут выглядеть результаты вашего агента.
  • Я открыл github.com/github/docs и нашёл README под списком файлов.
  • Я открыл историю по ссылке с числом коммитов и увидел, кто и когда вносил изменения.
  • Во вкладке Pull requests я открыл один PR и прочитал его описание.
  • Во вкладке Files changed я увидел зелёные (добавленные) и красные (удалённые) строки.
  • Я могу объяснить коллеге одной фразой, зачем ИИ-агенту репозиторий.

Вы знаете, зачем всё это. Дальше — аккаунт на GitHub, затем репозиторий с вашими документами и его подключение к Claude и ChatGPT.

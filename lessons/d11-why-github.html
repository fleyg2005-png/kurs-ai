Зачем GitHub, если код пишет ИИ

Ответ короткий: GitHub — рабочая папка для ИИ-агента. Без неё агенту негде читать ваши документы и некуда класть результат. Шесть минут — чтобы пять слов из мира программистов перестали мешать, а следующие уроки шли без вопроса «а это мне зачем».

Рабочая папка для агента

В модуле 3 вы отдавали ИИ документ прямо в чат и получали ответ там же. Для одного договора этого достаточно. Но представьте задачу побольше: проверить двадцать договоров поставки по одному чеклисту и свести сроки и штрафы в таблицу. Вставлять двадцать документов по одному и собирать ответы руками — та же рутина, только с ИИ.

Эту работу делает агент: он пишет небольшую программу, запускает её на всех документах сразу и складывает отчёты в папку. Для этого ему нужно место, где документы лежат и куда можно положить результат. В чате такого места нет — там только окно переписки. Это место — репозиторий на GitHub.

Документы в репозитории→ Задача ИИ→ ИИ пишет и запускает программу→ Pull request с результатом→ Ваша проверка→ Merge

Так будет выглядеть каждая задача до конца курса. Вы положили в репозиторий пять обезличенных договоров и чеклист. Написали агенту: «проверь каждый договор по чеклисту и сведи сроки и штрафы в таблицу». Агент написал программу, запустил её на своей облачной машине, сложил отчёты в папку reports/ и прислал результат на проверку. Вы прочитали отчёты, сверили пару цитат с договорами и нажали Merge. Код вы не видели и не писали — и не должны.

Пять слов: что вы увидите, когда ИИ поработал

Термины GitHub описывают не ваши действия, а то, что появится на экране после работы агента. Наведите на подчёркнутое слово, если потом забудете.

  • Репозиторий (repository) — ваша папка на GitHub: файлы и подпапки, как в проводнике, плюс полная история изменений. Один проект — один репозиторий: договоры и шаблоны отдела, кадровые регламенты, учётная политика.
  • Коммит (commit) — одна сохранённая порция изменений с подписью. Когда агент поработает, в истории появятся его записи вроде «Добавить отчёты по пяти договорам» — с датой и ссылкой на сессию, в которой он это сделал.
  • Ветка (branch) — черновик рядом с основной версией. Основная называется main; агент пишет в свою ветку, поэтому, пока вы не приняли результат, в main ничего не меняется.
  • Pull request (PR) — страница «посмотрите, что я сделал». В ней описание работы, список изменённых файлов, разница построчно (зелёное добавлено, красное удалено) и место для замечаний. Это ваш главный экран приёмки.
  • Merge (слияние) — кнопка «принять»: результат из ветки агента становится основной версией. Единственная кнопка в этом списке, которую нажимаете вы. Передумали — у слитого PR есть кнопка Revert, она отменяет изменения.

Заметьте: в списке нет ни одного действия, которое вы делаете руками, кроме последнего. Коммиты, ветки и pull request создаёт агент; вы их читаете.

Чего вы делать не будете

Программисты работают с GitHub через программу Git на компьютере и команды в терминале, сами создают ветки и открывают pull request. В этом пути всё это делает агент. Границу полезно провести сразу.

Не ваша работа

Ставить Git и писать команды. Создавать ветки. Открывать pull request. Писать и читать код. Делать сайты — в этом пути GitHub хранит документы, а не страницы.

Ваша работа

Положить документы в репозиторий кнопкой Upload files — это «перетащить файлы в папку», а не программирование. Поставить задачу текстом. Открыть pull request, прочитать результат, оставить замечания. Нажать Merge pull request — или попросить переделать, или закрыть PR.

Один раз, в уроке «Репозиторий с документами для ИИ», вы нажмёте кнопку Commit changes, загружая файлы. Это не исключение из правила: там она означает просто «сохранить». Все остальные коммиты в вашем репозитории будут подписаны агентом.

Почему именно репозиторий, а не папка в облаке

Логичный вопрос: документы уже лежат в общей папке отдела — на сетевом диске или в облаке. Почему бы не дать агенту её? Потому что папка умеет хранить файлы, и только. Репозиторий умеет ещё четыре вещи, без которых работа с агентом превращается в лотерею.

Общая папкаРепозиторий
ИсторияВерсии файла, если сервис их хранит и если не вышел срокКаждое изменение — коммит с подписью и датой, навсегда
Кто и что менял«Изменён: Иванова, вчера». Что именно — неизвестноПострочно: какие строки добавлены, какие удалены, в каком файле
ОткатИскать старую копию в почте и перепискеRevert одной кнопкой; любая прошлая версия открывается и копируется

ПриёмкаФайл перезаписан — и всёИзменения ждут в pull request, пока вы не нажмёте Merge

Последняя строка — главная. Агент может ошибиться: не так понять пункт чеклиста, перепутать стороны договора. В папке вы узнали бы об этом, когда файл уже перезаписан. В репозитории ошибка остаётся в ветке агента, вы видите её в PR и просто не принимаете.

Юридический отдел хранит шаблоны договоров и регламент согласования в общей папке на сервере. Раз в месяц выясняется, что кто-то поправил шаблон, и никто не помнит, что именно и когда. Руководитель хочет поручить ИИ проверять новые договоры по регламенту. Что изменится, если перенести эти файлы в репозиторий?

Четыре вещи. Каждая правка шаблона станет коммитом с подписью — видно, кто, когда и какие строки поменял. Любую прошлую версию можно открыть и вернуть одной кнопкой, не разыскивая её по почте. У агента появится рабочее место: он прочитает регламент и договоры из репозитория, запустит проверку и положит отчёты туда же. И появится приёмка: в основной версии ничего не изменится, пока руководитель не посмотрит pull request и не нажмёт Merge.

Что бесплатно, а что нет

Бесплатный личный аккаунт GitHub — не пробная версия. Приватные репозитории на нём без ограничений по количеству; история, pull request и слияние тоже бесплатны. Платный GitHub вам не нужен.

Платным будет только ИИ-агент. На октябрь 2026 достаточно одной подписки из трёх:

АгентПодпискаГде работает

Облачная машина, на которой агент запускает программы, отдельно не оплачивается — она входит в подписку. Если подписка на Claude или ChatGPT у вас уже есть, в этом модуле вы не потратите ничего.

Безопасность — два правила. Первое: в репозиторий кладём только обезличенные документы — роль вместо имени, без ИНН, адресов и паспортных данных, как в уроке 09. Агент и его облачная машина будут эти файлы читать. Второе: репозиторий с документами делаем Private — его видите только вы и те, кого вы добавили; агенту доступ вы даёте отдельно, через приложение. Как именно — в следующих уроках модуля.

Проверьте себя

Зачем ИИ-агенту репозиторий, если документ можно просто вставить в чат?

  • Репозиторий ускоряет ответы агента
  • Это его рабочая папка: оттуда он читает документы, туда кладёт программу и результат, и там вы видите, что именно изменилось
  • Без репозитория агент не может выйти в интернет

В чате есть только окно переписки. Чтобы запустить программу на двадцати договорах и сохранить двадцать отчётов, нужны файлы и папка — с историей и приёмкой.

Что такое pull request для вас как для приёмщика?

  • Запрос агента на доступ к репозиторию
  • Заявка на платный тариф GitHub
  • Страница «посмотрите, что я сделал»: описание, список изменённых файлов, разница построчно и место для замечаний — до того как изменения попадут в основную версию

Pull request — ваш главный экран. Пока вы не нажали Merge, в основной версии ничего не меняется.

Что из этого вы будете делать руками в этом пути?

  • Загружать документы через Upload files, ставить задачу текстом и нажимать Merge pull request
  • Создавать ветку перед каждой задачей агента
  • Писать команды git в терминале

Ветки, коммиты и pull request делает агент. Ваша часть — положить документы, поставить задачу, проверить и принять.

За что придётся платить?

  • За приватные репозитории на GitHub
  • За подписку на ИИ-агента — Claude Pro, ChatGPT Plus или Copilot Pro; GitHub при этом бесплатный
  • За каждый час работы облачной машины агента отдельно

Приватные репозитории входят в бесплатный тариф GitHub. Облачная машина агента отдельно не оплачивается — только подписка, на октябрь 2026 от $10 до $20 в месяц.

Практика

Посмотрите на живой репозиторий, в котором каждый день работают люди и агенты, — это документация самого GitHub. Аккаунт не нужен: репозиторий публичный. Откройте github.com/github/docs и найдите четыре вещи.

  1. Под списком файлов — README, «обложка» проекта: что это и как этим пользоваться.
  2. Над списком файлов — ссылка с числом коммитов и иконкой часов. Нажмите: это история — подписи, авторы, даты.
  3. Вкладка Pull requests. Откройте любой открытый PR и прочитайте описание: что сделано и зачем.
  4. В этом PR — вкладка Files changed: разница построчно, зелёное добавлено, красное удалено. Именно так будут выглядеть результаты вашего агента.
  • Я открыл github.com/github/docs и нашёл README под списком файлов.
  • Я открыл историю по ссылке с числом коммитов и увидел, кто и когда вносил изменения.
  • Во вкладке Pull requests я открыл один PR и прочитал его описание.
  • Во вкладке Files changed я увидел зелёные и красные строки и понял, какие добавлены, а какие удалены.
  • Я могу объяснить коллеге одной фразой, зачем ИИ-агенту репозиторий.

Вы знаете, зачем всё это. GitHub — рабочая папка агента с историей и приёмкой, а ваша роль — заказчик. Дальше — аккаунт на GitHub, затем репозиторий с вашими документами и его подключение к Claude и ChatGPT.

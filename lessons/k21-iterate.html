Доработки и повторные запуски

Инструмент работает — теперь его нужно развивать, не ломая. Вторая итерация, отчёт за месяц из шаблона, идёт по трём правилам; в конце — пять готовых задач агенту.

Три правила доработки

Одна доработка — одна задача — один PR

Отчёт за месяц — одна задача, проверка UTM-меток — другая. В одном PR вы не сможете принять первое и отклонить второе, а при откате потеряете оба.

«Не трогай то, что работает» — в каждом запросе

Агент охотно «улучшает» всё, до чего дотянется. Называйте, что менять нельзя: check_posts.py, reports/, posts/, campaigns/, — и сверяйте список файлов в Changes.

Новая сессия для новой задачи

Каждая сессия — своя ветка. Ветка первой задачи слита и удалена; новая задача начинается с чистой сессии на main, где инструмент уже лежит. В старой сессии агент тащит контекст прежней задачи.

Вторая итерация: отчёт за месяц из шаблона

В templates/otchet.md — шаблон отчёта с полями {месяц}, {кампания}, {показы}, {клики}, {CTR}, {расход}, {цена клика}, {вывод}. Агент подставит в них данные из выгрузки, посчитает CTR и цену клика и сохранит готовый отчёт в documents/. Семь шагов.

На claude.ai/code начните новую сессию, не продолжайте вчерашнюю: репозиторий marketing, ветка main (в ней уже лежит инструмент), режим Accept edits.

Текст готовый. Три защитные фразы: «программу проверки не трогай», «отчёты не пересоздавай», «покажи, откуда взято каждое число». Первые две берегут то, что работает, третья делает результат проверяемым.

Повторный запуск на новых файлах

Инструмент не следит за репозиторием: новые файлы он увидит, когда вы поставите задачу. Загрузите посты в posts/: Add file → Upload files → Commit changes — можно сразу несколько. Затем новая сессия на main:

Запрос к агенту — только новые файлы
Запусти проверку только для новых постов в posts/ — тех, у которых нет отчёта в reports/. Старые отчёты не пересоздавай, программу не меняй. Добавь в summary.md строки по новым постам, остальные строки не трогай. В описании PR перечисли проверенные файлы.

Новый месяц — новая выгрузка. Скачайте CSV из кабинета сами и загрузите через Upload files под тем же именем campaigns/campaigns.csv — файл заменит старый. Затем:

Запрос к агенту — новая выгрузка
Я обновил campaigns/campaigns.csv — это выгрузка за ноябрь. Пересобери в summary.md часть по кампаниям по новой выгрузке и собери отчёт за месяц в documents/otchet-noyabr.md по шаблону, как для октября. Посты, отчёты по постам и программу проверки не меняй. В описании PR покажи, откуда взято каждое число и как посчитаны CTR и цена клика.

Как агент ломает инструмент и как не допустить

Вы просите слишком много за раз

Пять пожеланий в одном сообщении — половина сделана, половина «почти», всё в одном PR: принять частями нельзя, откатить — только целиком. Одна задача на сессию.

Агент меняет программу при доработке

Добавляя отчёт за месяц, он «заодно» переписывает проверку постов — отчёты незаметно меняются. Фраза «не трогай» в запросе плюс список файлов в Changes. Тронул — «верни к состоянию main».

Длинные сессии

После десятка замечаний в одной сессии агент забывает ранние ограничения и смешивает задачи. После Merge сессию закрывайте; новая правка — новая сессия с именем файла и ссылкой на README.

Проверьте себя

Почему вторую итерацию делают в новой сессии, а не в той, где создавали инструмент?

  • Старая сессия удаляется автоматически после Create PR
  • Каждая задача — своя ветка; прежняя слита и удалена, а новая сессия начинается с main, где инструмент уже лежит
  • Чтобы не расходовать лимиты тарифа

Сессия живёт после PR, но её ветка уже влита в main. Новая задача на чистом main — проще для агента и прозрачнее для вас.

В Changes PR с отчётом за месяц оказались check_posts.py и все файлы из reports/. Что делать?

  • Слить: отчёты пересозданы из тех же постов, значит, одинаковые
  • Не сливать; попросить вернуть эти файлы к состоянию main и объяснить, что менялось
  • Исправить отчёты карандашом на GitHub

Вы просили не трогать программу и отчёты. Пересозданные отчёты могут отличаться незаметно — проверять их целиком дороже, чем вернуть.

В posts/ загрузили два новых поста. Как получить отчёты?

  • Подождать: агент заметит новые файлы и запустит проверку
  • Попросить пересоздать все отчёты заново
  • В новой сессии попросить проверить только файлы без отчёта, старые отчёты не пересоздавать

Агент работает только по вашей задаче. Пересоздавать всё — дольше, дороже и заставляет перепроверять уже принятые отчёты.

Практика

Пройдите степпер и сделайте один повторный запуск. Отмечайте только проверенное.

  • Вторая итерация слита отдельным PR; в Changes этого PR не было check_posts.py и файлов из reports/.
  • Каждое число отчёта за месяц я сверил(а) с campaigns.csv, а CTR и цену клика одной кампании пересчитал(а) на калькуляторе.
  • Новый пост загружен через Upload files и проверен задачей «только новые файлы»; PR слит.
  • В summary.md по постам строк столько же, сколько постов, по кампаниям — сколько строк в campaigns.csv.

Инструмент растёт, а не ломается. Следующий урок — как проверять результат инструмента, не читая код.

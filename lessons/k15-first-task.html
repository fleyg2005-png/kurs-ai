Первая задача: ИИ сам делает коммит и pull request

Агент прочитает ваши посты и выгрузку кампаний, перепишет README, сохранит изменения и пришлёт их на согласование. Вы увидите коммит, ветку и pull request в деле — и ни одного из них не сделаете руками.

Что сейчас произойдёт

Вы: задача→ Агент читает посты→ Пишет README, сохраняет (коммит)→ Pull request→ Вы: проверка→ Merge

Три слова, которые встретятся на экране. Коммит — агент сохранил версию файлов и подписал, что изменил. Ветка — он сделал это не в основной версии репозитория (main), а в отдельной копии, поэтому ваши посты в main нетронуты. Pull request — предложение «перенесите мои изменения в main», с точным списком, что изменится. Ваша роль — прочитать предложение и нажать Merge или вернуть на доработку.

По шагам

На claude.ai/code выберите в селекторе marketing, ветку main, режим Accept edits — как в прошлом уроке. Напомним: на октябрь 2026 Claude Code в браузере доступен на тарифах Pro, Max и Team.

Задача составлена по правилам модуля 3: что сделать, откуда брать данные, чего не делать, что написать в описании.

Create PR

Откройте один пост на GitHub во второй вкладке и сверьте его строку в таблице: площадка, дата, цель, отметка про UTM. Нашли расхождение — выделите строку в diff, напишите замечание и отправьте. Например: «в строке про post-keis.md площадка указана Telegram, а в шапке поста — VK. Исправь только эту строку». Агент внесёт правку, и числа в карточке Changes изменятся.

Если расхождений нет — всё равно отправьте одно замечание ради тренировки, например: «добавь в таблицу столбец „длина текста в знаках“». Так вы увидите цикл «замечание → правка» до того, как он понадобится всерьёз.

Нажмите Create PR. Агент создаст pull request с заголовком и описанием — там будет то, что вы просили: какие файлы прочитал и что непонятно. Сессия остаётся живой: замечания можно присылать и после.

Откройте ссылку. Вкладка Conversation — описание от агента и обсуждение. Вкладка Files changed — тот же diff: зелёное добавлено, красное удалено. У файлов .md GitHub умеет показывать результат как оформленный текст, а не как разметку — ищите кнопку просмотра над файлом. Так таблицу в README удобнее читать.

Merge pull request

Обратите внимание на Commits 2: два коммита — первая версия README и правка по вашему замечанию. Оба подписаны агентом, в каждом ссылка на сессию, где он работал.

Если всё верно — Merge pull request, затем Confirm merge. Появится Delete branch — нажмите: ветка агента больше не нужна, её коммиты уже в main. Откройте главную страницу репозитория: под списком файлов новый README с таблицей постов.

Что вы только что видели

Один цикл работы с ИИ-агентом целиком, и это тот же цикл, что у команд программистов. Агент сделал коммиты в своей ветке. Вы получили pull request — список изменений с описанием. Проверили не код, а результат: таблицу в README против шапок и текста постов. Отправили замечание — получили правку. Нажали Merge — изменения попали в main. Главное правило всего пути помещается в одну фразу.

Пока вы не нажали Merge, в репозитории ничего не изменилось. Всё, что делает агент, лежит в его ветке и ждёт вашего решения. Не нравится — закрываете pull request кнопкой Close pull request, и следов не остаётся. Слили, а потом передумали — у слитого PR есть кнопка Revert. Об этом урок «Когда ИИ сделал не то».

Проверьте себя

Агент написал README и отправил ветку. Что видят коллеги, у которых есть доступ к репозиторию, на главной странице?

  • Новый README
  • Пустую страницу, пока PR открыт
  • Старый README: изменения в ветке агента, в main они попадут после Merge

Ветка не трогает main. Это и есть защита: вы решаете, что попадёт в основную версию.

Что вы проверяете в pull request в первую очередь?

  • Правильность кода
  • Список изменённых файлов и факты в результате против содержимого постов
  • Количество коммитов

Тронут только README — агент не вышел за рамки. Факты в таблице сверены с шапками постов — результат верный. Код здесь не писался, а когда будет писаться, проверять всё равно результат.

Где оставить замечание так, чтобы агент сам внёс правку?

  • В сессии на claude.ai/code: к строке в diff или сообщением в чат
  • Исправить README руками через карандаш на GitHub
  • В письме в поддержку Anthropic

Сессия живёт и после создания PR. Правка руками сломала бы правило пути: git делает ИИ, вы ставите задачи и проверяете.

Что делает Delete branch после слияния?

  • Удаляет изменения агента из репозитория
  • Убирает ветку-черновик; её коммиты уже перенесены в main
  • Удаляет pull request из истории

После Merge ветка — пустой ярлык. История коммитов и сам PR остаются.

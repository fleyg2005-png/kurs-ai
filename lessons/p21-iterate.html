Доработки и повторные запуски

Инструмент работает — теперь его нужно развивать, не ломая. Вторая итерация, черновики ответов на отзывы, идёт по трём правилам; в конце — пять готовых задач агенту.

Три правила доработки

Одна доработка — одна задача — один PR

Ответы на отзывы — одна задача, свод цен — другая. В одном PR вы не сможете принять первое и отклонить второе, а при откате потеряете оба.

«Не трогай то, что работает» — в каждом запросе

Агент охотно «улучшает» всё, до чего дотянется. Называйте, что менять нельзя: check_cards.py, reports/, tovary/, — и сверяйте список файлов в Changes.

Новая сессия для новой задачи

Каждая сессия — своя ветка. Ветка первой задачи слита и удалена; новая задача начинается с чистой сессии на main, где инструмент уже лежит. В старой сессии агент тащит контекст прежней задачи.

Вторая итерация: ответы на отзывы

В templates/otvet-na-otzyv.md — шаблон ответа с полями {имя}, {товар}, {проблема}, {решение}. Агент возьмёт из выгрузки все отзывы с оценкой 1–3, заполнит шаблон по каждому и соберёт черновики в один файл. Семь шагов.

На claude.ai/code начните новую сессию, не продолжайте вчерашнюю: репозиторий shop, ветка main (в ней уже лежит инструмент), режим Accept edits.

Текст готовый. Обратите внимание на защитные фразы: «не обещай ничего, чего нет в карточке» запрещает выдумывать, «программу проверки не трогай» и «отчёты не пересоздавай» берегут то, что работает, а «откуда взято каждое поле» делает результат проверяемым.

Повторный запуск на новых файлах

Инструмент не следит за репозиторием: новые файлы он увидит, когда вы поставите задачу. Загрузите карточки в tovary/: Add file → Upload files → Commit changes — можно сразу несколько. Затем новая сессия на main:

Запрос к агенту — только новые файлы
Запусти проверку только для новых карточек в tovary/ — тех, у которых нет отчёта в reports/. Старые отчёты не пересоздавай, программу не меняй. Добавь в summary.md строки по новым товарам, остальные строки не трогай. В описании PR перечисли проверенные файлы.

Затем Create PR, сверить три строки нового отчёта, Merge pull request. Пришла свежая выгрузка отзывов — загрузите её через Upload files с тем же именем otzyvy.csv (новая версия встанет на место старой, прежняя останется в истории) и попросите обновить сводку:

Запрос к агенту — свежая выгрузка
В otzyvy/otzyvy.csv лежит свежая выгрузка. Пересчитай в summary.md колонку «число отзывов и средняя оценка» по новой выгрузке. Отчёты, программу и карточки не меняй. В описании PR покажи, какие строки изменились: было — стало.

Как агент ломает инструмент и как не допустить

Вы просите слишком много за раз

Пять пожеланий в одном сообщении — половина сделана, половина «почти», всё в одном PR: принять частями нельзя, откатить — только целиком. Одна задача на сессию.

Агент меняет программу при доработке

Добавляя ответы на отзывы, он «заодно» переписывает проверку — отчёты незаметно меняются. Фраза «не трогай» в запросе плюс список файлов в Changes. Тронул — «верни к состоянию main».

Длинные сессии

После десятка замечаний в одной сессии агент забывает ранние ограничения и смешивает задачи. После Merge сессию закрывайте; новая правка — новая сессия с именем файла и ссылкой на README.

Проверьте себя

Почему вторую итерацию делают в новой сессии, а не в той, где создавали инструмент?

  • Старая сессия удаляется автоматически после Create PR
  • Чтобы не расходовать лимиты тарифа
  • Каждая задача — своя ветка; прежняя слита и удалена, а новая сессия начинается с main, где инструмент уже лежит

Сессия живёт после PR, но её ветка уже влита в main. Новая задача на чистом main — проще для агента и прозрачнее для вас.

В Changes PR с ответами на отзывы оказались check_cards.py и все файлы из reports/. Что делать?

  • Не сливать; попросить вернуть эти файлы к состоянию main и объяснить, что менялось
  • Слить: отчёты пересозданы из тех же карточек, значит, одинаковые
  • Исправить отчёты карандашом на GitHub

Вы просили не трогать программу и отчёты. Пересозданные отчёты могут отличаться незаметно — проверять их целиком дороже, чем вернуть.

В tovary/ загрузили две новые карточки. Как получить отчёты?

  • Подождать: агент заметит новые файлы и запустит проверку
  • В новой сессии попросить проверить только карточки без отчёта, старые отчёты не пересоздавать
  • Попросить пересоздать все отчёты заново

Агент работает только по вашей задаче. Пересоздавать всё — дольше, дороже и заставляет перепроверять уже принятые отчёты.

Практика

Пройдите степпер и сделайте один повторный запуск. Отмечайте только проверенное.

  • Вторая итерация слита отдельным PR; в Changes этого PR не было check_cards.py и файлов из reports/.
  • Каждый ответ я сверил(а) с карточкой товара: обещаний, которых нет в карточке, не осталось.
  • Новая карточка (или свежая выгрузка отзывов) загружена через Upload files и обработана задачей «только новое»; PR слит.
  • В summary.md столько строк, сколько карточек в tovary/.

Инструмент растёт, а не ломается. Следующий урок — как проверять результат инструмента, не читая код.

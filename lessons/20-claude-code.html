Claude Code в браузере

Двенадцать шагов — и первый pull request, написанный агентом, слит в hello-ai, а сайт обновился. Откройте claude.ai/code в соседней вкладке и идите по шагам.

Что понадобится. Аккаунт Claude на тарифе Pro, Max или Team (на Free агента нет), аккаунт GitHub с репозиторием hello-ai, где уже работает GitHub Pages, и ТЗ калькулятора пени из урока 19 — оно повторено ниже, в шаге 7.

Первая задача: от входа до обновлённого сайта

Перейдите на claude.ai/code и войдите в свой аккаунт Claude. Нужен тариф Pro, Max или Team: на Free вместо рабочего экрана вы увидите сообщение вроде Claude Code isn't available on your account. Если платного тарифа нет — в уроке 21 есть бесплатный путь, а этот урок прочитайте, чтобы понимать общую логику.

Нажмите Sign in with GitHub. GitHub откроет страницу авторизации — он спрашивает, разрешить ли Claude доступ к вашему аккаунту. Нажмите Authorize, и вас вернёт на claude.ai/code.

Claude предложит установить Claude GitHub App — приложение, которое открывает агенту доступ к приватным репозиториям. Ваш hello-ai публичный, а публичные доступны сразу, поэтому нажмите Skip. Если позже понадобится приватный репозиторий — установите приложение по адресу github.com/apps/claude/installations/new: выбрать аккаунт и репозитории.

На Pro и Max рабочее окружение Default создаётся автоматически. Окружение — это настройки облачной машины, где Claude будет работать; у Default сетевой доступ Trusted: к вашему репозиторию и типовым хранилищам пакетов. Для сайта из одного файла этого достаточно, менять ничего не надо.

Под полем ввода — селектор репозитория. Откройте его и выберите hello-ai. Рядом показана ветка: оставьте main — Claude сам создаст от неё отдельную ветку для задачи.

Опишите, что нужно сделать в репозитории…
ivan-petrov/hello-ai ▾1main ▾2Accept edits ▾3
  1. Селектор репозитория.
  2. Ветка, от которой агент начнёт работу.
  3. Режим разрешений — о нём следующий шаг.

Рядом с селектором — режим разрешений. Их три:

  • Accept edits — Claude меняет файлы и пушит ветку, не спрашивая разрешения на каждую правку. Для своего учебного репозитория — лучший выбор: результат всё равно пройдёт через ваш pull request.
  • Plan — сначала предлагает план и ждёт одобрения. Пригодится для большой задачи, когда вы хотите сверить подход до начала работы.
  • Auto — каждое действие проверяет автоматический классификатор: безопасные пропускает, рискованные останавливает.

Для первой задачи выберите Accept edits.

Скопируйте ТЗ и вставьте в поле ввода. Перед отправкой пробегите глазами: назван файл index.html, есть пример для проверки, есть «не трогай».

Запрос к агенту — первая задача
Задача: добавь на главную страницу сайта (файл index.html) раздел «Калькулятор пени».

Цель: посетитель вводит сумму долга, ставку и срок просрочки и сразу видит сумму пени и формулу расчёта.

Где: index.html, новый раздел в конце страницы, перед закрывающим </body>. Стили и скрипт — внутри этого же файла.

Поведение:
— три поля ввода: «Сумма долга, ₽», «Ставка, % в день», «Дней просрочки»;
— кнопка «Рассчитать»;
— под кнопкой появляется результат: сумма пени с двумя знаками после запятой и формула словами: сумма × ставка / 100 × дни;
— если поле пустое или число отрицательное, показывай надпись «Проверьте введённые значения» и ничего не считай.
Пример: 100 000 ₽, 0,1 % в день, 30 дней → 3 000,00 ₽.

Критерии готовности:
— пример выше даёт 3 000,00 ₽;
— при пустом или отрицательном поле виден текст ошибки, а результата нет;
— раздел нормально выглядит на телефоне.

Не трогай: остальные разделы страницы, README.md и другие файлы.

Ограничения: без внешних библиотек и загрузки скриптов с других сайтов; весь текст интерфейса на русском; все изменения — только в index.html.

Когда закончишь, напиши коротко: что изменил и как мне проверить результат на сайте.

Нажмите Enter. Claude клонирует репозиторий в изолированную виртуальную машину в облаке и начинает работать: изучает файлы, правит index.html, запускает проверки, затем пушит ветку. В чате видно, что он делает в каждый момент. Можно следить и подсказывать, а можно закрыть вкладку и вернуться позже — сессия продолжается в облаке.

Найдите в diff строку, которую хотите поправить, выделите её и напишите замечание — например: «Добавь к результату знак ₽ и разделители тысяч: 3 000,00 ₽». Замечание прикрепится к строке и уйдёт вместе с вашим следующим сообщением. Отправьте сообщение и дождитесь ответа: Claude внесёт правку, карточка Changes обновится.

Добавь к результату знак ₽ и разделители тысяч: 3 000,00 ₽.
Готово: результат выводится как «3 000,00 ₽», разряды разделены пробелами. Изменена одна строка в функции расчёта, остальное не трогал.

Нажмите Create PR. Claude создаст в вашем репозитории pull request с заголовком и описанием того, что сделано. Хотите сначала показать коллеге черновик — правый клик по кнопке → Create draft PR. Сессия остаётся живой: правки можно присылать и после создания PR, они попадут в него же.

Откройте ссылку на PR. Вкладка Files changed — тот же diff. Прочитайте описание, убедитесь, что всё как договаривались, и нажмите Merge pull request → Confirm merge, затем Delete branch. Через 1–10 минут откройте https://username.github.io/hello-ai/: внизу страницы калькулятор. Введите пример из ТЗ: 100 000, 0,1, 30 — должно получиться 3 000,00 ₽.

Что тратится

Сессии Claude Code расходуют лимиты вашего тарифа — те же, что и чат: скользящие 5-часовые окна плюс недельный лимит. Виртуальная машина, в которой работает агент, отдельно не оплачивается. Одна задача агента — это десятки обращений к модели, поэтому она расходует заметно больше, чем вопрос в чате. Точные числа Anthropic меняет, курс их не называет; если лимит окна исчерпан, продолжить можно с началом следующего.

Несколько задач параллельно

Каждая задача — отдельная сессия и отдельная ветка, и ничто не мешает запустить две-три одновременно: калькулятор в одной, раздел «Контакты» в другой. Одно правило: не давайте двум сессиям менять одно и то же место в одном файле, иначе при слиянии второго PR получите конфликт (урок 18). Безопаснее — задачи в разные разделы и слияние по одной.

С телефона

Задачу можно поставить из приложения Claude: вкладка Code. Удобно отправить ТЗ в дороге, а diff проверить и PR слить уже за компьютером — сессия та же.

Типовые проблемы

В списке нет моего репозитория

Он приватный, а Claude GitHub App не установлено. Установите по адресу github.com/apps/claude/installations/new, выберите аккаунт и репозиторий, вернитесь и обновите список. Публичные репозитории видны сразу.

«Claude Code isn't available on your account»

Вы на тарифе Free. Агент доступен на Pro ($20/мес), Max и Team. Альтернатива без оплаты — Codespaces + Copilot Free из урока 21.

Claude задаёт вопрос и ждёт

Ответьте в чате — он продолжит. Запомните, что именно он спросил: это ровно то, чего не хватало в ТЗ. В следующий раз добавьте это сразу.

Проверьте себя

В каком режиме Claude сначала показывает план и ждёт вашего одобрения?

  • Plan
  • Accept edits
  • Auto

Accept edits правит и пушит без вопросов, Auto пропускает действия через автоматический классификатор. План перед работой показывает только Plan.

Вы закрыли вкладку браузера, пока Claude работал над задачей. Что произошло?

  • Сессия остановилась, правки потеряны
  • Сессия остановилась, но ветка уже запушена
  • Ничего: сессия продолжается в облаке, можно вернуться позже

Агент работает в виртуальной машине в облаке, а не в вашей вкладке. Закрытие вкладки сессию не останавливает.

Что делает кнопка Create PR?

  • Сразу сливает изменения в main и публикует сайт
  • Создаёт pull request с заголовком и описанием; сессия остаётся живой для правок
  • Завершает сессию и удаляет виртуальную машину

Слияние остаётся за вами и делается на GitHub. После Create PR можно продолжать присылать замечания — они попадут в тот же PR.

Приватного репозитория нет в селекторе. Самая вероятная причина?

  • Не установлено Claude GitHub App для этого репозитория
  • Репозиторий слишком большой
  • Нужно сначала создать ветку вручную

Публичные репозитории доступны сразу после Sign in with GitHub, приватные — только через Claude GitHub App.

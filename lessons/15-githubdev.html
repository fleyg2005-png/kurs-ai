github.dev: нажмите точку

Карандаш на github.com хорош для одной правки в одном файле. Когда файлов несколько, нужен редактор. Он у вас уже есть: одна клавиша открывает VS Code прямо в браузере, без установки. Откройте репозиторий hello-ai в соседней вкладке.

Что это такое

github.dev — редактор кода VS Code, запущенный во вкладке браузера и подключённый к вашему репозиторию. Тот же редактор, которым пользуются программисты, только ничего не установлено: закрыли вкладку — на компьютере ничего не осталось. Он умеет открывать много файлов, искать по всему проекту, подсвечивать разметку и делать коммиты. Не умеет запускать код — для этого в следующем уроке будет Codespaces.

Зайдите на github.com/ваш-username/hello-ai. Важно быть на странице репозитория со списком файлов, а не в настройках или истории.

Просто нажмите на клавиатуре . (точку). Страница перезагрузится, а адрес сменится с github.com/… на github.dev/…. Второй способ, если точка не сработала (например, курсор стоял в поле поиска): вручную замените в адресной строке github.com на github.dev и нажмите Enter.

https://github.devбыло .com/username/hello-ai

Первый запуск занимает 10–20 секунд: редактор загружается в браузер. Ставить ничего не нужно.

Область редактора: откройте файл слева3

  1. Полоска иконок у левого края. Три из них нужны: Explorer (файлы), Search (поиск по всем файлам проекта), Source Control (коммиты — иконка с ветвящимися линиями).
  2. Explorer — дерево файлов репозитория. Те же три файла, что на github.com.
  3. Редактор — справа. Каждый открытый файл — отдельная вкладка вверху.

В Explorer нажмите на index.html. Файл откроется справа; теги и текст подсвечены разными цветами — это помогает не потерять закрывающую скобку.

<ul> <li>Веду учёт малого бизнеса 12 лет</li> <li>Автоматизирую сверку актов с помощью ИИ</li> <li>Этот сайт сделан без единой установленной программы</li> <li>Четвёртый пункт из урока 14</li> </ul>

Добавьте в список ещё одну строку — например, <li>Умею редактировать сайт в github.dev</li> перед </ul>. Нажмите Ctrl+S (на Mac — ⌘+S). Пока файл не сохранён, на его вкладке вместо крестика стоит точка.

Сохранено ≠ закоммичено. Ctrl+S сохраняет файл только в вашем браузере. В репозитории на GitHub ничего не изменится, пока вы не сделаете коммит. Несохранённые в репозиторий правки живут только в этом браузере: на другом компьютере или после очистки данных браузера их не будет.

Нажмите иконку Source Control в левой полоске (ветвящиеся линии; на ней появился кружок с цифрой 1 — число изменённых файлов). Откроется панель: вверху поле для сообщения, ниже раздел Changes (изменения) со списком файлов. У index.html стоит буква M — modified, изменён.

SOURCE CONTROL
Message
✓ Commit & Push
Changes  1
index.html  ＋stage  M

Нажмите на файл в списке Changes — справа откроется сравнение: слева было, справа стало.

Наведите на index.html в списке Changes и нажмите + справа от имени. Файл переедет в раздел подготовленных изменений (Staged Changes). Это ответ на вопрос «что войдёт в коммит»: можно изменить пять файлов, а закоммитить два. Если файлов несколько и нужны все — нажмите + у заголовка Changes.

В поле Message вверху панели напишите сообщение коммита: Добавить пункт про github.dev в список. Нажмите Commit & Push. Коммит создан и сразу отправлен (push — «отправить») в репозиторий на GitHub; панель опустела.

Вернитесь на github.com/ваш-username/hello-ai (замените в адресе github.dev обратно на github.com). Счётчик коммитов над файлами вырос на один, рядом с index.html — ваше сообщение. Через несколько минут строка появится и на сайте.

Всё из правой колонки есть в Codespaces — это следующий урок. Но для большинства правок в текстах и страницах github.dev достаточно, и он открывается за секунды.

Карандаш, точка или Codespaces

Карандаш на github.com

Одна правка в одном файле: опечатка в README, новый пункт в списке, поменять дату. Открыть файл → карандаш → коммит. Быстрее ничего нет.

github.dev

Несколько файлов за раз, поиск по проекту, большие правки текста. Например, поменять название компании в index.html, README.md и notes.md одним коммитом.

Codespaces

Нужно что-то запустить, проверить, установить или поработать в терминале. Следующий урок.

Две горячие клавиши

  • Ctrl+S — сохранить файл в браузере. Напоминание: это ещё не коммит.
  • Ctrl+P — открыть файл по имени: начните печатать ind, и редактор предложит index.html. Когда файлов десятки, быстрее, чем искать в дереве.

На Mac вместо Ctrl — ⌘. Остальные сочетания пока не нужны.

Проверьте себя

Вы изменили файл в github.dev и нажали Ctrl+S. Что произошло с репозиторием на GitHub?

  • Создан новый коммит с изменением
  • Ничего: файл сохранён только в браузере, в репозиторий он попадёт после Commit & Push
  • Файл отправлен на сайт, но без записи в истории

В github.dev сохранение и коммит — разные действия. Пока не нажата Commit & Push, на GitHub ничего не меняется.

Что делает «+» у файла в панели Source Control?

  • Создаёт копию файла
  • Подготавливает (stage) файл — отмечает, что он войдёт в следующий коммит
  • Добавляет файл в избранное

Подготовка позволяет выбрать, какие из изменённых файлов попадут в коммит, а какие подождут. Если нужны все — «+» у заголовка Changes.

Чего нельзя сделать в github.dev?

  • Отредактировать два файла и закоммитить их вместе
  • Найти слово во всех файлах проекта
  • Открыть терминал и запустить команду

github.dev — только редактор. Терминал и запуск кода — в Codespaces.

Практика

Одним коммитом исправьте два файла. В README.md добавьте строку с адресом сайта: Сайт: https://ваш-username.github.io/hello-ai/. В notes.md добавьте четвёртый пункт списка. Всё — через github.dev, не через карандаш.

  • Открыл(а) github.dev клавишей «.» и вижу все три файла в Explorer.
  • Изменил(а) README.md и notes.md, оба сохранены — на вкладках нет точек.
  • В Source Control оба файла подготовлены через «+», сообщение написано, нажата Commit & Push.
  • На github.com в истории ровно один новый коммит, и, открыв его, я вижу изменения в двух файлах.
  • Через Search нашёл(а), в каких файлах проекта встречается слово «ИИ».

Редактор есть. Теперь вы можете менять проект целиком, а не по одному файлу, и это тот же инструмент, в котором работают программисты. Следующий урок добавляет к нему компьютер в облаке — с терминалом.

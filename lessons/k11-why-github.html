Зачем GitHub маркетологу

Ответ короткий: GitHub — рабочая папка для ИИ-агента. Без неё агенту негде читать ваши посты и выгрузки и некуда класть отчёты. Шесть минут — чтобы пять слов из мира программистов перестали мешать.

Рабочая папка для агента

В модуле 3 вы отдавали ИИ текст в чат и получали ответ там же. Для одного поста достаточно. Но проверить двадцать постов по одному чеклисту и свести три выгрузки рекламных кампаний в один отчёт — значит вставлять тексты по одному и собирать ответы руками. Та же рутина, только с ИИ.

Эту работу делает агент: пишет небольшую программу, запускает её на всех файлах сразу и складывает отчёты в папку. Ему нужно место, где лежат посты и выгрузки и куда положить результат; в чате такого места нет. Это место — репозиторий на GitHub.

Посты и выгрузки в репозитории→ Задача ИИ→ ИИ пишет и запускает программу→ Pull request с результатом→ Ваша проверка→ Merge

Так будет выглядеть каждая задача до конца курса. Вы положили в репозиторий посты, чеклист поста и выгрузку кампаний и написали агенту: «проверь каждый пост по чеклисту, сведи кампании из выгрузки в таблицу». Агент написал программу, запустил её на своей облачной машине, сложил отчёты в папку reports/ и прислал результат на проверку. Вы прочитали отчёты и нажали Merge. Код вы не видели — и не должны.

Сразу про границы. Курс не учит настраивать рекламные кабинеты, а агент не публикует посты, не запускает кампании и сам не забирает статистику из кабинетов. Репозиторий — подготовительная кухня: тексты и отчёты готовятся здесь, а публикуете посты и выгружаете статистику (CSV из кабинета) вы.

Пять слов: что вы увидите, когда ИИ поработал

Эти термины описывают не ваши действия, а то, что появится на экране после работы агента. Забудете — наведите на подчёркнутое слово.

  • Репозиторий (repository) — ваша папка на GitHub: файлы и подпапки, как в проводнике, плюс полная история изменений. Один проект — один репозиторий.
  • Коммит (commit) — одна сохранённая порция изменений с подписью. После работы агента в истории появятся его записи вроде «Добавить отчёты по шести постам» — с датой и ссылкой на сессию.
  • Ветка (branch) — черновик рядом с основной версией main. Агент пишет в свою ветку, поэтому, пока вы не приняли результат, в main ничего не меняется.
  • Pull request (PR) — страница «посмотрите, что я сделал»: описание работы, список изменённых файлов, разница построчно (зелёное добавлено, красное удалено) и место для замечаний. Ваш главный экран.
  • Merge (слияние) — кнопка «принять»: результат из ветки агента становится основной версией. Единственное в этом списке, что делаете вы. Передумали — у слитого PR есть кнопка Revert.

Коммиты, ветки и pull request создаёт агент; вы их читаете и принимаете.

Чего вы делать не будете

Программисты работают с GitHub через программу Git на компьютере, сами создают ветки и открывают pull request. Здесь всё это делает агент. Границу полезно провести сразу.

Не ваша работа

Ставить Git и писать команды. Создавать ветки и открывать pull request. Писать и читать код. Делать сайты: здесь GitHub хранит тексты и выгрузки, а не страницы.

Ваша работа

Положить посты и выгрузки в репозиторий кнопкой Upload files — это «перетащить файлы в папку». Поставить задачу текстом. Открыть pull request, прочитать отчёты, оставить замечания. Нажать Merge pull request — или попросить переделать, или закрыть PR.

Один раз, загружая файлы в уроке 13, вы нажмёте кнопку Commit changes. Там она означает просто «сохранить»; все остальные коммиты в вашем репозитории будут подписаны агентом.

Почему именно репозиторий, а не папка в облаке

Рабочие тексты и так где-то лежат: посты — в заметках и мессенджерах, согласованные версии — в файлах вида финальная_версия_2.docx, выгрузки — в почте. Почему не сложить всё в общую папку в облаке и не дать агенту её? Папка умеет только хранить файлы; репозиторий умеет ещё четыре вещи, без которых работа с агентом превращается в лотерею.

Последняя строка — главная. Если агент ошибся — перепутал кампании в сводной таблице, приписал посту призыв к действию, которого там нет, — ошибка остаётся в его ветке: вы видите её в PR и не принимаете. В папке файл был бы уже перезаписан.

Отдел маркетинга хранит посты в заметках и мессенджерах, согласованные версии — в файлах вида финальная_версия_2.docx. Раз в месяц выясняется, что опубликована не та версия, и никто не помнит, какую согласовали; отчёт клиенту собирается ночью из трёх выгрузок. Руководитель хочет поручить ИИ проверять посты по чеклисту перед публикацией и собирать отчёт по кампаниям. Что изменится, если перенести файлы в репозиторий?

Четыре вещи. Каждая правка поста станет коммитом с подписью — видно, кто, когда и какие строки поменял, а согласованная версия — это просто текущая версия в main. Любую прошлую версию можно вернуть одной кнопкой, не разыскивая её по чатам. У агента появится рабочее место: он прочитает чеклист, посты и выгрузки из репозитория и положит отчёты туда же. И появится приёмка: в основной версии ничего не изменится, пока руководитель не посмотрит pull request и не нажмёт Merge.

Что бесплатно, а что нет

Бесплатный личный аккаунт GitHub — не пробная версия: приватные репозитории без ограничений по количеству, история, pull request и слияние. Платный GitHub вам не нужен.

Платным будет только ИИ-агент. На октябрь 2026 достаточно одной подписки из трёх:

АгентПодпискаГде работает
Claude Code в браузереClaude Pro — $20/мес (на Free недоступен)claude.ai/code; основной инструмент этого пути
CodexChatGPT Plus — $20/мес (на Free и Go недоступен)chatgpt.com/codex
Copilot cloud agentCopilot Pro — $10/мес; бесплатно студентам, преподавателям и мейнтейнерам популярных open source-проектовПрямо на GitHub: задача — issue, результат — pull request

Облачная машина, на которой агент запускает программы, входит в подписку и отдельно не оплачивается. Если подписка уже есть, в этом модуле вы не потратите ничего.

Безопасность — два правила. Первое: персональные данные людей в репозиторий не кладём — имена, почты и телефоны клиентов и подписчиков из CRM и рассылок, как в уроке 09: агент будет эти файлы читать. Остальное обезличивать не обязательно: свои посты, контент-план и статистику кампаний можно брать как есть, если договор с клиентом не запрещает передавать его данные сторонним сервисам. Второе: репозиторий с рабочими файлами делаем Private — его видите только вы и те, кого вы добавили, а агенту доступ даёте отдельно, через приложение. Как именно — в следующих уроках модуля.

Проверьте себя

Зачем ИИ-агенту репозиторий, если пост можно просто вставить в чат?

  • Репозиторий ускоряет ответы агента
  • Это его рабочая папка: оттуда он читает посты и выгрузки, туда кладёт программу и отчёты, там вы видите изменения
  • Без репозитория агент не сможет публиковать посты

Чтобы запустить программу на двадцати постах и сохранить двадцать отчётов, нужны файлы и папка с историей и приёмкой — в чате их нет. А публиковать посты агент не будет и с репозиторием: публикация остаётся за вами.

Что такое pull request для вас как для приёмщика?

  • Страница «посмотрите, что я сделал»: список изменённых файлов, разница построчно и место для замечаний — до попадания изменений в основную версию
  • Запрос агента на доступ к репозиторию
  • Заявка на платный тариф GitHub

Pull request — ваш главный экран. Пока вы не нажали Merge, в основной версии ничего не меняется.

Что из этого вы будете делать руками в этом пути?

  • Создавать ветку перед каждой задачей агента
  • Писать команды git в терминале
  • Загружать посты и выгрузки через Upload files, ставить задачу текстом и нажимать Merge pull request

Ветки, коммиты и pull request делает агент. Ваша часть — положить файлы, поставить задачу, проверить и принять.

За что придётся платить?

  • За приватные репозитории на GitHub
  • За подписку на ИИ-агента — Claude Pro, ChatGPT Plus или Copilot Pro; GitHub при этом бесплатный
  • За часы работы облачной машины агента

Приватные репозитории входят в бесплатный тариф GitHub. Облачная машина агента отдельно не оплачивается — только подписка, от $10 до $20 в месяц.

Практика

Посмотрите на живой репозиторий — документацию самого GitHub. Аккаунт не нужен, репозиторий публичный. Откройте github.com/github/docs и найдите четыре вещи.

  1. Под списком файлов — README, «обложка» проекта.
  2. Над списком файлов — ссылка с числом коммитов и иконкой часов: история с подписями, авторами и датами.
  3. Вкладка Pull requests: откройте любой открытый PR и прочитайте описание.
  4. В нём вкладка Files changed: разница построчно — зелёное добавлено, красное удалено. Так будут выглядеть результаты вашего агента.
  • Я открыл github.com/github/docs и нашёл README под списком файлов.
  • Я открыл историю по ссылке с числом коммитов и увидел, кто и когда вносил изменения.
  • Во вкладке Pull requests я открыл один PR и прочитал его описание.
  • Во вкладке Files changed я увидел зелёные (добавленные) и красные (удалённые) строки.
  • Я могу объяснить коллеге одной фразой, зачем ИИ-агенту репозиторий.

Вы знаете, зачем всё это. Дальше — аккаунт на GitHub, затем репозиторий с вашими постами и выгрузками и его подключение к Claude и ChatGPT.

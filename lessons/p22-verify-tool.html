Как проверять результат инструмента

Код читать не нужно, и делать вид, что нужно, мы не будем. Проверяется результат: сводка, отчёты, черновики ответов — так же, как вы проверяете работу стажёра. Четыре проверки, три вопроса агенту и список красных флагов.

Что вы проверяете на самом деле

Инструмент — это программа плюс то, что она произвела. Программа для вас закрыта: вы не отличите хороший код от плохого, и это нормально. Зато результат — строку сводки по вашему товару — вы проверите лучше любого программиста, потому что знаете, что написано в карточке и на что жалуются покупатели.

Логика простая. Результат верен на выборке и полон — PR можно сливать. Результат расходится с файлами — замечание агенту, он правит программу и запускает её снова, вы проверяете ещё раз. Что внутри программы изменилось, вас не касается; касается только то, что сводка теперь совпадает с карточками.

Четыре проверки

1. Выборочная: три строки summary.md по карточкам

Откройте summary.md и выберите три значения из разных строк: цену товара со скидкой, остаток и название. Рядом откройте карточку из tovary/ — она читается в браузере — и ищите поиском (Ctrl+F). По каждому значению три вопроса:

  • Значение есть в карточке дословно? Поиск по числу или названию должен его найти. Не нашёл — значение пересказано или выдумано.
  • Взято из того поля? Цена — из строки «Цена», а не «Цена до скидки»; остаток — из строки «Остаток», а не из габаритов.
  • Товар тот самый? Строка не съехала: цена одного товара, остаток другого — так бывает.

Тот же приём — для отчётов в reports/: цитата из карточки находится поиском дословно, пункт чеклиста тот, а у «не выполнено» в карточке действительно пусто.

2. Пересчёт: средняя оценка одного товара — руками

Число отзывов и среднюю оценку по карточке не сверишь — программа их вычислила. Проверьте одну: откройте otzyvy/otzyvy.csv, найдите поиском строки одного товара и выпишите оценки. У термокружки девять строк: 5, 5, 5, 4, 4, 4, 4, 3, 2 — сумма 36, делим на 9, получаем 4,0. В summary.md должно стоять «9 / 4,0». Одного товара достаточно: если расчёт в программе неверный, он неверный для всех строк сразу.

3. Полнота: все ли товары на месте

Считайте. Карточек в tovary/ столько же, сколько отчётов в reports/, и столько же строк в summary.md. В каждом отчёте столько строк, сколько пунктов в checklist.md. Не сходится — агент молча пропустил файл или пункт, чаще всего потому, что не смог его прочитать. Молчание здесь хуже ошибки: спросите, что случилось.

4. Граничные случаи: где инструмент склонен врать

Если среди ваших товаров есть такой — проверьте его строку первым делом. Нет — задайте агенту второй вопрос из следующего раздела.

Спросите агента

Сессия жива после Create PR — три вопроса можно отправить прямо в неё. Ответы агента тоже проверяйте выборочно: одно-два названных значения найдите в файлах.

Запрос к агенту — источники
Для каждой строки summary.md напиши, откуда взято каждое значение: для названия, цены и остатка — дословная строка карточки, для числа отзывов и средней оценки — сколько строк otzyvy.csv учтено. Если источника нет — напиши «источника нет» и объясни, откуда значение. Ничего в файлах не меняй.
Запрос к агенту — сомнения
Что ты не смог прочитать или понял неуверенно? Перечисли карточки, пункты чеклиста и строки выгрузки, в которых сомневался, и почему. Ничего не исправляй, просто ответь.
Запрос к агенту — самопроверка
Проверь сам свой результат как придирчивый менеджер маркетплейса: открой каждый отчёт, сравни каждую цитату с карточкой, пересчитай число отзывов и среднюю оценку по otzyvy.csv для каждого товара и перечисли расхождения списком с именами файлов. Ничего не исправляй, пока я не скажу.

Красные флаги

  • Данные, которых нет в файлах. В отчёте у термокружки «держит тепло 12 часов», а в карточке — «до 6 часов». Правдоподобность не аргумент: инструмент не должен знать ничего сверх файлов репозитория.
  • Файлы в tovary/, checklist.md или otzyvy/ изменены. Видно в Changes и в Files changed. Даже «поправил опечатки в карточке» — не сливать, попросить вернуть.
  • Предложение отправить файлы во внешний сервис — «прогнать отзывы через онлайн-сервис аналитики», «загрузить карточки в стороннюю таблицу». Файлы остаются в репозитории и в машине агента. Отказывайте и просите решить задачу у себя.
  • «Должно работать». В PR есть программа, но нет отчётов, или в описании написано «после запуска появятся». Агент не запускал программу. Результат — файлы в репозитории, а не обещание.

Правило. Не сливайте PR с результатами, которые не проверили хотя бы выборочно. Ответственность за карточку, которая уйдёт на витрину, и за ответ, который прочитает покупатель, остаётся на менеджере. Агент её не несёт и нести не может.

Найдите проблему

Строка из summary.md:

lampa.md — Лампа настольная с диммером — 1 890 ₽ — остаток 37 — 5 отзывов, средняя 4,3 — не выполнено: 3

Строки лампы в otzyvy/otzyvy.csv, колонка «оценка»:

5, 4, 4, 3, 3

Что не так и что написать агенту?

Число отзывов верное, а средняя — нет: 5 + 4 + 4 + 3 + 3 = 19, делим на 5 — получается 3,8, а не 4,3. Откуда 4,3? Похоже на среднюю по всей выгрузке сразу: программа не отобрала строки своего товара. Догадка проверяется за минуту: у пледа два отзыва по 5, средняя должна быть 5,0 — если и там 4,3, расчёт общий. Такая ошибка искажает каждую строку сводки, а по сводке вы решаете, какую карточку спасать первой. Сливать нельзя. Замечание: «В summary.md у lampa.md средняя 4,3, а по otzyvy.csv оценки лампы 5, 4, 4, 3, 3 — средняя 3,8. Похоже, средняя посчитана по всей выгрузке, а не по товару. Исправь: число отзывов и среднюю считай только по строкам своего товара, пересчитай все строки summary.md и перечисли, что изменилось. Больше ничего не трогай».

Чеклист проверки результата

Шесть пунктов на каждый PR с результатами инструмента. Отмечайте только то, что проверили сами.

  • В Changes и Files changed нет файлов из tovary/, checklist.md и otzyvy/.
  • Отчётов столько же, сколько карточек; строк в summary.md столько же; в каждом отчёте все пункты чеклиста.
  • Три строки summary.md сверены с карточками: название, цена и остаток найдены дословно и взяты из нужных полей.
  • Средняя оценка одного товара пересчитана по otzyvy.csv вручную и совпала со сводкой.
  • У пунктов «не выполнено» цитаты пустые; характеристик, которых нет в карточках, в результатах нет.
  • В описании PR агент назвал, что не получилось и что не смог прочитать, и это совпадает с тем, что я вижу; внешних сервисов он не предлагал.

Проверьте себя

В summary.md у термокружки цена 1 590 ₽, а в карточке: «Цена: 1 290 ₽. Цена до скидки: 1 590 ₽». Ваше решение?

  • Слить: число из карточки, разница небольшая
  • Исправить цену в summary.md карандашом и слить
  • Не сливать; замечание агенту: программа берёт цену из строки «Цена до скидки» — исправить и проверить все строки

Перепутанные поля — ошибка программы, она повторяется в каждой строке и вернётся при следующем запуске. Правка руками лечит симптом, а не причину.

В tovary/ четыре карточки, в reports/ три отчёта, в summary.md четыре строки. Что это значит?

  • Один товар не обработан — скорее всего, не прочитан; его строка в summary.md может быть выдумана. Спросить агента, не сливать
  • Нормально: три из четырёх — хороший результат
  • Лишнюю карточку нужно удалить из tovary/

Проверка полноты поймала молчаливый пропуск. Четвёртая строка сводки без отчёта — вопрос «откуда данные?», который нужно задать агенту.

В PR есть программа, папка reports/ пустая, в описании: «отчёты появятся после запуска». Что делать?

  • Слить: после Merge GitHub запустит программу сам
  • Не сливать; попросить агента запустить программу у себя и положить отчёты в PR
  • Слить и запустить программу самостоятельно

Результат инструмента — файлы в репозитории. GitHub при слиянии ничего не запускает, а у вас для запуска ничего не установлено — и не нужно.

Инструмент подготовил ответ на отзыв, вы опубликовали его в кабинете маркетплейса, обещание оказалось неверным. Кто отвечает?

  • Разработчик модели
  • Менеджер, который опубликовал ответ, не сверив обещание с карточкой
  • Никто: это был черновик

Инструмент — помощник. Проверка хотя бы выборочная и публикация в кабинете — ваши.

Практика

Откройте последний PR с результатами инструмента — слитый тоже подойдёт, его Files changed никуда не делся. Пройдите по чеклисту из шести пунктов и задайте агенту хотя бы один вопрос из раздела «Спросите агента».

  • Я прошёл(ла) по последнему PR все шесть пунктов чеклиста и отметил(а) только проверенное.
  • Три строки summary.md сверены с карточками, средняя оценка одного товара пересчитана по otzyvy.csv.
  • Я задал(а) агенту хотя бы один вопрос из раздела «Спросите агента» и сверил(а) одно значение из его ответа с файлами.
  • Решение принято: PR слит, либо остаётся открытым до исправления.

Вы умеете принимать результат инструмента, не читая код. Дальше контрольная: свой инструмент по собственному ТЗ — от задачи до повторного запуска.

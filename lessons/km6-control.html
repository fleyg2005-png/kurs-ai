Контрольная 6: инструмент по вашему ТЗ

Без подсказок и степперов: сами, от ТЗ на свой инструмент до слитого PR и повторного запуска на новом посте. Всё это вы делали в уроках 19–22.

Задание

  1. Выберите инструмент — не проверку постов по чеклисту из урока 20, а свой: таблица контент-плана из папки постов; проверка всех ссылок на UTM-метки; поиск запрещённых обещаний по всем текстам; раскладка и переименование постов по датам и площадкам. Условие: результат можно проверить по постам и выгрузке.
  2. Напишите ТЗ по шаблону урока 19: что есть, что сделать, ограничения, критерии готовности. В ограничениях — «данные только из файлов репозитория», «файлы никуда не отправлять», «файлы в posts/ не менять» (для раскладки — «только перемещать и переименовывать»). И обязательно: «запусти у себя и положи результат в репозиторий».
  3. Отдайте ТЗ агенту в новой сессии — Claude Code, Codex или Copilot cloud agent — и дождитесь pull request.
  4. Проведите ревью по чеклисту урока 22: минимум два замечания с конкретикой — файл, строка, что на самом деле в посте или выгрузке. Дождитесь исправлений.
  5. Слейте PR на GitHub.
  6. Загрузите новый обезличенный пост через Upload files и запустите инструмент повторно — отдельным PR; проверьте и слейте.
  7. Убедитесь, что в README.md есть раздел «Как пользоваться». Нет — ещё одна задача агенту.

Критерии приёмки

Отмечайте только то, что проверили сами. Чеклист и квиз засчитывают контрольную автоматически.

  • Моё ТЗ содержит четыре части — что есть, что сделать, ограничения, критерии готовности — и хотя бы один критерий называет конкретный файл.
  • Агент сам написал программу, запустил её у себя и положил результат в репозиторий: в PR и программа, и файлы результата.
  • В Files changed нет изменений в posts/, checklist.md и campaigns/ (для раскладки — только перемещения и переименования).
  • Три значения результата я сверил(а) с файлами: цитаты найдены в постах дословно, числа сошлись с campaigns.csv на калькуляторе.
  • В PR минимум два моих замечания; после них агент прислал исправления, где они учтены.
  • PR слит на GitHub (Merge pull request → Confirm merge); результат читается в репозитории как текст.
  • Повторный запуск на новом посте сделан отдельным PR, который тоже слит; старые результаты не пересозданы.
  • В README.md есть раздел «Как пользоваться», понятный коллеге: как добавить пост и запустить инструмент.

Проверка понимания

Из каких частей состоит ТЗ на инструмент для маркетинга?

  • Цель, аудитория, дизайн, сроки
  • Что есть, что сделать, ограничения, критерии готовности
  • Список библиотек, код, тесты, лицензия

Агенту нужно знать, с чем он работает, что должно получиться, чего нельзя и как понять, что готово.

Где агент запускает программу, которую написал?

  • На вашем компьютере
  • В своей виртуальной машине в облаке; результат присылает в репозиторий
  • На GitHub в момент слияния PR

Вы ничего не устанавливаете; GitHub при Merge ничего не запускает.

Что считается результатом работы инструмента?

  • Текст ответа агента в чате сессии
  • Ссылка на сессию в коммите
  • Файлы в репозитории — отчёты, таблицы, готовые документы, — присланные через PR

Ответ в чате пропадёт, файлы в репозитории останутся — их можно показать и проверить.

Что такое выборочная проверка результата?

  • Прочитать программу и найти в ней ошибки
  • Сверить три строки результата с текстом поста и пересчитать CTR одной кампании на калькуляторе
  • Спросить агента, всё ли верно

Код вы не читаете, а «всё верно» от агента — не проверка. Убеждает только сверка с постами и выгрузкой.

Какая ситуация — красный флаг: PR сливать нельзя?

  • Агент вынес отчёт за месяц в отдельный файл программы
  • Агент пишет, что опубликует пост в соцсети и подтянет свежую статистику из рекламного кабинета
  • Агент пометил один пункт «неясно» и объяснил почему

К площадкам и кабинетам у агента доступа нет: публикация и выгрузка статистики — ваши. Отдельный файл и честное «неясно» — нормальная работа.

Зачем правило «одна доработка — один PR»?

  • GitHub не позволяет менять больше одного файла за PR
  • Агент не умеет делать две вещи в одной сессии
  • Чтобы каждое изменение можно было проверить, принять или откатить отдельно

PR — единица приёмки и отката: смешав две доработки, вы не сможете принять одну и отклонить другую.

Если не получается

Агент не смог разобрать выгрузку или посты

Попросите его определить формат самому (разделитель, кодировка, строка «Итого»); не помогло — пересохраните выгрузку как простой CSV и загрузите через Upload files. Нет нужных колонок — посчитать метрики не из чего, пусть агент так и напишет.

Результат не сходится с файлами

Не сливайте; замечание с конкретикой: файл, строка, что на самом деле в посте или выгрузке. Расходится почти всё — Close pull request, усильте в ТЗ ограничения («данные только из файлов, цитаты дословно, числа не округлять») и запустите новую сессию.

Агент переделал всё подряд

В Changes десятки файлов, включая запрещённые. Не разбирайте по частям: попросите вернуть лишнее к состоянию main; PR безнадёжен — закройте и разделите задачу на две.

Причина непонятна — спросите ИИ в обычном чате:

Запрос к ИИ
Я поставил задачу ИИ-агенту в приватном репозитории marketing на GitHub (обезличенные посты и выгрузка рекламных кампаний).
Агент: [Claude Code / Codex / Copilot cloud agent].
Моё ТЗ: [текст целиком].
Что сделал агент: [какие файлы появились или изменились, что написано в описании PR].
Что не так: [что вижу и что ожидал; если агент сообщил об ошибке — её точный текст].
Назови 3 самые вероятные причины, для каждой — как проверить за минуту по файлам в репозитории, и предложи текст замечания агенту, которое исправит проблему и не тронет лишнего.

Зачем GitHub менеджеру маркетплейсов

Ответ короткий: GitHub — рабочая папка для ИИ-агента. Без неё агенту негде читать ваши карточки товаров и отзывы и некуда класть результат. Шесть минут — чтобы пять слов из мира программистов перестали мешать.

Рабочая папка для агента

В модуле 3 вы отдавали ИИ файл в чат и получали ответ там же. Для одной карточки товара достаточно. Но перед акцией перепроверить сорок карточек по одному чеклисту и свести цены и остатки в таблицу — значит вставлять карточки по одной и собирать ответы руками. Та же рутина, только с ИИ.

Эту работу делает агент: пишет небольшую программу, запускает её на всех карточках сразу и складывает отчёты в папку. Ему нужно место, где лежат файлы и куда положить результат; в чате такого места нет. Это место — репозиторий на GitHub.

Карточки и отзывы в репозитории→ Задача ИИ→ ИИ пишет и запускает программу→ Pull request с результатом→ Ваша проверка→ Merge

Так будет выглядеть каждая задача до конца курса. Вы положили в репозиторий пять карточек товаров, выгрузку отзывов и чеклист и написали агенту: «проверь каждую карточку по чеклисту, сведи цены и остатки в таблицу». Агент написал программу, запустил её на своей облачной машине, сложил отчёты в папку reports/ и прислал результат на проверку. Вы прочитали отчёты и нажали Merge. Код вы не видели — и не должны.

Где граница. Курс не учит работе с кабинетами Wildberries и Ozon, и агент ничего не меняет на самом маркетплейсе: доступа к вашему кабинету у него нет. Репозиторий — подготовительная кухня. Тексты карточек и ответы на отзывы готовятся и проверяются здесь, а в кабинет маркетплейса вы переносите готовое сами: открыть файл, скопировать, вставить.

Пять слов: что вы увидите, когда ИИ поработал

Эти термины описывают не ваши действия, а то, что появится на экране после работы агента. Забудете — наведите на подчёркнутое слово.

  • Репозиторий (repository) — ваша папка на GitHub: файлы и подпапки, как в проводнике, плюс полная история изменений. Один магазин — один репозиторий.
  • Коммит (commit) — одна сохранённая порция изменений с подписью. После работы агента в истории появятся его записи вроде «Добавить отчёты по пяти карточкам» — с датой и ссылкой на сессию.
  • Ветка (branch) — черновик рядом с основной версией main. Агент пишет в свою ветку, поэтому, пока вы не приняли результат, в main ничего не меняется.
  • Pull request (PR) — страница «посмотрите, что я сделал»: описание работы, список изменённых файлов, разница построчно (зелёное добавлено, красное удалено) и место для замечаний. Ваш главный экран.
  • Merge (слияние) — кнопка «принять»: результат из ветки агента становится основной версией. Единственное в этом списке, что делаете вы. Передумали — у слитого PR есть кнопка Revert.

Коммиты, ветки и pull request создаёт агент; вы их читаете и принимаете.

Чего вы делать не будете

Программисты работают с GitHub через программу Git на компьютере, сами создают ветки и открывают pull request. Здесь всё это делает агент. Границу полезно провести сразу.

Не ваша работа

Ставить Git и писать команды. Создавать ветки и открывать pull request. Писать и читать код. Делать сайты: здесь GitHub хранит карточки и отзывы, а не страницы.

Ваша работа

Положить файлы в репозиторий кнопкой Upload files — это «перетащить файлы в папку». Поставить задачу текстом. Открыть pull request, прочитать результат, оставить замечания. Нажать Merge pull request — или попросить переделать, или закрыть PR.

Один раз, загружая файлы в уроке 13, вы нажмёте кнопку Commit changes. Там она означает просто «сохранить»; все остальные коммиты в вашем репозитории будут подписаны агентом.

Почему именно репозиторий, а не папка в облаке

Карточки и так где-то живут: в Excel на трёх компьютерах, в заметках на телефоне, в переписке. Почему не сложить их в общую папку в облаке и не дать агенту её? Папка умеет только хранить файлы; репозиторий умеет ещё четыре вещи, без которых работа с агентом превращается в лотерею.

Общая папкаРепозиторий

Последняя строка — главная. Если агент ошибся — перепутал цену и цену до скидки, взял остаток не из той карточки, — ошибка остаётся в его ветке: вы видите её в PR и не принимаете. В папке файл был бы уже перезаписан.

Магазин продаёт на двух маркетплейсах. Тексты карточек живут в Excel на трёх компьютерах, ответы на отзывы каждый раз пишутся заново, а на вопрос «какая цена сейчас в карточке?» никто не отвечает уверенно — правили втроём. Руководитель хочет поручить ИИ проверять карточки по чеклисту перед каждой акцией. Что изменится, если перенести карточки и чеклист в репозиторий?

Четыре вещи. Каждая правка карточки станет коммитом с подписью — видно, кто, когда и какие строки поменял, в том числе цену. Любую прошлую версию можно вернуть одной кнопкой, не разыскивая её по почте и чатам. У агента появится рабочее место: он прочитает чеклист и карточки из репозитория и положит отчёты туда же. И появится приёмка: в основной версии ничего не изменится, пока руководитель не посмотрит pull request и не нажмёт Merge.

Что бесплатно, а что нет

Бесплатный личный аккаунт GitHub — не пробная версия: приватные репозитории без ограничений по количеству, история, pull request и слияние. Платный GitHub вам не нужен.

Платным будет только ИИ-агент. На октябрь 2026 достаточно одной подписки из трёх:

АгентПодпискаГде работает
Claude Code в браузереClaude Pro — $20/мес (на Free недоступен)claude.ai/code; основной инструмент этого пути
CodexChatGPT Plus — $20/мес (на Free и Go недоступен)chatgpt.com/codex
Copilot cloud agentCopilot Pro — $10/мес; бесплатно студентам, преподавателям и мейнтейнерам популярных open source-проектовПрямо на GitHub: задача — issue, результат — pull request

Облачная машина, на которой агент запускает программы, входит в подписку и отдельно не оплачивается. Если подписка уже есть, в этом модуле вы не потратите ничего.

Безопасность — два правила. Первое: персональные данные покупателей в репозиторий не кладём — ФИО, телефоны и адреса из заказов, настоящие имена из отзывов, как в уроке 09: агент будет эти файлы читать. Остальное обезличивать не обязательно: свои карточки, цены и остатки можно брать как есть. Второе: репозиторий с карточками делаем Private — его видите только вы и те, кого вы добавили, а агенту доступ даёте отдельно, через приложение. Как именно — в следующих уроках модуля.

Проверьте себя

Зачем ИИ-агенту репозиторий, если карточку товара можно просто вставить в чат?

  • Репозиторий ускоряет ответы агента
  • Без репозитория агент не может выйти в интернет
  • Это его рабочая папка: оттуда он читает карточки и отзывы, туда кладёт программу и результат, там вы видите изменения

Чтобы запустить программу на сорока карточках и сохранить сорок отчётов, нужны файлы и папка с историей и приёмкой — в чате их нет.

Что такое pull request для вас как для приёмщика?

  • Запрос агента на доступ к репозиторию
  • Страница «посмотрите, что я сделал»: список изменённых файлов, разница построчно и место для замечаний — до попадания изменений в основную версию
  • Заявка на платный тариф GitHub

Pull request — ваш главный экран. Пока вы не нажали Merge, в основной версии ничего не меняется.

Что из этого вы будете делать руками в этом пути?

  • Создавать ветку перед каждой задачей агента
  • Загружать карточки и отзывы через Upload files, ставить задачу текстом и нажимать Merge pull request
  • Писать команды git в терминале

Ветки, коммиты и pull request делает агент. Ваша часть — положить файлы, поставить задачу, проверить и принять.

Может ли агент сам изменить цену в вашем кабинете на Wildberries или Ozon?

  • Да, если дать ему ссылку на карточку
  • Нет: агент работает только с файлами репозитория, а готовые тексты и цены в кабинет переносите вы
  • Да, но только на время акции

У агента нет доступа к кабинету маркетплейса. Репозиторий — подготовительная кухня: здесь готовится и проверяется, в кабинет переносится руками.

Практика

Посмотрите на живой репозиторий — документацию самого GitHub. Аккаунт не нужен, репозиторий публичный. Откройте github.com/github/docs и найдите четыре вещи.

  1. Под списком файлов — README, «обложка» проекта.
  2. Над списком файлов — ссылка с числом коммитов и иконкой часов: история с подписями, авторами и датами.
  3. Вкладка Pull requests: откройте любой открытый PR и прочитайте описание.
  4. В нём вкладка Files changed: разница построчно — зелёное добавлено, красное удалено. Так будут выглядеть результаты вашего агента.
  • Я открыл github.com/github/docs и нашёл README под списком файлов.
  • Я открыл историю по ссылке с числом коммитов и увидел, кто и когда вносил изменения.
  • Во вкладке Pull requests я открыл один PR и прочитал его описание.
  • Во вкладке Files changed я увидел зелёные (добавленные) и красные (удалённые) строки.
  • Я могу объяснить коллеге одной фразой, зачем ИИ-агенту репозиторий.

Вы знаете, зачем всё это. Дальше — аккаунт на GitHub, затем репозиторий с вашими карточками и отзывами и его подключение к Claude и ChatGPT.

# Курсы: сайт с каталогом, регистрацией и админкой

PHP 8.2+ и MySQL, без фреймворка и без composer. Репозиторий целиком кладётся в корень сайта, доступ к базе лежит в `.env`, обновление — `./deploy.sh`.

- **Каталог курсов** на главной: поиск, категории, карточки.
- **Доступ к курсу** — один из трёх. *Открытый*: проходят все, без регистрации. *По регистрации*: бесплатно после входа. *Закрытый*: по коду доступа или когда администратор выдал доступ вручную. Любой урок можно сделать бесплатным предпросмотром.
- **Прогресс**. Без входа он хранится в браузере. После входа синхронизируется с аккаунтом. Прогресс, набранный до регистрации, переносится в аккаунт. На общем компьютере после выхода чужой прогресс не остаётся.
- **Админка** по адресу `/admin`: курсы, пути, модули, уроки, пользователи, настройки. В редакторе урока есть кнопки виджетов, живой предпросмотр и сохранение по Ctrl+S.
- **ИИ-помощник** в редакторе пишет черновик урока, квиз, практику с чеклистом или улучшает выделенный фрагмент. Ответ приходит потоком прямо в панель.
- Курс «ИИ для работы: от юриста до программиста» лежит в `content/kurs-ai` и загружается в базу при первом `./deploy.sh --seed`. Он открывается по старому адресу `/kurs-ai/`.

## Установка на VDS

**Что нужно на сервере**: PHP 8.2 или 8.3 с расширениями `pdo_mysql`, `mbstring`, `curl`; MySQL 5.7+ или MariaDB 10.3+; Apache с `mod_rewrite` и разрешённым `.htaccess` (в панелях он обычно стоит за nginx); git.

1. В панели создай базу MySQL и пользователя для неё. Запиши имя базы, пользователя и пароль.
2. Заведи git прямо в корне сайта. Папка может быть не пустой: файлы с такими же именами, как в репозитории, заменятся, остальное останется на месте.
   ```
   cd /var/www/fleyg/data/www/aiblocks.ru
   git init -b main
   git remote add origin https://github.com/fleyg2005-png/kurs-ai.git
   git fetch origin main
   git checkout -f -B main --track origin/main
   ```
   Настоящие папки и файлы в корне сайта сервер отдаёт как есть. Например, старая статичная версия курса в папке `kurs-ai` продолжает открываться по адресу `/kurs-ai/`.
3. Заполни `.env`: доступ к базе, адрес сайта и почту администратора.
   ```
   cp .env.example .env
   nano .env
   ```
4. Запусти первый деплой: он создаст таблицы, администратора, настройки и загрузит курс.
   ```
   ./deploy.sh --seed
   ```
   Если `ADMIN_PASSWORD` в `.env` пустой, скрипт придумает пароль и покажет его один раз.
5. Открой сайт и войди в админку `/admin` под почтой из `ADMIN_EMAIL`.

**Обновление** — одна команда в корне сайта: подтягивает код и применяет новые миграции.
```
./deploy.sh
```

**Если `php` в консоли не тот** — старая версия или без `pdo_mysql`, — скрипт скажет об этом. Укажи нужный PHP явно. Где лежат версии, зависит от панели: `ls /opt/php*/bin/php /usr/bin/php8*`.
```
PHP_BIN=/opt/php83/bin/php ./deploy.sh
```

**Изменения базы** — новый файл в `database/migrations` со следующим номером, например `002_comments.sql`. `{p}` в нём заменяется на префикс таблиц. Применённые миграции записываются в таблицу `kurs_migrations`, каждая выполняется один раз. Посмотреть состояние: `php bin/migrate.php --status`.

**Курсы из `content/`** загружаются в базу только при сидах и только те, которых в базе ещё нет. Дальше курс правится в админке, файлы в `content/` на сайт уже не влияют. Если адрес курса занят папкой в корне сайта, курс загружается по свободному адресу, например `/kurs-ai-new/`. Когда папка станет не нужна, удали её и поменяй адрес курса в админке.

**Если сайт ставился прежним веб-установщиком**: перенеси доступ к базе из `config.php` в `.env` и запусти `./deploy.sh --seed`. Существующие таблицы, курсы и администратор не пересоздаются. Пока `.env` нет, сайт читает старый `config.php`.

Письма для восстановления пароля уходят через почту сервера. Ссылка в письме строится из `APP_URL`, адрес отправителя — `MAIL_FROM` или **Админка → Настройки**.

## Безопасность

- `.env` не попадает в git: он в `.gitignore`. Никогда не добавляй его в репозиторий.
- `.htaccess` закрывает `.env`, `.git`, папки `app`, `bin`, `content`, `database`, `tools`, файлы `*.md`, `*.sql`, `*.sh`. Проверь после установки, что адреса `/.env`, `/.git/config` и `/deploy.sh` отвечают ошибкой 403 или 404.
- Пароли хранятся как хеши. Вход защищён от перебора: после 10 неудачных попыток почта блокируется на 15 минут. Все формы защищены от подделки запросов.
- Ключ API нейросети хранится в базе и не показывается в админке.

## Персональные данные (152-ФЗ)

Сайт хранит имя и почту учеников, поэтому владелец сайта становится оператором персональных данных.

1. Отредактируй политику обработки данных: **Админка → Настройки → Политика**. Сиды положили туда шаблон. Укажи оператора: наименование или ФИО, ИНН и адрес. Текст стоит проверить с юристом.
2. Подай уведомление в Роскомнадзор об обработке персональных данных. Это делается на сайте pd.rkn.gov.ru до начала обработки.
3. Согласие на обработку собирается галочкой при регистрации. Ученик может удалить аккаунт и все свои данные в личном кабинете.
4. Сервер с базой персональных данных граждан РФ должен находиться в России.

## ИИ-помощник

**Админка → Настройки → Нейросеть.**

- **Формат API**: «Anthropic (Claude)» или «OpenAI-совместимый».
- **Модель**: по умолчанию `claude-opus-5-5`.
- **Адрес API**: пусто — официальный адрес. С российского хостинга официальные API обычно недоступны. Укажи адрес прокси или агрегатора с тем же форматом API; окончание `/v1` можно писать и не писать.
- **Ключ API**.

Помощник знает разметку виджетов курса и пишет готовый HTML. Скрипты, стили и обработчики событий из ответа вырезаются. Перед вставкой текст стоит прочитать: нейросеть может ошибаться в фактах.

## Как устроен код

```
index.php            точка входа: все адреса идут сюда через .htaccess
deploy.sh            деплой: git pull, миграции, сиды
.env.example         образец настроек; рабочий .env в git не попадает
bin/migrate.php      миграции базы
bin/seed.php         первичное наполнение: настройки, администратор, курсы
app/                 код сайта (закрыт от браузера)
  bootstrap.php      настройки из .env, сессия, подключение модулей
  router.php         адреса сайта
  pages_public.php   каталог, страницы курса, уроки, API прогресса
  pages_account.php  вход, регистрация, восстановление пароля, кабинет
  admin/admin.php    админка
  ai.php             ИИ-помощник: запрос к API потоком через curl
  courses.php        доступ к курсам, структура для движка, прогресс
  importer.php       загрузка курса из папки content/ и из файла экспорта
  migrate.php        применение миграций
  seed.php           сиды
database/migrations/ миграции базы по порядку номеров
content/kurs-ai/     исходники курса: course.json, home.html, lessons/*.html
assets/              стили, шрифты, движок курса app.js, скрипты админки
tools/dev-router.php роутер для локального запуска
```

Движок курса `assets/app.js` получает структуру курса от сервера и отвечает за навигацию, выбор пути, прогресс и виджеты. Виджеты описываются разметкой: `.quiz`, `ul.checklist`, `.stepper`, `.reveal`, `.tabs`, `.prompt`, `.mock`, `.compare`, `.flow`, `.task-box`, врезки `.note .tip .warn .win .key`. Кнопки редактора вставляют готовые заготовки.

**Перенос курса** между сайтами: **Курс → Экспорт** скачивает один JSON-файл, **Курсы → Импорт** загружает его как черновик.

## Локальный запуск

```
cp .env.example .env        # доступ к локальной базе MySQL или MariaDB
php bin/migrate.php
php bin/seed.php
php -S localhost:8790 tools/dev-router.php
```

Открой `http://localhost:8790/`.

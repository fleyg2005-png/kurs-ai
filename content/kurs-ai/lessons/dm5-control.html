Контрольная 5: две задачи и один откат

Без подсказок — полный цикл работы с агентом: две задачи по очереди, проверка результата с замечаниями и один откат. Агент сам делает и сам сохраняет; ваша часть — задачи, проверка и просьбы. Всё это было в уроках 15–18.

Задание

  1. Откройте новую сессию на claude.ai/code: окружение full, репозиторий contracts, ветка main, режим Auto.
  2. Поставьте первую задачу (текст ниже; расчётную дату замените на свою) и дождитесь отчёта агента.
  3. Проверьте результат по чеклисту урока 17: отчёт, список файлов, факты против договоров. Отправьте минимум одно замечание сообщением в сессию — ошибка или доработка — и дождитесь, пока агент поправит и сохранит.
  4. Только после этого — вторая задача, лучше в новой сессии: проверка, минимум одно замечание, правка.
  5. Один из результатов откатите просьбой: «Отмени всё, что ты сделал в задаче про глоссарий» или «Верни репозиторий к состоянию до задачи с таблицей сроков». Убедитесь на github.com, что файлы вернулись.
Задача 1 — таблица сроков
Прочитай все договоры в contracts/ и создай файл deadlines.md с таблицей всех сроков: договор (имя файла) — что за срок — дата или формулировка дословно из текста — сколько дней до неё от расчётной даты (дата не названа — «не указано»). Данные только из текста договоров. Файлы в contracts/ и README не менять. В отчёте напиши, как проверить таблицу за 5 минут.
Расчётная дата: 1 ноября 2026.
Сохрани результат сам, как в правилах.
Задача 2 — глоссарий
Прочитай все договоры в contracts/ и добавь в конец README.md раздел «Глоссарий»: термины из договоров (пеня, претензионный порядок, форс-мажор…) — определение в одно предложение и имя файла, где термин встречается; если договор определяет термин сам — цитируй его. Остальные разделы README, файлы в contracts/ и другие файлы не менять. В отчёте перечисли термины и файлы.
Сохрани результат сам, как в правилах.

Критерии приёмки

Отмечайте только то, что проверили. Чеклист и квиз ниже засчитывают контрольную автоматически.

  • В обоих ТЗ есть «файлы в contracts/ не менять» и «данные только из текста договоров».
  • Агент сам сохранил результаты обеих задач: в каждом отчёте — «сохранил в main» и список файлов: deadlines.md в первой задаче, README.md во второй, ничего из contracts/.
  • deadlines.md и глоссарий в README видны на github.com — для этого я ничего не нажимал(а) на GitHub.
  • По каждой задаче — минимум одно моё замечание сообщением в сессию; агент поправил и сохранил сам, правка видна в репозитории.
  • Три значения из таблицы сроков сверены с договорами; где даты в договоре нет — «не указано».
  • Откат сделан просьбой: агент вернул прошлую версию и сохранил её; deadlines.md исчез из репозитория (или глоссарий пропал из README).
  • За всю контрольную я не нажимал(а) на GitHub ничего, кроме просмотра файлов.

Проверка понимания

Агент написал: «Сохранил в main: deadlines.md». Где сейчас таблица?

  • В черновике агента, пока вы не подтвердите её на GitHub
  • В репозитории: её видно на github.com, нажимать ничего не нужно
  • Только в чате сессии

«Сохранил в main» — результат уже в основной версии. Ваша часть — открыть и проверить.

Как узнать, какие файлы тронул агент?

  • Прочитать изменения построчно на GitHub
  • Из отчёта агента в конце ответа; файлы не названы — попросить перечислить
  • Спросить в поддержке GitHub

По правилу 8 агент в конце каждого ответа пишет, что сделано, какие файлы и где результат. Сомневаетесь — попросите проверить по истории.

В таблице сроков ошибка в одной строке. Как отправить замечание?

  • Комментарием к строке на GitHub
  • Исправить строку самому карандашом на GitHub
  • Сообщением в ту же сессию: файл, строка, что не так, как должно быть, и «остальное не трогай»

Агент поправит и снова сохранит сам. Правка руками сломала бы правило пути.

Результат задачи оказался плохим. Как вернуть файлы?

  • Загрузить старые версии файлов через Upload files
  • Попросить агента: «отмени всё, что ты сделал в этой задаче» — он найдёт прошлую версию в истории и сохранит сам
  • Удалить репозиторий и создать заново

Все прошлые версии лежат в истории репозитория. Достать нужную — работа агента.

Две сессии правили README одновременно, и вторая пишет про конфликт. Что делать?

  • Разобрать строки вручную на GitHub
  • Попросить Claude объединить обе правки и сохранить; впредь — одна задача за раз
  • Запустить обе задачи ещё раз одновременно

«Одна задача — один агент» снимает конфликты. Если уже случилось — объединение тоже работа агента.

Какая ситуация — красный флаг: результат принимать нельзя?

  • Агент назвал столбец «Срок» вместо «Срок действия»
  • Агент перечислил в отчёте прочитанные файлы
  • Агент пишет, что не смог открыть .docx, и заполнил таблицу по названиям файлов

Данные без источника — выдумка. Первое — повод для замечания, но не опасность; второе — нормальный отчёт.

Если не получается

Агент не видит репозиторий или не сохраняет

Нужен Pro, Max или Team и Claude GitHub App на приватный репозиторий. Проверьте окружение full и режим Auto, а в CLAUDE.md — блок «Как сохранять работу» (урок 14). Агент пишет, что слить не получилось, — попросите объяснить простыми словами, что мешает.

Две сессии правили одно и то же

Вторая задача поставлена до того, как первая сохранена и проверена. Попросите Claude объединить обе правки и сохранить, а следующие задачи ставьте по одной.

Откат вернул не то

Попросите: «Покажи, какие версии deadlines.md (или README.md) есть в истории, с датами и описанием, и верни ту, что была до задачи». Затем снова проверьте на github.com.

Сайт в интернете: GitHub Pages

Страница о вас уже лежит в hello-ai. Одна настройка руками — и она открывается по адресу https://ваш-username.github.io/hello-ai/ у любого человека в мире. Дальше любые правки страницы — запросом агенту, сайт обновляется сам. Откройте репозиторий в соседней вкладке.

Что мы делаем

GitHub Pages — встроенный в GitHub хостинг. Вы один раз указываете, из какой ветки брать файлы, и GitHub показывает их как сайт. Ветка — main, та самая основная версия, куда агент сохраняет работу. Главный файл сайта — index.html в корне репозитория. Его агент создал в уроке 14.

На странице репозитория hello-ai нажмите вкладку Settings (справа в верхнем ряду вкладок). В левом меню найдите раздел Code and automation и в нём пункт Pages.

В блоке Build and deployment найдите поле Source (источник). Выберите Deploy from a branch — «публиковать из ветки». Под ним появится выбор ветки.

В поле Branch выберите main, рядом оставьте папку /(root): корень репозитория, где лежит index.html. Нажмите Save.

Это вся ручная работа с сайтом. Больше в настройках ничего менять не придётся.

Публикация занимает от 1 до 10 минут. Через пару минут обновите страницу Settings → Pages: вверху появится адрес сайта. Или наберите адрес сами: https://ваш-username.github.io/hello-ai/.

Готово. Сохранил в main: index.html — в первый список добавлен четвёртый пункт, остальное не трогал. Сайт обновится через минуту-две: https://username.github.io/hello-ai/

Подождите минуту-две после отчёта и обновите сайт с очисткой кеша: Ctrl+Shift+R. Пункт появился. Так теперь работает любое изменение: запрос, агент сохраняет в main, сайт обновляется сам.

Почему это работает

Ваш сайт статический: это просто файлы, которые браузер показывает как есть. Ему не нужны база данных, программа на сервере и администратор. Поэтому GitHub раздаёт такие сайты бесплатно: он просто отдаёт содержимое main по адресу username.github.io/имя-репозитория.

Запрос агенту→ Агент сохраняет в main→ GitHub Pages берёт файлы из main→ username.github.io/hello-ai/

Два вывода. Первый: что в main, то и на сайте, с задержкой в минуту-две. Если агент открыл pull request, но не слил его, сайт не изменится: напишите ему «слей сам, как в правилах». Второй: на таком сайте работает всё, что умеет браузер, включая калькуляторы и формы на JavaScript. Такие инструменты агент будет делать для вас в следующих модулях. Правило 2 в CLAUDE.md («простые файлы без сборки, в корне») нужно именно для того, чтобы Pages показывал их сразу.

Своя картинка на сайте

По желанию. Картинку с вашего компьютера, например логотип или иллюстрацию, агент сам взять не может. Загрузите её в репозиторий: на главной странице hello-ai нажмите Add file → Upload files, перетащите файл и нажмите Commit changes. Здесь это просто «сохранить». Имя файла — латиницей, без пробелов, например logo.png. Потом попросите агента: «Вставь картинку logo.png в начало страницы, шириной не больше 200 пикселей. Сохрани результат сам, как в правилах».

Картинку тоже видят все. Не загружайте фото документов, экранов с данными клиентов и чужие фотографии.

Pages публикует каждое сохранение в main. Настройки трогать не нужно: подождите и обновите страницу с очисткой кеша.

Агент написал: «Открыл pull request, слить не удалось». Что будет с сайтом?

  • Сайт обновится как обычно
  • Сайт перестанет открываться
  • Ничего: правка не в main, сайт остался прежним

Сайт показывает только main. Попросите агента объяснить, что мешает, и довести дело до конца самому.

Практика

  • В Settings → Pages: Source — Deploy from a branch, Branch — main, папка /(root); на странице показан адрес сайта.
  • Сайт открывается по адресу https://мой-username.github.io/hello-ai/ в режиме инкогнито.
  • Четвёртый пункт добавлен запросом, а не руками, и появился на сайте через минуту-две после отчёта агента.
  • Сайт открывается с телефона.
  • Я отправил(а) адрес коллеге или другу, и у него страница открылась.

Первая задача: от входа до обновлённого сайта

Перейдите на claude.ai/code и войдите в аккаунт Claude. Нужен Pro, Max или Team: на Free вместо рабочего экрана будет сообщение вроде Claude Code isn't available on your account. Нет платного тарифа — прочитайте урок для понимания логики, а делать будете по уроку 21.

Нажмите Sign in with GitHub. GitHub откроет страницу авторизации: разрешить ли Claude доступ к аккаунту. Нажмите Authorize, и вас вернёт на claude.ai/code.

Окружение создаётся один раз, дальше все задачи идут в нём. На экране новой сессии, под полем ввода, первая кнопка — выбор окружения, по умолчанию там Default. Откройте её и внизу меню выберите New environment. В окне New environment:

  • Name — full;
  • Network access — Full, любой адрес в интернете. У Default стоит Trusted: только магазины пакетов и GitHub, поэтому агент иногда не может скачать нужное;
  • Network secrets, Setup script, Environment variables не трогайте, курсу они не нужны. Environment variables — это строки вида KEY=value на случай, если инструменту понадобится ключ. Ключи и пароли в чат не вставляйте никогда.

Рядом с полем ввода есть выбор режима, Mode:

  • Auto — Claude сам решает, что можно делать без вопросов;
  • Accept edits — сам принимает правки файлов, остальное спрашивает;
  • Plan — сначала план, потом изменения.

Выберите Auto: так агент доводит задачу до конца — сам создаёт ветку и открывает pull request. А в main он не сливает: это запрещают правила из следующего шага, merge вы сделаете сами на GitHub.

Это первый запрос в hello-ai, поэтому сверху к ТЗ из урока 19 добавлены правила для агента. Агент сохранит их в два файла с одинаковым текстом: CLAUDE.md читает Claude Code, AGENTS.md — Codex, облачный агент Copilot читает оба. Главное правило — ветку и pull request агент создаёт сам, а проверяете и сливаете вы.

Первый запрос к агенту — правила и первая задача
Сначала создай в корне репозитория два файла с одинаковым текстом — CLAUDE.md и AGENTS.md. Это единственное исключение из ограничений задачи ниже.

# Правила для ИИ-агента в этом репозитории
1. Это публичный сайт: никаких персональных данных, паролей и ключей ни в коде, ни в текстах.
2. Каждую задачу делай в новой ветке и сам открывай pull request с понятным описанием: что сделано и как проверить.
3. В main не сливай: pull request проверяю и сливаю я.
4. В конце ответа дай ссылку на pull request и коротко напиши, какие файлы изменены.

Потом выполни задачу. Файлы правил и калькулятор — в одной ветке и одном pull request.

Задача: добавь на главную страницу сайта (файл index.html) раздел «Калькулятор пени».

Цель: посетитель вводит сумму долга, ставку и срок просрочки и сразу видит сумму пени и формулу расчёта.

Где: index.html, новый раздел в конце страницы, перед закрывающим </body>. Стили и скрипт — внутри этого же файла.

Поведение:
— три поля ввода: «Сумма долга, ₽», «Ставка, % в день», «Дней просрочки»;
— кнопка «Рассчитать»;
— под кнопкой появляется результат: сумма пени с двумя знаками после запятой и формула словами: сумма × ставка / 100 × дни;
— если поле пустое или число отрицательное, показывай надпись «Проверьте введённые значения» и ничего не считай.
Пример: 100 000 ₽, 0,1 % в день, 30 дней → 3 000,00 ₽.

Критерии готовности:
— пример выше даёт 3 000,00 ₽;
— при пустом или отрицательном поле виден текст ошибки, а результата нет;
— раздел нормально выглядит на телефоне.

Не трогай: остальные разделы страницы, README.md и другие файлы.

Ограничения: без внешних библиотек и загрузки скриптов с других сайтов; весь текст интерфейса на русском; все изменения — только в index.html.

Ветки и pull request создавай сам, как в этих правилах: новая ветка, pull request с описанием, ссылка на него в конце ответа. В main не сливай — проверю и солью я.

Когда закончишь, напиши коротко: что изменил и как мне проверить результат на сайте.

Правила пишутся один раз. В следующих запросах к этому репозиторию достаточно последней строкой добавить: «Сделай ветку и pull request сам, как в правилах».

Можно следить и подсказывать, а можно закрыть вкладку и вернуться позже — сессия продолжается в облаке.

Что тратится

Сессии Claude Code расходуют лимиты тарифа — те же, что и чат: скользящие 5-часовые окна плюс недельный лимит. Виртуальная машина отдельно не оплачивается. Одна задача агента — десятки обращений к модели, поэтому расходует она заметно больше, чем вопрос в чате; точные числа меняются, курс их не называет.

Несколько задач параллельно

Каждая задача — отдельная сессия, ветка и pull request, их агент создаёт сам; можно запустить две-три одновременно: калькулятор в одной, раздел «Контакты» в другой. Одно правило: две сессии не должны менять одно место в одном файле, иначе при слиянии второго PR получите конфликт (урок 18). Безопаснее — разные разделы и слияние по одной.

С телефона

Задачу можно поставить из приложения Claude: вкладка Code. Отправьте ТЗ в дороге — агент сам откроет pull request, а проверите и сольёте вы его за компьютером.

Типовые проблемы

В списке нет моего репозитория

Чаще всего на него не установлено Claude GitHub App. Установите по адресу github.com/apps/claude/installations/new, выберите аккаунт и репозиторий, вернитесь и обновите список.

«Claude Code isn't available on your account»

Вы на тарифе Free. Агент доступен на Pro ($20/мес), Max и Team; бесплатная альтернатива — Codespaces + Copilot Free из урока 21.

Claude задаёт вопрос и ждёт

Ответьте в чате — он продолжит. Его вопрос — ровно то, чего не хватало в ТЗ; в следующий раз пишите сразу.

В отчёте нет ссылки на pull request

Напишите в ту же сессию: «Сделай ветку и pull request сам, как в правилах, и пришли ссылку». Если в репозитории ещё нет CLAUDE.md и AGENTS.md, начните с первого запроса из шага 7.

Агент пишет, что не может скачать нужное

Скорее всего, сессия идёт в окружении Default с доступом Trusted. Проверьте кнопку окружения под полем ввода: должно быть full с Network access Full (шаг 4).

Проверьте себя

Какой режим выбрать, чтобы агент сам довёл задачу до pull request?

  • Auto
  • Accept edits
  • Plan

В Auto Claude сам решает, что можно делать без вопросов, и доводит задачу до конца. Accept edits сам принимает только правки файлов, остальное спрашивает; Plan сначала показывает план и ждёт одобрения.

Зачем создавать окружение full вместо Default?

  • Без него агент не видит репозиторий
  • У full сетевой доступ Full — любой адрес в интернете; у Default — Trusted, только магазины пакетов и GitHub
  • В full можно вставить пароль от GitHub, чтобы агент работал быстрее

С доступом Trusted агент иногда не может скачать нужное. Пароль от GitHub агенту не нужен — доступ дал вход через GitHub. Ключи и пароли в чат не вставляйте никогда.

Вы закрыли вкладку браузера, пока Claude работал над задачей. Что произошло?

  • Сессия остановилась, правки потеряны
  • Сессия остановилась, но ветка уже запушена
  • Ничего: сессия продолжается в облаке, можно вернуться позже

Агент работает в облачной машине, а не в вашей вкладке; её закрытие сессию не останавливает.

Кто создаёт ветку и pull request для задачи агента и кто его сливает?

  • Ветку и pull request создаёте вы на GitHub, агент только правит файлы
  • Ветку и pull request агент создаёт сам — так написано в первом запросе и в CLAUDE.md и AGENTS.md; проверяете и сливаете вы
  • Агент сразу сливает изменения в main и публикует сайт

Правило 2 велит агенту самому открывать pull request, правило 3 — не сливать в main. Вы открываете ссылку из отчёта, проверяете и нажимаете Merge pull request. Замечания после этого попадают в тот же pull request.

Приватного репозитория нет в селекторе. Самая вероятная причина?

  • Не установлено Claude GitHub App для этого репозитория
  • Репозиторий слишком большой
  • Нужно сначала создать ветку вручную

Публичные репозитории доступны сразу после Sign in with GitHub, приватные — только через Claude GitHub App.

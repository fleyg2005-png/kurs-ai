Проект: инструмент для своей профессии

К концу урока у вас будет собственный инструмент в интернете: вы отдаёте ТЗ, агент пишет страницу и сам сохраняет её, GitHub Pages показывает её по ссылке, а вы проверяете на сайте. Руками — три настройки нового репозитория, всё остальное — сообщения в чате.

Отдельный репозиторий, а не папка в hello-ai

Инструмент можно положить страницей в hello-ai, но для первого настоящего проекта лучше новый публичный репозиторий my-tool. Причины простые:

Своя ссылка

Коллегам уходит короткий адрес username.github.io/my-tool/, который открывается сразу на инструменте, а не на вашей визитке.

Своя история

Просьба «верни как было» касается только инструмента: личный сайт она не заденет, а правки сайта не сломают калькулятор.

Свой README

Главная страница репозитория — инструкция именно к инструменту: что делает, как пользоваться, контрольные примеры.

Цена — три настройки руками, один раз и минут на десять: создать репозиторий, включить Pages, открыть к нему доступ агенту. Вариант «страница в hello-ai» тоже рабочий, им вы воспользуетесь в контрольной 6.

Сценарий проекта

Десять шагов, около часа с учётом ожидания агента. Выполняйте в соседней вкладке, по одному шагу.

На GitHub нажмите ＋ справа вверху → New repository. Имя — my-tool, видимость Public, галочка Add a README file, кнопка Create repository. Public обязателен: на бесплатном тарифе Pages работает только с публичными репозиториями. README нужен, чтобы репозиторий не был пустым.

ТЗ: калькулятор неустойки
Сделай одностраничный веб-инструмент «Калькулятор договорной неустойки (пени)».

Цель: юрист быстро считает сумму пени по договору за период просрочки и получает готовый текст для претензии.

Технические требования:
- Один файл index.html: разметка, стили и скрипт внутри него. Без внешних библиотек, шрифтов и скриптов с других сайтов.
- Статическая страница для GitHub Pages: без сервера, данные никуда не отправляются.
- Интерфейс на русском языке. Корректно выглядит на телефоне (ширина экрана от 360 px): поля в одну колонку, кнопки на всю ширину.

Поля ввода:
1. Сумма долга, руб. — число больше нуля, копейки через запятую или точку.
2. Ставка неустойки — число больше нуля — и переключатель единицы: «% в день» или «% годовых».
3. Первый день просрочки и последний день периода — два поля типа date.
4. Дней в году (только для ставки «% годовых») — выбор 365 или 366, по умолчанию 365.
5. Пункт договора о неустойке — текст, например «п. 7.2»; подставляется в текст претензии.

Расчёт:
- Дней просрочки = (последний день − первый день) + 1, то есть обе даты включительно.
- Ставка в день: пени = сумма × ставка / 100 × дни.
- Ставка годовых: пени = сумма × ставка / 100 × дни / дней в году.
- Округление до копеек только в итоговой сумме.

Вывод (появляется под формой после нажатия кнопки «Рассчитать»):
- Количество дней просрочки.
- Итоговая сумма пени с разделителями тысяч и знаком рубля, например «3 000,00 ₽».
- Формула с подставленными числами, например «100 000,00 × 0,1 % × 30 дн. = 3 000,00 ₽».
- Текст для претензии из 3–4 предложений: период просрочки, сумма долга, ставка со ссылкой на пункт договора, итоговая сумма пени.
- Кнопка «Скопировать результат»: копирует формулу и текст претензии в буфер обмена и показывает подтверждение «Скопировано».

Валидация:
- Пустое поле, не число, ноль или отрицательное значение в сумме или ставке — расчёт не выполнять, показать понятное сообщение рядом с полем.
- Последний день раньше первого — сообщение «Дата окончания не может быть раньше даты начала».
- Пока есть ошибки, блок результата не показывать.

Критерии готовности:
- 100 000 руб., 0,1 % в день, с 1 по 30 марта 2026 → 30 дней, 3 000,00 ₽.
- 250 000 руб., 0,5 % в день, с 10 по 21 июня 2026 → 12 дней, 15 000,00 ₽.
- 100 000 руб., 20 % годовых, 365 дней в году, с 1 января по 14 марта 2026 → 73 дня, 4 000,00 ₽.
- На экране телефона форма не выезжает за край, кнопки нажимаются пальцем.
- В корне репозитория лежат index.html и README.md; README коротко описывает, что делает инструмент, как им пользоваться, и приводит три контрольных примера выше.

Кроме index.html и README.md, ничего не создавай и не меняй. В отчёте перечисли, что сделано, и отдельно — что из ТЗ не выполнено, если такое есть. Сохрани результат сам, как в правилах.
ТЗ: калькулятор НДС
Сделай одностраничный веб-инструмент «Калькулятор НДС: начислить и выделить».

Цель: бухгалтер за десять секунд начисляет НДС на сумму или выделяет его из суммы и копирует готовую строку в счёт или платёжку.

Технические требования:
- Один файл index.html: разметка, стили и скрипт внутри него. Без внешних библиотек, шрифтов и скриптов с других сайтов.
- Статическая страница для GitHub Pages: без сервера, данные никуда не отправляются.
- Интерфейс на русском языке. Корректно выглядит на телефоне (ширина экрана от 360 px): поля в одну колонку, кнопки на всю ширину.

Поля ввода:
1. Сумма, руб. — число больше нуля, копейки через запятую или точку.
2. Ставка НДС, % — число от 0 до 100, по умолчанию пусто: ставку вводит пользователь.
3. Направление — переключатель «Начислить НДС сверху» или «Выделить НДС из суммы», по умолчанию «Выделить».

Расчёт:
- Начислить: НДС = сумма × ставка / 100; сумма с НДС = сумма + НДС.
- Выделить: НДС = сумма × ставка / (100 + ставка); сумма без НДС = сумма − НДС.
- НДС округляется до копеек; вторая сумма считается от округлённого НДС, чтобы всё сходилось до копейки.

Вывод (под формой после нажатия кнопки «Рассчитать»):
- Сумма без НДС, НДС и сумма с НДС — с разделителями тысяч и знаком рубля, например «122 000,00 ₽».
- Строка для документа: «Сумма 122 000,00 ₽, в т. ч. НДС 22 % — 22 000,00 ₽».
- Кнопка «Скопировать строку» с подтверждением «Скопировано».

Валидация:
- Пустая сумма, не число, ноль или отрицательное значение — сообщение «Укажите сумму больше нуля» рядом с полем.
- Пустая ставка или ставка вне диапазона 0–100 — сообщение «Укажите ставку от 0 до 100».
- Пока есть ошибки, результат не показывать.

Критерии готовности:
- 100 000 руб., 22 %, начислить → НДС 22 000,00 ₽, сумма с НДС 122 000,00 ₽.
- 122 000 руб., 22 %, выделить → сумма без НДС 100 000,00 ₽, НДС 22 000,00 ₽.
- 1 000 руб., 10 %, выделить → НДС 90,91 ₽, сумма без НДС 909,09 ₽.
- Граничный случай: 5 000 руб., 0 %, начислить → НДС 0,00 ₽, сумма с НДС 5 000,00 ₽.
- Работает на телефоне; в корне лежат index.html и README.md с описанием и контрольными примерами.

Кроме index.html и README.md, ничего не создавай и не меняй. В отчёте перечисли, что сделано, и отдельно — что из ТЗ не выполнено, если такое есть. Сохрани результат сам, как в правилах.
ТЗ: генератор оффера
Сделай одностраничный веб-инструмент «Генератор оффера».

Цель: HR за две минуты собирает текст предложения о работе по данным вакансии и копирует его в письмо кандидату.

Технические требования:
- Один файл index.html: разметка, стили и скрипт внутри него. Без внешних библиотек, шрифтов и скриптов с других сайтов.
- Статическая страница для GitHub Pages: без сервера, данные никуда не отправляются и не сохраняются между открытиями страницы.
- Интерфейс на русском языке. Корректно выглядит на телефоне (ширина экрана от 360 px): поля в одну колонку, кнопки на всю ширину.

Поля ввода:
1. Имя кандидата — текст, обязательное.
2. Должность — текст, обязательное.
3. Оклад, руб. в месяц — число больше нуля.
4. Дата выхода — поле типа date.
5. Руководитель — текст, обязательное, например «Мария, руководитель юридического отдела».
6. Испытательный срок — выбор: без испытательного срока, 1, 2 или 3 месяца; по умолчанию 3 месяца.

Вывод (под формой после нажатия кнопки «Собрать оффер»):
- Письмо из 5–7 предложений: обращение по имени, должность, оклад «до вычета НДФЛ», дата выхода, руководитель, испытательный срок, просьба подтвердить ответным письмом.
- Оклад с разделителями тысяч: «120 000 ₽». Дата словами и с днём недели: «1 декабря 2026 года (вторник)».
- Кнопка «Скопировать текст» с подтверждением «Скопировано».

Валидация:
- Пустое обязательное поле — сообщение рядом с полем.
- Оклад не число, ноль или меньше — «Укажите оклад больше нуля».
- Дата выхода на субботу или воскресенье — предупреждение «Дата выхода выпадает на выходной»; текст при этом собирается.
- Пока есть ошибки, текст не показывать.

Критерии готовности:
- Анна, «Юрист», 120000, 01.12.2026, «Мария, руководитель юридического отдела», 3 месяца → в тексте есть «Анна», «Юрист», «120 000 ₽», «1 декабря 2026 года (вторник)», «испытательный срок — 3 месяца».
- То же, но без испытательного срока → слов «испытательный срок» в тексте нет.
- Дата выхода 05.12.2026 → предупреждение о выходном, текст собран.
- Пустая должность → сообщение, текста нет.
- Работает на телефоне; в корне лежат index.html и README.md с описанием и контрольными примерами.

Кроме index.html и README.md, ничего не создавай и не меняй. В отчёте перечисли, что сделано, и отдельно — что из ТЗ не выполнено, если такое есть. Сохрани результат сам, как в правилах.
ТЗ: генератор UTM-ссылок
Сделай одностраничный веб-инструмент «Генератор UTM-ссылок с историей».

Цель: маркетолог за минуту собирает ссылку с UTM-метками для рассылки или поста, не ошибаясь в написании параметров, и видит, какие ссылки уже делал.

Технические требования:
- Один файл index.html: разметка, стили и скрипт внутри него. Без внешних библиотек, шрифтов и скриптов с других сайтов.
- Статическая страница для GitHub Pages: без сервера, данные никуда не отправляются. История хранится в localStorage.
- Интерфейс на русском языке. Корректно выглядит на телефоне (ширина экрана от 360 px): поля в одну колонку, кнопки на всю ширину.

Поля ввода:
1. Адрес страницы — текст, обязательное, должен начинаться с http:// или https://.
2. utm_source — выбор из списка: telegram, vk, email, yandex, google, «другое» (с текстовым полем).
3. utm_medium — выбор из списка: social, email, cpc, banner, «другое» (с текстовым полем).
4. utm_campaign — текст, обязательное.
5. utm_content и utm_term — текст, необязательные.

Поведение:
- Ссылка собирается на лету при любом изменении полей.
- В значениях пробелы заменяются на подчёркивание, буквы приводятся к нижнему регистру, кириллица и спецсимволы кодируются как в адресной строке браузера.
- Если в адресе уже есть параметры после «?», новые добавляются через «&», а не через второй «?».
- Пустые необязательные параметры в ссылку не попадают.
- Кнопка «Скопировать ссылку» копирует результат и добавляет запись в историю: дата и время, кампания, ссылка. Хранить последние 50 записей, новые сверху; у каждой — «Скопировать» и «Удалить»; под таблицей «Очистить историю» с подтверждением.

Валидация: адрес пустой или без http(s):// — «Укажите адрес страницы, начиная с https://»; пустая кампания — «Укажите название кампании». Пока есть ошибки, кнопка копирования неактивна.

Критерии готовности:
- https://example.com/promo, telegram, social, кампания spring_sale → https://example.com/promo?utm_source=telegram&utm_medium=social&utm_campaign=spring_sale
- https://example.com/page?lang=ru, email, email, кампания digest_05 → https://example.com/page?lang=ru&utm_source=email&utm_medium=email&utm_campaign=digest_05
- Граничный случай: адрес «example.com» без https:// — сообщение об ошибке, ссылка не собирается.
- Работает на телефоне; в корне лежат index.html и README.md с описанием и контрольными примерами.

Один посчитайте сами — на бумаге или в калькуляторе телефона: 100 000 × 0,1 % × 30 дней = 3 000 ₽. Затем пустая форма и отрицательное число: должно появиться понятное сообщение, а не «NaN». Отчёт агента «проверил» — не проверка, проверка — ваши примеры на сайте. Подробно о проверке — в уроке 22.

Видите старую страницу или 404 — подождите ещё пару минут и обновите. Через 10 минут ничего не изменилось — спросите агента в той же сессии: «Сайт по адресу … не показывает инструмент. Проверь, что index.html лежит в корне main».

Нашли расхождение — не пишите «что-то не так». В ту же сессию отправьте конкретику: что ввели, что ожидали, что получили. И всегда добавляйте «ничего другого не меняй» — иначе агент заодно «улучшит» то, что работало.

Замечания агенту
Замечания по инструменту на сайте:
1. Пример «100 000 руб., 20 % годовых, с 1 января по 14 марта 2026» даёт 3 945,21 ₽ вместо 4 000,00 ₽ — похоже, не учтён последний день. Дней должно быть 73, обе даты включительно.
2. При пустой сумме в результате появляется «NaN ₽». Нужно сообщение «Укажите сумму долга» и никакого результата.
3. Кнопка «Скопировать результат» копирует только формулу, без текста претензии.
Исправь только эти три пункта, ничего другого не меняй. Перечисли, что именно изменилось. Сохрани результат сам, как в правилах.

После ответа агента обновите сайт и повторите все три примера, а не только исправленный: так видно, что правка ничего не сломала.

Откройте ссылку с телефона: форма помещается по ширине, в числовых полях цифровая клавиатура, в полях дат — календарь, кнопка копирования работает. Разъезжается — одно замечание: «на ширине 360 px поля в одну колонку, кнопки на всю ширину, остальное не трогай». Всё в порядке — отправьте ссылку коллеге и попросите одну фразу: чего не хватает.

Ответьте в чате — он продолжит. Его вопрос — ровно то, чего не хватило в ТЗ; в следующий раз впишите это сразу.

Появились лишние файлы

В отчёте кроме index.html и README.md есть package.json или папки. Замечание: «Убери лишние файлы: инструмент — один index.html без библиотек. Ничего другого не меняй».

Codex или Copilot вместо Claude Code. ТЗ подойдёт без изменений. Но эти агенты оставляют результат pull request'ом и сами его не сливают — слить попросите Claude Code в его сессии: «Слей открытый pull request от Codex в main и удали его ветку».

Проверьте себя

Зачем инструменту отдельный репозиторий my-tool, а не страница в hello-ai?

  • В hello-ai нельзя добавить вторую страницу
  • Своя короткая ссылка для коллег, свой README и своя история: «верни как было» не заденет личный сайт
  • Агент работает только в новых репозиториях

Страница в hello-ai тоже работает — ею вы воспользуетесь в контрольной 6. Отдельный репозиторий удобнее, когда инструментом будут пользоваться другие.

Что из этого вы делаете руками, а не просите агента?

  • Создаёте CLAUDE.md и AGENTS.md
  • Сохраняете index.html в main
  • Включаете GitHub Pages в Settings → Pages

Pages — одна настройка репозитория, её делаете вы. Файлы правил и все сохранения — работа агента по вашему запросу.

Агент написал: «Проверил все три примера, всё сходится». Инструмент принят?

  • Да: агент запускал примеры сам
  • Нет: сначала вы вводите примеры на сайте, один считаете сами, и проверяете пустую форму
  • Да, если в отчёте нет слов «не выполнено»

Отчёт агента — его слова. Принимаете вы — по результату на сайте.

Как правильно отправить замечание?

  • «Калькулятор считает неправильно, переделай»
  • «Ввёл 100 000, 20 % годовых, 1 января — 14 марта: ожидал 4 000,00 ₽, получил 3 945,21 ₽. Ничего другого не меняй»
  • Открыть index.html на GitHub и исправить формулу самому

Ввод, ожидание, результат и граница «ничего другого» — по такому замечанию агент находит ошибку с первого раза.

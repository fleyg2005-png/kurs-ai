Контрольная 5: два PR от ИИ и один откат

Без подсказок — полный цикл приёмки: две задачи агенту по очереди, два ревью с замечаниями, два слитых PR и один откат. Всё это было в уроках 15–18.

Задание

  1. Выберите агента: Claude Code, Codex или облачный агент Copilot. Репозиторий — ваш приватный marketing.
  2. Поставьте первую задачу (текст ниже; расчётную дату замените на свою) и дождитесь pull request.
  3. Проведите ревью по чеклисту урока 17, оставьте минимум одно замечание — ошибка или доработка — и добейтесь исправления в том же PR. Слейте.
  4. Только после этого — вторая задача: ревью, минимум одно замечание, исправление, слияние.
  5. Один из PR откатите: Revert у слитого PR → обратный PR → слить. Убедитесь, что файлы вернулись.
Задача 1 — контент-план
Прочитай все посты в posts/ и создай файл content-plan.md с таблицей контент-плана: дата — файл — площадка — цель — есть ли ссылка с UTM-меткой — статус от расчётной даты («опубликован», если дата раньше расчётной, иначе «запланирован»; даты нет — «не указано»). Строки отсортируй по дате, посты без даты — в конец. Данные только из файлов репозитория. Файлы в posts/ и README не менять. Открой pull request; в описании — как проверить таблицу за 5 минут.
Расчётная дата: 20 ноября 2026.
Задача 2 — запрещённые формулировки
Прочитай checklist.md и все посты в posts/. Добавь в конец README.md раздел «Запрещённые формулировки»: список запрещённых обещаний из checklist.md (каждую формулировку цитируй дословно — «гарантируем результат», «лучший на рынке»…) и для каждой — в каких постах она встречается: имя файла и предложение-цитата; если нигде — «не встречается». Данные только из файлов репозитория. Остальные разделы README, файлы в posts/ и другие файлы не менять. Открой pull request; в описании — формулировки и файлы.

Критерии приёмки

Отмечайте только то, что проверили. Чеклист и квиз ниже засчитывают контрольную автоматически.

  • В обоих ТЗ есть «файлы в posts/ не менять» и «данные только из файлов репозитория».
  • По каждой задаче — отдельный PR; в Files changed только content-plan.md в первом и README.md во втором, ничего из posts/.
  • В каждом PR минимум одно моё замечание — к строке или в Conversation — и коммит агента, где оно учтено.
  • Три строки контент-плана сверены с шапками постов; где даты в шапке нет — «не указано».
  • Оба PR слиты: Merge pull request → Confirm merge → Delete branch; content-plan.md и раздел «Запрещённые формулировки» видны в репозитории.
  • Один PR откачен: Revert у слитого PR, обратный PR слит; content-plan.md исчез (или раздел пропал из README).
  • В истории коммитов — коммиты агента, два слияния и запись, начинающаяся с Revert.

Проверка понимания

Что такое pull request от агента?

  • Изменение, уже применённое к файлам репозитория
  • Отчёт агента о работе без изменений в файлах
  • Предложение изменений в отдельной ветке; в main ничего не меняется до Merge

PR — контрольная точка. Файлы в main меняются только после слияния.

Где увидеть, какие файлы тронул агент, и как оставить замечание к строке?

  • Во вкладке Files changed; навести на строку и нажать «+»
  • Во вкладке Conversation; замечание — ответом на описание PR
  • В истории коммитов; замечание — новым issue

Files changed — список файлов и diff; «+» у строки — комментарий к ней.

Вы нажали Merge pull request. Что дальше?

  • Ничего: изменения уже в main
  • Confirm merge, затем Delete branch — файлы в main изменились
  • Revert, чтобы подтвердить слияние

Слияние требует подтверждения. Ветка после него не нужна.

Слитый PR оказался плохим. Как вернуть файлы?

  • Загрузить старые версии постов через Upload files
  • Нажать Revert у слитого PR и слить обратный PR
  • Попросить агента «сделай как было»

Revert — точная отмена каждой строки. Ручная загрузка и память агента — новые ошибки.

Два агента правили README одновременно; второй PR показывает конфликт. Что делать?

  • Нажать Resolve conflicts и разобрать строки вручную
  • Слить оба PR одновременно
  • Закрыть второй PR и повторить его задачу после слияния первого

«Одна задача за раз» снимает конфликты. Ручной разбор — не ваша работа.

Какая ситуация — красный флаг: PR сливать нельзя?

  • Агент пишет, что постов не читал, и заполнил контент-план по названиям файлов
  • Агент назвал столбец «Дата» вместо «Дата публикации»
  • Агент добавил в описание PR список прочитанных файлов

Данные без источника — выдумка. Другие два варианта — повод для замечания, но не опасность.

Если не получается

Агент не видит репозиторий или не делает PR

Claude Code: нужен Pro, Max или Team и Claude GitHub App для приватного репозитория. Codex: GitHub не подключён или окружение не опубликовано. Copilot: нет Copilot Pro. См. уроки 14–16.

Второй PR показывает конфликт

Вторая задача поставлена до слияния первой. Закройте второй PR, слейте первый и поставьте вторую задачу заново.

Не нахожу кнопку Revert

Она есть только у слитого PR, внизу вкладки Conversation; слитые PR лежат среди закрытых. Запасной путь: история коммитов → коммит слияния → «…» → Revert.

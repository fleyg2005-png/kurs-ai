Контрольная 5: две задачи и один откат

Без подсказок — полный цикл приёмки: две задачи агенту по очереди, две проверки с замечаниями и один откат просьбой. Всё это было в уроках 15–18. На GitHub вы только открываете файлы.

Задание

  1. Агент — Claude Code. Новая сессия: репозиторий marketing, ветка main, окружение full, режим Auto. Работали в Codex или Copilot — их результат слейте просьбой к Claude Code, как в уроке 16.
  2. Поставьте первую задачу (текст ниже; расчётную дату замените на свою) и дождитесь отчёта агента.
  3. Проверьте результат по чеклисту урока 17, напишите в ту же сессию минимум одно замечание — ошибка или доработка — и дождитесь, когда агент исправит и сохранит.
  4. Только после этого — вторая задача, в новой сессии: проверка, минимум одно замечание, исправление.
  5. Одну из задач откатите просьбой: в её сессии — «Отмени всё, что ты сделал в этой задаче: верни изменённые файлы как было до неё. Сохрани результат сам, как в правилах». Убедитесь на github.com, что файлы вернулись.
Задача 1 — контент-план
Прочитай все посты в posts/ и создай файл content-plan.md с таблицей контент-плана: дата — файл — площадка — цель — есть ли ссылка с UTM-меткой — статус от расчётной даты («опубликован», если дата раньше расчётной, иначе «запланирован»; даты нет — «не указано»). Строки отсортируй по дате, посты без даты — в конец. Данные только из файлов репозитория. Файлы в posts/ и README не менять. В отчёте напиши, как проверить таблицу за 5 минут.
Расчётная дата: 20 ноября 2026.
Сохрани результат сам, как в правилах.

Прочитай checklist.md и все посты в posts/. Добавь в конец README.md раздел «Запрещённые формулировки»: список запрещённых обещаний из checklist.md (каждую формулировку цитируй дословно — «гарантируем результат», «лучший на рынке»…) и для каждой — в каких постах она встречается: имя файла и предложение-цитата; если нигде — «не встречается». Данные только из файлов репозитория. Остальные разделы README, файлы в posts/ и другие файлы не менять. В отчёте перечисли формулировки и файлы.
Сохрани результат сам, как в правилах.

Критерии приёмки

Отмечайте только то, что проверили. Чеклист и квиз ниже засчитывают контрольную автоматически.

  • В обоих ТЗ есть «файлы в posts/ не менять», «данные только из файлов репозитория» и последняя строка «Сохрани результат сам, как в правилах».
  • Каждая задача — в своей сессии; в отчёте агента изменённым назван только content-plan.md в первой и README.md во второй, ничего из posts/.
  • На github.com у папки posts прежняя подпись и время последнего изменения — посты не тронуты.
  • В каждой задаче минимум одно моё замечание в сессии и ответ агента, что он исправил и сохранил.
  • Три строки контент-плана сверены с шапками постов; где даты в шапке нет — «не указано».
  • Одна задача откачена просьбой: content-plan.md исчез из репозитория (или раздел пропал из README), а агент написал, что вернул и сохранил.
  • На GitHub я ничего не нажимал(а), только открывал(а) файлы: ветки, сохранение, слияние и откат сделал агент.

Проверка понимания

Агент написал в отчёте: «Создал ветку, открыл pull request и слил его в main». Что вам нужно сделать?

  • Зайти на GitHub и подтвердить слияние
  • Ничего с этими словами: открыть результат и сверить его с постами
  • Удалить ветку агента вручную

Это слова из отчёта: агент описывает, как сохранил работу. Ваша часть — проверка результата.

Как убедиться, что агент не тронул посты, не читая построчные сравнения?

  • В отчёте агента изменёнными названы только разрешённые файлы, а на github.com у папки posts прежняя подпись и время изменения
  • Посчитать, сколько записей появилось в истории
  • Спросить агента «ты точно не трогал посты?» и поверить

Отчёт агента плюс подпись у папки на github.com — две независимые проверки, и обе без кода.

Вы нашли ошибку в контент-плане. Куда писать замечание?

  • Исправить файл карандашом на GitHub
  • Сообщением в ту же сессию: файл, строка, что не так и как должно быть, — агент исправит и сохранит сам
  • В новую сессию с другим агентом

В той же сессии у агента весь контекст задачи. Правка руками ломает правило пути.

Результат задачи оказался плохим. Как вернуть файлы?

  • Загрузить старые версии через Upload files
  • Попросить агента «отмени всё, что ты сделал в этой задаче» — он найдёт прошлую версию в истории и сохранит сам
  • Удалить репозиторий и создать заново

Возврат из истории точен: файлы становятся ровно такими, какими были. Ручная загрузка — новые ошибки.

Две сессии правили README одновременно; вторая пишет, что не может сохранить. Что делать?

  • Разобрать строки вручную на GitHub
  • Закрыть обе сессии и удалить README
  • Попросить вторую сессию объединить её правку с тем, что уже в main; дальше — одна задача за раз

«Одна задача за раз» снимает такие ситуации. Если случилось — объединяет агент.

Какая ситуация — красный флаг: результат принимать нельзя?

  • Агент пишет, что постов не читал, и заполнил контент-план по названиям файлов
  • Агент назвал столбец «Дата» вместо «Дата публикации»
  • Агент перечислил в отчёте прочитанные файлы

Данные без источника — выдумка. Другие два варианта — повод для замечания, но не опасность.

Если не получается

Агент не видит репозиторий или не сохраняет сам

Claude Code: нужен Pro, Max или Team и Claude GitHub App на приватный репозиторий. Проверьте, что в CLAUDE.md есть раздел «Как сохранять работу», а в сессии выбраны окружение full и режим Auto. См. урок 14.

Агент пишет, что слить не получается

Он объяснит причину простыми словами — так записано в правилах. Не поняли объяснение — «объясни ещё проще и скажи, что мне у тебя попросить». Причина — параллельная задача: попросите объединить.

Не уверен(а), что откат сработал

Откройте файл на github.com и обновите страницу. Спросите агента: «Покажи простыми словами, какие версии этого файла есть в истории и какая сейчас в main. Ничего не меняй».

Какие инструменты для документов может сделать ИИ

До сих пор агент делал разовую работу: прочитал договоры — переписал README. Инструмент — следующий шаг: программа, которая лежит в репозитории и запускается снова на новых документах. Что реально сделать с договорами и реестрами, где граница и как написать ТЗ.

Чем инструмент отличается от ответа в чате

Спросить в чате «какие сроки в этом договоре» — быстро и годится для одного документа. Но через месяц приходят ещё двенадцать договоров, и всё повторяется; ответ живёт в переписке, коллеги его не видят, а проверить, не пропущен ли пункт, нечем.

Инструмент устроен иначе: правила записаны один раз в программе, программа лежит рядом с документами и запускается снова на новых файлах, а результат — отчёты и таблицы, которые открываются прямо на GitHub и проверяются по одному чеклисту.

Что агент может построить

В облачной машине агента есть Python, и агент сам ставит библиотеки для чтения .docx и .pdf. Всё, что сводится к «прочитать документы из папки по правилам и записать результат в файлы», — его работа:

  • Проверка договора по чеклисту: отчёт по каждому договору — пункт, найдено или нет, цитата.
  • Сводная таблица сроков, сумм и штрафов из папки договоров.
  • Сравнение версий договора: что изменилось между редакцией контрагента и вашей.
  • Генерация претензии, уведомления или оффера из шаблона по данным договора.
  • Переименование и раскладка файлов по папкам по содержанию.
  • Реестр документов: таблица всего, что лежит в папке, — тип, стороны, даты.
  • Напоминания о сроках в виде таблицы: что — когда — сколько дней осталось.

Юрист

Проверка каждого нового договора по чеклисту с отчётом и цитатами. Сравнение двух редакций договора: таблица отличий по пунктам.

Бухгалтер

Таблица сумм, ставок НДС и сроков оплаты из папки договоров и актов. Реестр первичных документов по содержимому файлов.

HR

Проверка шаблонов трудовых договоров и локальных актов на обязательные разделы. Генерация должностной инструкции или уведомления из шаблона по данным позиции.

Менеджер

Реестр договоров с контрагентами и датами окончания. Раскладка файлов проекта по папкам и переименование по единому образцу.

Обезличивание — по-прежнему обязательно. Инструмент видит только то, что лежит в репозитории, а туда кладутся документы без ФИО, реквизитов и коммерческой тайны (урок 09). Для HR особенно: шаблоны — да, личные дела — нет.

Где это работает — и где граница

Схема та же, что в модуле 5, только вместо README агент приносит программу и результат:

ТЗ→ Агент пишет программу→ Запускает на документах→ Сам сохраняет программу и отчёты→ Вы сверяете отчёты с договорами→ Новые документы — «запусти снова»

Программа выполняется в машине агента, не на вашем компьютере, и только по вашей просьбе: «добавил два договора, запусти проверку снова» — и агент сам сохраняет в репозиторий новые отчёты. Документы никуда не уходят, кроме машины агента и репозитория.

Граница: по расписанию — «каждый понедельник собирать таблицу сроков» — программа сама не запустится. Для этого нужна дополнительная настройка (на GitHub — GitHub Actions), следующий уровень за рамками курса. Нужен результат — попросите агента.

Бухгалтеру к совещанию через час нужно свести суммы и сроки оплаты по четырём договорам. Юристу каждый месяц приходят 15–20 договоров, по каждому нужен отчёт по чеклисту, который читают ещё два коллеги. Где инструмент, а где хватит чата?

Бухгалтеру — чат: четыре документа, один раз, результат нужен сейчас и только ему. Юристу — инструмент: повторяется каждый месяц, документов много, результат читают коллеги. Три признака инструмента: повторяется, документов больше десятка, результат нужен не только вам.

Структура ТЗ для инструмента

Четыре части: первые две определяют, что агент построит; третья защищает документы; четвёртая даёт способ проверить результат за пять минут.

  1. Что есть — папки и файлы: где документы, в каких форматах, где правила (чеклист, шаблон).
  2. Что сделать — написать программу и назвать файл; запустить на всех документах; положить результат в названные файлы; добавить в README раздел «Как пользоваться».
  3. Ограничения — данные только из текста; документы и правила не менять; никуда не отправлять; библиотеки агент выбирает сам.
  4. Критерии готовности — проверяемый пример по конкретному документу, ответ на который вы знаете заранее: «в отчёте по contracts/dogovor-postavki.md пункт „Ответственность и штрафы“ помечен „найдено“ с цитатой про пени».
Шаблон ТЗ для инструмента
Сделай инструмент «НАЗВАНИЕ».

Что есть: папка с документами и их форматы (.docx, .md, .pdf), файлы с правилами (чеклист, шаблон) и что в них.

Что сделать:
1. Напиши программу на Python (назовите файл, например check_contracts.py), которая для каждого документа из папки … — опишите результат одного прогона: какой файл появляется, что в нём и в каком виде (таблица с такими столбцами).
2. Собери сводный файл по всем документам: имя файла и столбцы таблицы.
3. Запусти программу у себя на всех документах и положи готовые результаты в репозиторий вместе с программой.
4. В README добавь раздел «Как пользоваться»: как добавить новый документ и как попросить тебя запустить инструмент снова.

Ограничения: данные брать только из текста документов, ничего не додумывать — если в документе чего-то нет, писать «не найдено». Документы никуда не отправлять, кроме твоей рабочей машины. Библиотеки для чтения файлов выбери сам. Файлы в папке с документами и файлы с правилами не менять.

Критерии готовности: для каждого документа есть результат; в сводной таблице столько строк, сколько документов; один проверяемый пример по конкретному документу — в таком-то файле должно быть написано то-то (вы знаете это заранее). Сохрани результат сам, как в правилах.

Заполненный пример — ТЗ проекта «Проверка договоров по чеклисту» — в следующем уроке; по нему вы получите первый инструмент.

Так не надо

«Сделай программу, которая проверяет договоры и находит все риски. Используй нейросеть, чтобы было умно».

Нет файлов и вида результата, «риск» не определён — агент решит сам, что считать риском, и проверить его будет нечем.

Так надо

«Что есть: contracts/ (четыре договора .docx и .md), checklist.md (11 пунктов). Что сделать: программа check_contracts.py; для каждого договора — отчёт в reports/ с таблицей пункт — найдено/не найдено — цитата; запусти на всех. Ограничения: данные только из текста; договоры не менять; никуда не отправлять. Критерий: в отчёте по dogovor-postavki.md пункт „Ответственность и штрафы“ — „найдено“ с цитатой про пени».

Проверьте себя

Чем инструмент отличается от ответа ИИ в чате?

  • Инструмент использует более мощную модель
  • Программа лежит в репозитории, запускается снова на новых документах, а результат — файлы, которые видят коллеги
  • Инструмент работает без документов в репозитории

Модель может быть той же. Разница — в повторяемости и в результате-файле вместо текста в переписке.

Где выполняется программа, которую написал агент?

  • На вашем компьютере, после установки Python
  • На серверах GitHub при каждом открытии репозитория
  • В облачной машине агента, по вашей просьбе; результат агент сам сохраняет в репозиторий

Вы ничего не устанавливаете. Агент ставит библиотеки и запускает программу у себя; документы не покидают его машину и репозиторий.

Вы хотите, чтобы таблица сроков собиралась сама каждый понедельник. Что верно?

  • Достаточно написать это в ТЗ — агент настроит
  • Без дополнительной настройки программа сама не запустится; пока — просить агента «запусти снова»
  • Это невозможно в принципе

Запуск по расписанию — отдельная настройка, следующий уровень. В курсе запуск всегда по вашей просьбе.

Что обязательно должно быть в критериях готовности ТЗ?

  • Название библиотеки для чтения .docx
  • Срок выполнения в минутах
  • Проверяемый пример по конкретному документу, ответ на который вы знаете заранее

По примеру агент проверит себя, а вы — его. Библиотеки выбирает агент, а время работы ни о чём не говорит.

Практика

Выберите инструмент для своей работы — из списка выше или свой — и заполните по нему шаблон ТЗ в заметках или в чате с ИИ. Оно понадобится в контрольной 6.

  • В ТЗ четыре части: что есть, что сделать, ограничения, критерии готовности.
  • Названы папки, форматы файлов и файлы с правилами; названы файлы, которые появятся в репозитории.
  • В ограничениях есть все три: данные только из текста, документы не менять, никуда не отправлять.
  • Критерий готовности — проверяемый пример по конкретному документу с ответом, который я знаю заранее.
  • ТЗ сохранено там, где я найду его в контрольной 6.

Вы знаете, что заказывать и как. В следующем уроке агент построит первый инструмент — проверку договоров по чеклисту, — а вы примете его как заказчик.

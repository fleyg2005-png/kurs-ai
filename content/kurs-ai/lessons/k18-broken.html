Когда ИИ сделал не то

Пять типовых ситуаций — и все решаются одним сообщением агенту, без кнопок на GitHub. Главная мысль урока: ничего не теряется. Каждое сохранение — версия в истории репозитория, и прошлую версию агент вернёт по просьбе.

Почему можно не бояться

Агент сохраняет результат сам, сразу в main. Звучит рискованно, но каждое сохранение записывается в историю с подписью и датой, а прежняя версия файлов остаётся там же. Вернуть её — тоже работа агента: так записано в его правилах, пункт 9.

Агент сохранил неудачное→ Вы: «верни как было»→ Агент нашёл прошлую версию и сохранил её

Ни неудачная версия, ни возврат из истории не исчезают — история для того и нужна. Вам в неё заглядывать не обязательно: достаточно открыть файл на github.com и увидеть, что он снова прежний.

Сценарий 1. Агент сделал не то, что просили

Просили таблицу постов — получили пересказ каждого поста на абзац

Дальше два пути — по объёму переделки.

  • Поправимо — не так несколько строк: замечание с конкретикой в той же сессии: файл, что ожидали, что получили. Агент исправит и снова сохранит.
  • Переделывать всё — агент понял задачу иначе: «Переделай: …» с уточнённым ТЗ в той же сессии. Или сначала «отмени всё, что ты сделал в этой задаче», а потом новая сессия с новым ТЗ. Обычно не хватало примера результата («таблица с такими столбцами») и границ («остальное не трогать»).

Замечание, которое не сработает

«Не то. Переделай нормально».

Замечание, которое сработает

«Переделай: в README нужна таблица, а не абзацы — столбцы файл — площадка — дата — цель — есть ли ссылка с UTM-меткой, по одной строке на пост. Пересказы убери. Данные только из файлов. Сохрани результат сам, как в правилах».

Сценарий 2. В README ерунда — «верни как было»

Агент сохранил README, а таблица развалилась или половина данных выдумана

Откат — одна просьба. Писать можно в ту же сессию или в новую: агент найдёт прошлую версию в истории.

Назовите файл и момент, к которому вернуться. Два готовых варианта:

Запрос к агенту — один файл
Верни README.md как было до последнего изменения. Другие файлы не трогай. Сохрани результат сам, как в правилах.
Запрос к агенту — вся задача
Отмени всё, что ты сделал в этой задаче: верни все изменённые файлы как было до неё. Сохрани результат сам, как в правилах.

Агент напишет, какую версию нашёл и что вернул.

Верни README.md как было до последнего изменения. Другие файлы не трогай. Сохрани результат сам, как в правилах.
Нашёл в истории версию README.md до изменения «Переписать README одним словом» и вернул её: снова таблица постов из пяти строк. Другие файлы не трогал. Сохранил в main: README.md.

Обновите главную страницу репозитория: README снова такой, каким был. В истории остались обе записи — неудачная и возврат. Ничего не потеряно, и на GitHub вы ничего не нажимали.

Возврат — целиком. Плоха одна строка, а остальное хорошо — не откатывайте, а поставьте агенту точечную задачу: «исправь строку про анонс вебинара, остальное не трогай».

Сценарий 3. Агент изменил посты, хотя не просили

В отчёте агента рядом с README — файлы из posts/

Красный флаг из урока 17: посты — первоисточник, агент не меняет их ни «для единообразия», ни «исправляя опечатки». Текст поста согласован с клиентом или руководителем, и «улучшенная» агентом версия уйдёт в публикацию несогласованной. Разбирать, что изменилось в постах, не нужно — верните их целиком:

Запрос к агенту
Верни посты в posts/ и выгрузку в campaigns/ как были до этой задачи и больше их не трогай. README оставь как есть. Сохрани результат сам, как в правилах.

Правило на будущее: в каждом ТЗ, даже самом коротком, есть строка «файлы в posts/ не менять». Что не написано — агент додумает сам.

Сценарий 4. Два агента сразу

Две сессии правили README одновременно, вторая пишет, что не может сохранить

Вы запустили две задачи параллельно — раздел «Правила UTM-разметки» в README и раздел «Расписание публикаций» в README. Обе сессии изменили одни и те же строки. Первая сохранила, а вторая пишет что-то вроде «слить не получается: конфликт». Это слово встретится в отчёте нейросети, делать с ним ничего не нужно: git просто не знает, какой вариант строк правильный.

Лучше так не делать: одна задача за раз. Случилось — попросите Claude объединить:

Запрос к агенту — во второй сессии
Объедини свою правку с тем, что уже лежит в main: в README должны быть оба раздела — «Правила UTM-разметки» и «Расписание публикаций». Ничего из них не потеряй, остальное не трогай. Сохрани результат сам, как в правилах.

Одна задача за раз. Пока агент не написал «Сохранил в main», следующую задачу в этот репозиторий не ставьте. Параллельно — только над разными файлами.

Сценарий 5. Не понимаю, что вижу

Незнакомое слово в отчёте, непонятная ошибка, новое окно

Не угадывайте. Попросите агента объяснить простыми словами — прямо в той же сессии, он знает, что делал. Непонятное на экране скопируйте дословно или сделайте скриншот: Claude читает картинки.

Запрос к агенту
Я маркетолог, не программист, на GitHub ничего не нажимаю. Объясни простыми словами, без терминов:
1. Что ты сейчас сделал и сохранил ли результат в main.
2. Что значит фраза из твоего отчёта: «[скопируйте её дословно]».
3. Потеряно ли что-нибудь и нужно ли мне что-то сделать. Если нужно — напиши, что именно попросить у тебя.

Что бы вы сделали?

Агент неделю назад сохранил в README таблицу из пяти постов. Коллега заметил, что площадка у анонса вебинара указана неверно; остальные четыре строки верны, и команда уже ссылается на таблицу. «Верни как было» или новая задача агенту?

Новая задача. Возврат откатит весь README к прошлой версии — исчезнут и четыре верные строки, которыми уже пользуются. Поставьте точечную задачу: «В README исправь строку про posts/anons-vebinara.md: площадка — дословно из шапки поста. Остальное не трогай. Сохрани результат сам, как в правилах», — и сверьте результат. «Верни как было» — когда плохо всё или вред больше пользы: например, даты и площадки выдуманы по всем постам.

Проверьте себя

Агент сохранил новый README, а вы поняли, что прежний был лучше. Потерян ли прежний?

  • Да: агент перезаписал файл в main
  • Нет: прежняя версия осталась в истории, агент вернёт её по просьбе
  • Только если с тех пор прошло меньше суток

Каждое сохранение — новая версия, старые остаются в истории. Возврат — задача агенту, пункт 9 его правил.

README испорчен. Самый короткий путь назад?

  • Написать агенту: «Верни README.md как было до последнего изменения. Сохрани результат сам, как в правилах»
  • Попросить агента написать README с нуля
  • Удалить репозиторий и загрузить посты заново

Возврат из истории ничего не выдумывает: файл становится ровно таким, каким был. Написать заново — новая работа агента с новыми рисками.

Две сессии правили README одновременно; вторая пишет, что не может сохранить из-за конфликта. Что делать?

  • Открыть GitHub и разобрать строки вручную
  • Удалить README и попросить обе сессии начать заново
  • Попросить во второй сессии объединить её правку с тем, что уже в main, и сохранить; дальше — одна задача за раз

Объединить две правки — работа агента. Ваша — не запускать две задачи над одним файлом сразу.

Вместе с README агент «поправил формулировки» в двух постах в posts/. Что делать?

  • Попросить вернуть посты как были и больше их не трогать, а в следующие ТЗ добавить «файлы в posts/ не менять»
  • Оставить: формулировки стали лучше
  • Удалить посты и загрузить их заново через Upload files

Посты меняет только человек: текст согласован, и в публикацию должна уйти согласованная версия. Агент вернёт их из истории одной просьбой.

Практика

Сломайте и почините — специально, пока это ничего не стоит. Поставьте агенту намеренно плохую задачу «Перепиши README одним словом. Сохрани результат сам, как в правилах» (переспросит — подтвердите) и посмотрите README на github.com. Затем верните его просьбой. Потом попросите «добавь в конец README строку: Учебный репозиторий курса по ИИ» и отмените эту задачу целиком.

  • README «одним словом» сохранён агентом; я увидел(а) его на github.com.
  • По просьбе «верни README.md как было до последнего изменения» агент вернул прежний README и сам сохранил; я проверил(а) на github.com.
  • Строка «Учебный репозиторий курса по ИИ» добавлена, затем по просьбе «отмени всё, что ты сделал в этой задаче» убрана.
  • Я попросил(а) агента объяснить простыми словами одну фразу из его отчёта и понял(а) ответ.
  • В следующих ТЗ будет строка «файлы в posts/ не менять», а задачи пойдут по одной.

Теперь ошибки агента не страшны. Вы знаете, что ничего не теряется, и умеете вернуть как было одной просьбой. Впереди контрольная модуля: две задачи агенту, две проверки и один откат.

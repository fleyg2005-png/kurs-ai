Когда ИИ сделал не то

Пять типовых ситуаций — и все решаются сообщением агенту, без кнопок на GitHub. Главная мысль урока: ничего не теряется. Любую прошлую версию агент вернёт по просьбе «верни как было».

Почему можно не бояться

Каждое сохранение агента записывается в историю репозитория: что изменено, когда и в какой задаче. Старые версии файлов из истории никуда не деваются. Поэтому любую ошибку можно отменить одной фразой: «верни README.md как было до последнего изменения» или «отмени всё, что ты сделал в этой задаче». Агент сам находит прошлую версию и сам её сохраняет — правило 9 в CLAUDE.md.

И неудачная версия, и откат остаются в истории. Она для того и нужна: можно вернуться и к тому, и к другому.

Агент сохранил→ Вы проверили — не то→ «Верни как было»→ Агент вернул и сохранил

Сценарий 1. Агент сделал не то, что просили

Просили таблицу договоров — получили пересказ каждого договора на абзац

Скажите об этом в той же сессии — агент переделает. Дальше два пути, по объёму переделки.

  • Поправимо — не так несколько строк: замечание с конкретикой. Файл, строка, что ожидали, что получили. Агент исправит и сохранит снова.
  • Переделывать всё — агент понял задачу иначе: «Отмени всё, что ты сделал в этой задаче», затем задача заново, с уточнённым ТЗ. Обычно не хватало примера результата («таблица с такими столбцами») и границ («остальное не трогать»).

Замечание, которое не сработает

«Не то. Переделай нормально».

Замечание, которое сработает

«В README нужна таблица, а не абзацы: столбцы файл — стороны — предмет — дата — срок действия, по одной строке на договор. Пересказы убери. Данные только из текста договоров. Сохрани результат сам, как в правилах».

Сценарий 2. Агент сохранил ерунду

Открыли README — таблица развалилась или половина данных выдумана

Откат — одна просьба. Три шага.

Напишите в ту же сессию. Если она закрыта — в новую: агент найдёт нужную версию по истории.

Запрос к агенту — откат
Верни README.md как было до последнего изменения. Другие файлы не трогай. Сохрани результат сам, как в правилах, и напиши, к какой версии вернул.

Вся задача оказалась неудачной, а не один файл: «Отмени всё, что ты сделал в этой задаче».

Агент находит прошлую версию в истории репозитория и сохраняет её как новую. В отчёте он называет файл и то, к какой версии вернул.

Верни README.md как было до последнего изменения. Другие файлы не трогай. Сохрани результат сам, как в правилах…
Готово. Вернул README.md к версии до задачи «Переписать README одним словом» — с таблицей договоров. Сохранил в main. Другие файлы не трогал.

Обновите главную страницу репозитория: README снова такой, каким был до неудачной задачи. В истории остались обе записи — неудачная и откат.

Откат возвращает файл целиком. Плоха одна строка, а остальное хорошо — не откатывайте, а поставьте агенту точечную задачу: «исправь строку про договор аренды, остальное не трогай. Сохрани результат сам, как в правилах».

Сценарий 3. Агент изменил договоры без просьбы

В отчёте рядом с README — файлы из contracts/

Красный флаг из урока 17: документы — первоисточник, агент не меняет их ни «для единообразия», ни «исправляя опечатки». Даже если README хорош, сначала верните договоры:

Запрос к агенту
Верни документы в contracts/ как были и больше их не трогай. README оставь. Сохрани результат сам, как в правилах, и перечисли, какие файлы вернул.

Затем проверьте правило 4. Откройте на github.com файл CLAUDE.md (для Codex и Copilot — AGENTS.md) и найдите строку «Документы в contracts/ не меняй и не удаляй без прямой просьбы». Её нет или она изменена — попросите агента восстановить правила дословно по тексту из первого запроса урока 14.

Правило на будущее: в каждом ТЗ, даже самом коротком, — строка «файлы в contracts/ не менять». Что не написано, агент додумает сам.

Сценарий 4. Два агента правят одно и то же

Две сессии одновременно меняли README

Вы запустили две задачи параллельно: глоссарий в README и раздел о сроках в README. Обе сессии изменили одни и те же строки. Вторая может написать в отчёте, что слить не получилось из-за конфликта, или вовсе перезаписать работу первой. Слово «конфликт» встретится в отчёте, делать с ним самим ничего не нужно.

Лучше всего — не доводить до этого: одна задача — один агент, следующая задача в тот же файл — после того, как первая сохранена и проверена. Если уже случилось, попросите Claude объединить:

Запрос к агенту — объединить
Две сессии изменили README.md по-разному: в одной добавлен глоссарий, в другой — раздел о сроках. Объедини обе правки в один README, ничего из них не потеряв. Если правки противоречат друг другу — не выбирай сам, спроси меня. Сохрани результат сам, как в правилах.

Сценарий 5. Не понимаю, что вижу

Незнакомое слово в отчёте, непонятная надпись, новое окно

Не угадывайте и не ищите кнопку с этим словом на GitHub. Попросите агента объяснить простыми словами — в той же сессии. Если непонятно что-то на экране, скопируйте текст дословно или сделайте скриншот: Claude и ChatGPT читают картинки.

Запрос к агенту или к ИИ в чате
Я юрист, не программист. Git и GitHub в моём репозитории contracts полностью на тебе — я на GitHub ничего не нажимаю.
Ты написал (или я вижу на экране, дословно): «...».
Объясни простыми словами, что произошло, потеряно ли что-нибудь и нужно ли мне что-то делать. Если нужно — по шагам и одной фразой каждый. Если есть риск что-то потерять — предупреди заранее.

Что бы вы сделали?

Агент неделю назад сохранил в README таблицу из пяти договоров. Коллега заметил, что срок действия договора поставки указан неверно; остальные четыре строки верны, и коллеги уже ссылаются на таблицу. «Верни как было» или точечная правка?

Точечная правка. Откат вернёт README к версии до таблицы — исчезнут и четыре верные строки, которыми уже пользуются. Поставьте точечную задачу: «В README исправь строку про contracts/dogovor-postavki.md: срок действия — дословно из п. 10.1 договора. Остальное не трогай. Сохрани результат сам, как в правилах» — и сверьте строку с договором. Откат — когда плохо всё или вред больше пользы: например, даты выдуманы по всем договорам.

Проверьте себя

Агент сохранил README, а там ерунда. Самый короткий путь назад?

  • Удалить репозиторий и загрузить документы заново
  • Попросить агента написать README с нуля
  • Написать агенту: «верни README.md как было до последнего изменения»

Прошлая версия уже есть в истории: агент возвращает её за минуту, ничего не выдумывая. Написать заново — новая работа с новыми рисками.

Вместе с README агент «поправил опечатки» в двух договорах в contracts/. Что делать?

  • Оставить: опечатки в договорах — это полезно
  • Скачать старые версии договоров и загрузить их через Upload files
  • Написать «Верни документы в contracts/ как были и больше их не трогай» и проверить, что в CLAUDE.md есть правило 4

Документы меняет только человек. Агент вернёт их сам, а правило 4 не даст этому повториться.

Две сессии одновременно правили README, и вторая пишет про конфликт. Что делать?

  • Найти на GitHub кнопку разбора конфликта и выбрать строки вручную
  • Попросить Claude объединить обе правки в один README и сохранить; впредь — один агент на задачу
  • Удалить README и начать заново

Разбор конфликта — работа агента. Ваша часть — попросить объединить и решить, если правки противоречат друг другу.

В отчёте агента незнакомое слово, например «rebase». Что делать?

  • Спросить в той же сессии: «объясни простыми словами, что произошло и нужно ли мне что-то делать»
  • Найти на GitHub кнопку с этим словом и нажать её
  • Закрыть сессию и начать задачу заново

Слова из git описывают, как агент сохранял работу. Если что-то нужно от вас, агент так и скажет — по шагам.

Практика

Сломайте и почините — специально, пока это ничего не стоит. Поставьте агенту намеренно плохую задачу «Перепиши README одним словом. Сохрани результат сам, как в правилах» (переспросит — подтвердите). Откройте README на github.com — одно слово. Затем верните как было.

  • Агент сохранил «README одним словом», и я увидел(а) это на github.com.
  • По просьбе «верни README.md как было до последнего изменения» агент вернул прежнюю версию и сохранил её сам.
  • README снова с таблицей договоров — я проверил(а), обновив страницу.
  • Я открыл(а) CLAUDE.md и нашёл(ла) правило 4 про документы в contracts/.
  • В следующих задачах будет строка «файлы в contracts/ не менять», а задачи пойдут по одной.

Теперь ошибки агента не страшны. Вы умеете вернуть как было одной фразой и не дать агенту трогать документы. Впереди контрольная модуля: две задачи агенту, проверка и один откат.

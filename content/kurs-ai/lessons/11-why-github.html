Зачем GitHub не-программисту

GitHub считается сайтом для программистов. Для вас это три вещи: папка с вечной историей версий, рабочее место для ИИ-агентов и бесплатный адрес в интернете. Шесть минут — чтобы следующие три урока шли без вопроса «а зачем это».

Папка с историей, которую нельзя потерять

Вспомните общую папку любого отдела: Договор_поставки_финал.docx, Договор_поставки_финал2.docx, Договор_поставки_ФИНАЛ_правки_Ивановой.docx. Кто и что поменял между версиями — неизвестно. Какая из них последняя — спорно. Вернуться к тому, что было в марте, — невозможно.

GitHub решает ровно эту проблему. Репозиторий — это папка с файлами, у которой есть полная история: каждое сохранение подписано (кто, когда, что и зачем изменил), и к любому состоянию можно вернуться. Ближайшая аналогия — режим «Исправления» в Word, только он работает для любых файлов, а не только для текста, и история не теряется никогда, даже если файл удалили.

Это первая причина завести аккаунт. Есть ещё три, и для курса они важнее.

Место, где работают ИИ-агенты

Claude Code, Codex, Copilot — агенты из модуля 6 — не работают «в воздухе». Им нужен репозиторий: оттуда они читают файлы, туда вносят изменения и там показывают вам, что именно поменяли. Нет репозитория — нет агента.

Бесплатный хостинг сайтов

Любой публичный репозиторий за несколько кликов превращается в сайт по адресу вида username.github.io. Без оплаты, без домена, без хостинг-провайдера. В уроке 14 вы это сделаете.

Ваше портфолио

Профиль на GitHub показывает, что вы реально сделали: инструменты, шаблоны, инструкции. Для юриста или HR с собственным рабочим инструментом в интернете это заметное отличие от строки «уверенный пользователь ПК» в резюме.

Защита от «случайно удалил»

Всё, что хоть раз попало в репозиторий, восстановимо. Удалённый файл, затёртый абзац, неудачная правка — возвращаются за минуту. Как именно — в уроке 18.

Пять слов, которых хватит

Терминов в GitHub много, но для работы с ИИ-агентами нужны пять. Наведите на подчёркнутое слово, если потом забудете.

  • Репозиторий (repository, «репо») — папка проекта с историей. Один проект — один репозиторий: сайт отдела, набор шаблонов договоров, калькулятор отпускных.
  • Коммит (commit) — сохранённая версия с подписью. Как «Сохранить как» с обязательной заметкой «что изменилось». История проекта — цепочка коммитов.
  • Ветка (branch) — черновик рядом с основной версией. Основная ветка называется main, в ней живёт то, что работает. Агент правит в своей ветке, чтобы не сломать основную.
  • Pull request (PR) — предложение «посмотрите мои правки и, если всё хорошо, примите их в main». Как согласование документа: виден каждый изменённый абзац, можно оставить замечания, потом нажать «принять».
  • GitHub Pages — превращает файлы из main в сайт. Поменяли файл в репозитории — через несколько минут поменялся сайт.

Вместе они складываются в сценарий, который будет повторяться до конца курса:

Задача→ Агент→ Ветка→ Pull request→ Ваша проверка→ main→ Сайт

Вы ставите задачу. Агент делает её в отдельной ветке и открывает pull request. Вы смотрите, что изменилось — не код построчно, а результат и описание — и принимаете или просите переделать. Принятое попадает в main и через несколько минут появляется на сайте. Ваша роль здесь — заказчик и приёмщик, а не исполнитель.

Бухгалтерия хранит шаблоны актов и счетов в общей папке. Раз в квартал кто-нибудь затирает рабочий шаблон своей версией, и полдня уходит на восстановление. Что изменится, если положить шаблоны в репозиторий?

Три вещи. Каждое изменение станет коммитом с подписью — видно, кто и когда правил. Любую прошлую версию можно открыть и вернуть за минуту, не разыскивая её по почте. А спорные правки можно делать в ветке и принимать через pull request — после того как главный бухгалтер посмотрел разницу.

Чего мы делать не будем

Программисты работают с GitHub через программу Git на своём компьютере и команды в терминале. Мы — нет, и это принципиально.

  • Не будем ставить Git на компьютер. Всё, что нужно, делается на сайте github.com и в двух его браузерных редакторах — github.dev и Codespaces (модуль 5). На рабочем компьютере, где администратор запретил установку программ, это особенно ценно: устанавливать ничего не придётся.
  • Не будем учить команды наизусть. Три команды терминала вы увидите в уроке 16 — просто чтобы понимать, что происходит на экране. Всё остальное напишет ИИ, если попросить.
  • Не будем писать код руками. Код пишут агенты. Ваша работа — поставить задачу, проверить результат и принять решение.

Что GitHub бесплатно даёт вам

Бесплатный личный аккаунт — не пробная версия. На нём курс проходится целиком, и для большинства рабочих задач его хватает надолго.

Проверьте себя

Чем репозиторий отличается от обычной общей папки на сервере компании?

  • Он быстрее открывается и занимает меньше места
  • У каждого изменения есть автор, дата и подпись, и к любому прошлому состоянию можно вернуться
  • В него нельзя положить документы Word и Excel — только код

Репозиторий хранит любые файлы, а главное — всю их историю. Общая папка хранит только последнее состояние, и то, что затёрли, пропало.

Зачем ИИ-агенту вроде Claude Code нужен ваш репозиторий?

  • Агент читает из него файлы, вносит правки в отдельную ветку и показывает их вам через pull request
  • Без репозитория агент не может отвечать на вопросы в чате
  • Репозиторий нужен только для оплаты подписки на агента

Агенту нужно место, где лежат файлы проекта и куда он положит результат. Обычный чат с ИИ работает и без репозитория, агент — нет.

Что такое pull request?

  • Запрос на скачивание чужого репозитория себе
  • Просьба к GitHub опубликовать сайт
  • Предложение принять изменения из ветки в main — с просмотром разницы и обсуждением

Pull request — это согласование: видно каждое изменение, можно оставить замечания и только потом принять. Именно так вы будете проверять работу агентов.

Что нужно установить на компьютер, чтобы пройти модули 4–6 курса?

  • Git и редактор кода
  • Ничего: всё делается в браузере — на github.com, в github.dev и Codespaces
  • Только Git, редактор не нужен

Это принцип курса. Терминал и редактор тоже будут — но в облаке, во вкладке браузера, а не на вашем компьютере.

Практика

Осмотритесь в чужом репозитории — так вы увидите, как выглядит живой проект, ещё до того, как сделаете свой. Откройте github.com/github/docs — это репозиторий с документацией самого GitHub, его ведут сотни людей. Регистрация не нужна.

  • Нашёл(а) список файлов и папок проекта и файл README.md — его содержимое показано ниже списка файлов.
  • Нашёл(а) над списком файлов ссылку с числом коммитов (рядом иконка часов) и открыл(а) историю: видно, кто, когда и с какой подписью менял проект.
  • Открыл(а) вкладку Issues и прочитал(а) заголовки двух-трёх задач — это «задачник» проекта.
  • Открыл(а) вкладку Pull requests и посмотрел(а) один открытый PR: заголовок, описание, обсуждение.

Теперь понятно, зачем. Репозиторий — папка с историей, агентам нужно где-то работать, сайт достаётся бесплатно. Следующий шаг — завести аккаунт: восемь минут по шагам.

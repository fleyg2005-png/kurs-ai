То же в ChatGPT (Codex) и Copilot

В прошлом уроке Claude Code переписал README репозитория marketing и сам его сохранил. Теперь ту же задачу — слово в слово — получат два других агента: Codex в ChatGPT и облачный агент Copilot на GitHub. Честно о главном отличии и о том, как обойтись без кнопок на GitHub. Выберите вкладку под свою подписку.

Чем они отличаются от Claude Code

Codex и Copilot тоже работают с репозиторием: читают посты, пишут и запускают программы, готовят изменения. Но результат они оставляют pull request'ом — предложением «перенести изменения в main» — и сами его не сливают. Пока pull request не слит, в репозитории ничего не меняется.

Чтобы ничего не делать на GitHub руками:

  • в Codex нажмите его кнопку Create PR — это кнопка в самом Codex, а не на GitHub;
  • слить попросите Claude Code в его сессии: «Слей открытый pull request от Codex в main и удали его ветку»;
  • в Copilot задачу пишут в issue и назначают Copilot — это как написать задачу. Его pull request сливается так же, через Claude Code.

Основной инструмент курса — Claude Code. Codex и Copilot — запасной вариант: пригодятся, если Claude временно недоступен или хочется сравнить два результата. Без Claude Code слить их pull request можно только кнопками на GitHub, а в этом пути их нет. Поэтому подписка Claude нужна в любом случае.

Одна задача — любой агент

Агенты различаются кнопками, а не языком общения. Задача описывает результат — что прочитать, что написать, чего не трогать, что сообщить в отчёте — и ничего не говорит о том, кто её выполняет. Поэтому текст из прошлого урока отдаём без единой правки:

Задача агенту — та же, что в прошлом уроке
Прочитай все файлы в репозитории. Ничего в постах не меняй.
Сделай две вещи:
1. Перепиши README.md: что лежит в репозитории, список постов таблицей (файл — площадка — дата — цель — есть ли ссылка с UTM-меткой; данные бери только из файлов, если чего-то нет — ставь «не указано»).
2. В конце README предложи 3 задачи, которые ты можешь выполнить по этим файлам автоматически, с оценкой: что получится на выходе.
В отчёте напиши, какие файлы ты прочитал и что в них непонятно.
Сохрани результат сам, как в правилах.

Последнюю строку Codex и Copilot выполнят наполовину: правила из AGENTS.md они прочитают, изменения подготовят, но в main не сольют — это сделает Claude Code. README уже переписан Claude, и это помогает: второй агент сделает то же по-своему, и вы впервые сравните два результата — у кого таблица полнее, кто честнее ставит «не указано». Понравился второй вариант — попросите Claude Code его слить; первый лучше — попросите закрыть pull request без слияния.

Два агента — два пути

Нужен ChatGPT Plus ($20/мес), Pro или Business — на Free и Go агента нет. Откройте chatgpt.com/codex в соседней вкладке. Если вы подключали Codex в уроке 14, начните с шага «Start a new task».

Перейдите на chatgpt.com/codex. В приложении ChatGPT тот же раздел: Codex → Work in → Cloud; на телефоне — раздел Codex.

Нажмите Connect GitHub. GitHub предложит установить приложение Codex на ваш аккаунт и спросит, какие репозитории ему открыть: Select repositories → marketing (или All repositories). Тот же принцип, что Claude GitHub App: приватный репозиторий агент видит только через своё приложение.

Select environment → Create environment → выберите marketing. Окружение создаётся один раз — дальше все задачи по этому репозиторию идут в нём.

Get started

Нажмите Get started. Codex сам изучает проект и ставит зависимости; в репозитории с постами программ пока нет, так что этап короткий. Проверьте, что выбран нужный репозиторий, и нажмите Publish. Подтверждение Environment published — окружение готово.

Нажмите Start a new task, вставьте задачу из начала урока и отправьте. Обратите внимание: вы ничего не меняли в тексте.

Задача выполняется в изолированной среде с копией репозитория, обычно от 1 до 30 минут. Codex показывает, какие файлы изменил, и ход работы: видно, как он читает папку posts/. Изменённый файл должен быть один — README.md.

Сам результат попросите показать текстом: напишите в той же задаче «Покажи итоговый текст README.md целиком здесь». Сверьте две строки таблицы с шапками постов, как в уроке 15. Нужна правка — напишите её в той же задаче: «В таблице у анонса вебинара дата не указана, хотя в шапке поста она есть — поправь».

Copilot работает в GitHub Actions — облачных машинах GitHub — и оставляет результат pull request'ом. Сам он его не сливает. Можно уйти и вернуться позже.

Открывать pull request на GitHub не нужно. Новая сессия на claude.ai/code (marketing, main, full, Auto):

Запрос к Claude Code
В репозитории есть открытый pull request от Copilot. Покажи здесь целиком текст README.md из него и перечисли, какие файлы он меняет. Ничего не меняй и не сливай.

Нашли ошибку — допишите: «После слияния исправь в README: дата и цель есть в шапке post-keis.md — 05.11.2026 и „заявки на услугу“. Сохрани результат сам, как в правилах». Версия Claude лучше — «Закрой pull request от Copilot без слияния и удали его ветку».

Проверьте себя

Какой тариф ChatGPT нужен для Codex?

  • Любой, включая Free
  • Plus, Pro или Business
  • Go и выше

На Free и Go Codex недоступен. Минимальный тариф с агентом — Plus за $20/мес.

Как запустить облачного агента Copilot?

  • Написать задачу в комментарии к последнему коммиту
  • Открыть README и нажать кнопку Copilot
  • Создать issue с задачей и назначить его на Copilot в блоке Assignees

Назначение issue на Copilot — и есть запуск. Результат он оставит pull request'ом.

Codex закончил задачу. Как довести результат до main, ничего не нажимая на GitHub?

  • Ничего не делать: Codex сольёт сам
  • Открыть pull request на GitHub и нажать кнопку слияния
  • Нажать Create PR в самом Codex и попросить Claude Code: «Слей открытый pull request от Codex в main и удали его ветку»

Codex сам не сливает, а кнопки на GitHub в этом пути не нажимают. Create PR — кнопка Codex, слияние — просьба к Claude Code.

Что нужно изменить в тексте задачи, переходя от Claude Code к Codex или Copilot?

  • Убрать пункт про отчёт — другие агенты его не пишут
  • Ничего: задача описывает результат и границы, а не исполнителя
  • Переписать на английский

Хорошая задача говорит, что прочитать, что сделать, чего не трогать и что сообщить. Это одинаково для любого агента; отличается только то, как результат попадает в main.

Практика

Пройдите один из двух путей и сравните README второго агента с версией Claude: у кого таблица полнее, чьи три предложенные задачи вы бы поручили.

  • Я выбрал агента под свою подписку и отдал ему задачу слово в слово — ту же, что Claude Code в прошлом уроке.
  • Я посмотрел текст README от второго агента — в задаче Codex или через Claude Code — и сверил таблицу с файлами в posts/.
  • Изменён только README.md; если агент ошибся в таблице, я написал замечание и получил правку.
  • По моей просьбе Claude Code слил pull request второго агента в main или закрыл его без слияния — и я могу назвать одну причину своего решения.
  • На GitHub я не нажимал ни одной кнопки pull request: слияние сделал Claude Code.

Вы знаете, как работать с любым из трёх агентов — и почему основной всё-таки Claude Code. Следующий урок — как проверять результат и писать замечания так, чтобы агент понял с первого раза.

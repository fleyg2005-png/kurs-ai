Подключить GitHub к Claude и ChatGPT

Репозиторий с постами и выгрузкой есть. Теперь даём к нему доступ ИИ: три способа для Claude и один для ChatGPT, каждый — по шагам «нажал → увидел». В конце урока ИИ перечислит файлы вашего репозитория, и вы поймёте, что подключение работает.

Два режима: дать почитать и дать поработать

Подключений несколько, и путаница начинается здесь. Разница простая.

В этом пути главный режим — второй. Первый пригодится для быстрых вопросов, когда программа не нужна.

Тарифы на октябрь 2026. Claude Code в браузере работает на Pro, Max и Team; на Free его нет. Codex в ChatGPT — на Plus, Pro и Business. Кнопка + → Add from GitHub в чате Claude доступна после подключения коннектора GitHub в настройках.

Способ 1. Claude Code в браузере: дать поработать

Откройте claude.ai/code в соседней вкладке и идите по шагам.

Войдите в свой аккаунт Claude. Нужен тариф Pro, Max или Team. Если вместо рабочего экрана сообщение вроде Claude Code isn't available on your account — вы на Free; дочитайте урок и выберите Codex в способе 4.

Нажмите Sign in with GitHub. GitHub откроет страницу: разрешить ли Claude доступ к вашему аккаунту. Нажмите Authorize. Это одноразовый шаг.

Если claude.ai/code предложит это само — соглашайтесь; если вы нажали Skip или окно не появилось — откройте github.com/apps/claude/installations/new.

Выберите свой аккаунт, затем Only select repositories → marketing → Install. Приложение получит доступ только к этому репозиторию; позже сюда можно добавить другие.

На Pro и Max рабочее окружение Default создаётся само. Это настройки облачной машины, в которой будет работать агент: доступ к GitHub и к хранилищам библиотек, больше ничего. Для постов и выгрузок этого достаточно.

Нажмите селектор репозитория под полем ввода и выберите marketing. Ветку оставьте main: агент сам создаст от неё свою ветку для каждой задачи. Если репозитория нет в списке — приложение из шага 3 не установлено на него.

Опишите, что нужно сделать в репозитории…

  1. Селектор репозитория.
  2. Режим разрешений — следующий шаг.

Три режима: Accept edits — агент меняет файлы и пушит ветку, не спрашивая на каждую правку; Plan — сначала план, ждёт одобрения; Auto — действия проверяет автоматический классификатор. Для работы с постами и выгрузками берите Accept edits: всё, что агент сделает, всё равно придёт к вам как pull request, и без вашего Merge в репозитории ничего не изменится.

Вставьте задачу и нажмите Enter. Это проверка подключения: агент только читает.

Способ 2. Кнопка «+» в чате: дать почитать

Для вопросов по постам и выгрузкам без программ. Один раз подключаете коннектор, потом добавляете файлы в любой чат.

В claude.ai откройте настройки: Customize → Connectors, найдите GitHub и нажмите подключить. GitHub попросит войти и разрешить доступ — как в способе 1. Для приватного репозитория нужно то же приложение Claude GitHub App; если вы ставили его в шаге 3 способа 1, ничего делать не нужно.

Начните новый чат. В левом нижнем углу поля ввода нажмите + и выберите Add from GitHub.

Напишите сообщение…
＋1→ Upload a file · Add from GitHub · …

Найдите marketing в поиске или вставьте его адрес. В файловом браузере отметьте только нужное — например, checklist.md и один пост. Весь репозиторий добавлять не надо: всё выбранное попадает в контекст чата, а он не бесконечный.

Запрос к ИИ
Сверь приложенный пост с чеклистом. Таблицей: пункт чеклиста — выполнено / не выполнено / неясно — цитата из поста. Только из текста, ничего не додумывай.

Claude ответит в чате. В репозитории ничего не изменится — это режим «почитать».

Три ограничения режима «почитать». Claude видит только выбранные файлы и только их содержимое — не историю изменений, не pull request. Файлы не обновляются сами: после изменений в репозитории выбирайте их заново. Приватный репозиторий открывается, только если на него установлено приложение Claude; если доступа нет, Claude покажет ссылку на его установку.

Способ 3. Файлы репозитория в проекте Claude

Если вы заводили проект в уроке 10, посты из репозитория можно положить прямо в его знания: в разделе знаний проекта нажмите + → GitHub → найдите репозиторий или вставьте адрес → выберите файлы и папки. Они будут видны во всех чатах проекта. Когда посты в репозитории изменились, нажмите Sync — подтянется свежая версия; состав файлов меняется через Configure files. Это удобнее, чем добавлять файлы в каждый чат, но правило то же: выбирайте только нужное.

Способ 4. ChatGPT: Codex

Тот же режим «поработать», только у OpenAI. Нужен Plus, Pro или Business.

Перейдите на chatgpt.com/codex. В приложении тот же раздел: Codex → Work in → Cloud.

Нажмите Connect GitHub. GitHub предложит установить приложение Codex и спросит, какие репозитории открыть: Select repositories → marketing. Приватный репозиторий открывается именно так — через выбор в приложении.

Select environment → Create environment → репозиторий marketing → Get started. Codex сам осмотрит проект; у папки с постами и выгрузками настраивать нечего. Проверьте и нажмите Publish.

Нажмите Start a new task, вставьте ту же проверочную задачу («Перечисли все файлы репозитория… Ничего не меняй») и отправьте. Задача выполняется в отдельной среде с копией репозитория; ответ появится в задаче.

  • В pull request

«+» — режим «почитать». Менять репозиторий умеет только агент: Claude Code или Codex.

Приватного репозитория marketing нет в селекторе на claude.ai/code. Самая вероятная причина?

  • Приватные репозитории агенту недоступны в принципе
  • Нужно сначала сделать репозиторий публичным
  • На репозиторий не установлено приложение Claude GitHub App

Авторизация даёт доступ к публичным репозиториям; приватные открываются установкой приложения на конкретный репозиторий. Делать репозиторий с рабочими файлами публичным нельзя.

В режиме Accept edits агент изменил файлы. Что уже произошло с вашим репозиторием?

  • Ничего: изменения лежат в отдельной ветке и придут к вам как pull request
  • Файлы в main изменены
  • Старые версии файлов удалены

Accept edits — про то, что агента не спрашивают на каждую правку. В main изменения попадают только после вашего Merge.

Вы изменили checklist.md в репозитории, а Claude в проекте отвечает по старой версии. Что сделать?

  • Пересоздать проект
  • Нажать Sync в знаниях проекта
  • Ничего: файлы в проекте обновляются сами

Файлы из GitHub в проекте — копия на момент добавления. Sync подтягивает свежую версию.

Практика

  • Claude Code (или Codex) видит репозиторий marketing в селекторе; приложение установлено только на него.
  • Проверочная задача выполнена: агент перечислил мои файлы и ничего не создал.
  • В обычном чате через «+» → Add from GitHub добавлены один пост и чеклист, получена таблица сверки.
  • Я могу объяснить коллеге одной фразой разницу между «дать почитать» и «дать поработать».

ИИ видит ваши посты и выгрузки. Дальше — первая настоящая задача: агент перепишет README, сделает коммит и откроет pull request. Вы только проверите и нажмёте Merge.

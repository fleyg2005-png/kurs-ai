Проверка понимания

Вы открыли новую сессию и не присылали правила. Почему агент их знает?

  • Claude помнит все ваши прошлые чаты
  • Он читает CLAUDE.md из репозитория в начале каждой сессии
  • Правила хранятся в настройках окружения full

Контекст живёт в репозитории, а не в чате. Поэтому новая сессия начинается с тех же правил.

Зачем в репозитории два файла с одинаковыми правилами?

  • Один основной, другой — резервная копия
  • GitHub требует два файла для публичных репозиториев
  • CLAUDE.md читает Claude Code, AGENTS.md — Codex; Copilot читает оба

Разные агенты ищут правила в разных файлах. Одинаковый текст значит одинаковое поведение любого из них.

Какой фразой закончить задачу агенту после первого запроса?

  • «Сохрани результат сам, как в правилах.»
  • «Создай pull request, я сам его приму.»
  • «Ничего не сохраняй, я перенесу код сам.»

Подробности уже записаны в правилах 5–8. Короткая строка напоминает о них.

Почему на странице не должно быть телефона и адреса?

  • GitHub удаляет такие страницы
  • Репозиторий публичный: страницу и все файлы видят все
  • Агент не умеет вставлять цифры

Это правило 1 в CLAUDE.md. Агент его соблюдает, но и сами не присылайте ему личные данные.

Какой режим и какое окружение выбираются в каждой новой сессии?

  • Plan и Default
  • Auto и full
  • Accept edits и full

Auto — чтобы агент довёл задачу до сохранения сам. Full — полный доступ в сеть, чтобы ему не мешали ограничения.

Если не получается

Агент не знает правил

Скорее всего, файлов правил нет в main: агент открыл pull request, но не слил его. Напишите в сессии из урока 14: «Слей свой pull request в main сам, как в правилах».

Агент изменил ещё и README

Напишите в той же сессии: «Верни README.md как было до этой задачи и сохрани сам». Подробнее об откатах — в уроке 18.

Нет окружения full в меню

Оно создаётся один раз: кнопка окружения под полем ввода → New environment, шаг 4 урока 14.

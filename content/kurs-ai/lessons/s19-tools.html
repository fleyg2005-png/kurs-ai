Какие инструменты может сделать ИИ

До сих пор агент правил ваш сайт hello-ai. Теперь он сделает инструмент — страницу, которой вы и коллеги будете пользоваться каждый рабочий день. Разберём, чем инструмент лучше ответа в чате, что реально построить как веб-страницу, где граница и как написать ТЗ, чтобы агент сделал с первого раза.

Чем инструмент отличается от ответа в чате

Спросите чат «посчитай пени: 100 000 ₽, 0,1 % в день, 30 дней» — он ответит. Завтра будет другой договор, и всё повторится: найти чат, вставить новые числа, перепроверить, не ошибся ли он в днях. Ответ живёт в переписке, коллеги его не видят, а каждый раз ИИ считает чуть-чуть по-своему.

Инструмент устроен иначе. Правила записаны один раз — в коде страницы. Страница лежит в вашем репозитории, а GitHub Pages показывает её по ссылке. Открыли, ввели числа, получили ответ — без ИИ и без чата. Нейросеть нужна только тогда, когда инструмент надо сделать или доработать.

Три признака, что пора делать инструмент: задача повторяется, правила понятны и записываются на бумаге, результат нужен не только вам.

Что агент может построить

Всё, что умещается в одну страницу в браузере, — работа агента. Он пишет файл index.html, в котором лежат и вид, и логика, и сам сохраняет его в репозиторий. Через несколько минут страница открывается по ссылке.

  • Калькуляторы — любая формула, которую вы можете записать на бумаге: неустойка, сроки, НДС, комиссии, скидки, сумма прописью.
  • Чек-листы с галочками — онбординг, подготовка к проверке, закрытие месяца. Отметки помнятся в браузере, даже если закрыть вкладку.
  • Генераторы документов — форма с полями превращается в готовый текст претензии, оффера, уведомления. Одна кнопка копирует текст в письмо.
  • Обработка таблиц в браузере — выгрузили реестр из Excel в CSV, выбрали файл на странице: поиск, сортировка, подсветка сроков. Файл никуда не загружается, его читает только ваш браузер.
  • Справочники — регламент или FAQ с поиском по словам; текст лежит прямо в странице.

Юрист

Калькулятор неустойки с готовым абзацем для претензии. Калькулятор сроков: дата плюс N рабочих или календарных дней.

Бухгалтер

НДС в обе стороны с округлением до копеек. Сумма прописью для счёта и договора.

HR

Генератор оффера по должности, окладу и дате выхода. Чек-лист первой недели новичка.

Маркетолог

Генератор UTM-ссылок без опечаток в метках и с историей последних ссылок.

Менеджер

Трекер задач с приоритетами и сроками; просроченные подсвечены.

Где граница

Инструмент в этом курсе — статическая страница: без сервера и без базы данных. Всё происходит в браузере того, кто её открыл.

Ваше ТЗ→ Агент пишет страницу→ Сам сохраняет в репозиторий→ GitHub Pages показывает по ссылке→ Вы проверяете на сайте
  • Данные вводит пользователь на странице, и они никуда не уходят. Числа в полях, выбранный CSV-файл, галочки остаются в браузере на этом устройстве. Если инструменту нужно что-то помнить между открытиями, он пишет это в localStorage.
  • Всё, что лежит в самом репозитории, публично. Код страницы, README, примеры видят все, включая поисковики. Поэтому в ТЗ и в коде — только вымышленные числа, никаких реальных окладов, ФИО и реквизитов. Это правило 1 в вашем CLAUDE.md.
  • Чего страница не умеет: работать, когда вкладка закрыта (рассылки, напоминания на почту, запуск по расписанию), показывать одни и те же данные на двух устройствах (вы отметили — коллега увидел), хранить общие данные команды. Для этого нужен сервер — следующий уровень, за рамками курса.

Три идеи. Бухгалтер хочет калькулятор НДС для себя и коллег. Руководитель хочет, чтобы сотрудники вносили расходы на своих телефонах, а он видел общую сводку у себя. HR хочет форму, из которой получается текст оффера. Что из этого можно сделать страницей на GitHub Pages?

Калькулятор НДС и генератор оффера — да: ввёл, получил результат, скопировал — всё в браузере одного человека. Сводка расходов — нет: данные с телефонов сотрудников должны встретиться на компьютере руководителя, а страница без сервера так не умеет. Вопрос-проверка на будущее: нужно ли данным встречаться на двух устройствах и должно ли что-то происходить при закрытой вкладке? Если да хотя бы на одно — это не наш инструмент.

Структура ТЗ для инструмента

Агент сделает ровно то, что написано, а что не написано — додумает, не обязательно так, как вы хотели. Поэтому задача для инструмента — это ТЗ из семи частей. Каждая отвечает на один вопрос:

  1. Цель — кто и какую рабочую задачу решает: «юрист за минуту считает пени и получает абзац для претензии».
  2. Технические требования — один и тот же блок для любого инструмента: один файл, без внешних библиотек, данные никуда не уходят, работает на телефоне. Его копируете как есть.
  3. Поля ввода — каждое отдельной строкой: название, тип (число, текст, дата, выбор из списка), допустимые значения.
  4. Поведение — что происходит по кнопке: формулы, правила округления, что запоминается.
  5. Вывод — как выглядит готовый результат: пример строки, кнопка «Скопировать».
  6. Валидация — что считать ошибкой ввода и какое сообщение показать.
  7. Критерии готовности — три контрольных примера «ввод → точный ответ», которые вы знаете заранее. По ним агент проверит себя, а вы — его.

Последняя строка любого запроса к агенту — «Сохрани результат сам, как в правилах». Остальное агент знает из CLAUDE.md: сам сохранит работу и напишет, что сделано и где смотреть.

Шаблон ТЗ для инструмента
Сделай одностраничный веб-инструмент «НАЗВАНИЕ».

Цель: кто и какую рабочую задачу решает с его помощью — одним предложением.

Технические требования:
- Один файл index.html: разметка, стили и скрипт внутри него. Без внешних библиотек, шрифтов и скриптов с других сайтов.
- Статическая страница для GitHub Pages: без сервера, данные никуда не отправляются. Если нужно что-то помнить между открытиями страницы — localStorage.
- Интерфейс на русском языке. Корректно выглядит на телефоне (ширина экрана от 360 px): поля в одну колонку, кнопки на всю ширину.

Поля ввода: каждое поле отдельной строкой — название, тип, допустимые значения, значение по умолчанию.

Поведение: что происходит при нажатии кнопки; формулы; округление; что сохраняется между открытиями страницы.

Вывод: что показать и в каком виде — пример готовой строки результата. Кнопка «Скопировать результат» с подтверждением.

Валидация: что считать ошибкой и какое сообщение показать рядом с полем. Пока есть ошибки, результат не показывать.

Критерии готовности: три контрольных примера «ввод → точный ответ»; один граничный случай; работает на телефоне; в корне лежат index.html и README.md с описанием и контрольными примерами.

Кроме index.html и README.md, ничего не создавай. В отчёте перечисли, что сделано, и отдельно — что из ТЗ не выполнено, если такое есть. Сохрани результат сам, как в правилах.

Так не надо

«Сделай удобный калькулятор для бухгалтера, чтобы считать НДС и всё такое. Оформи красиво».

Какие поля, в какую сторону считать, как округлять, когда считать готовым — агент решит сам. Проверить его будет нечем.

Так надо

«Поля: сумма, ставка в %, направление — начислить или выделить. Округление до копеек. Пример: 100 000 ₽, 22 %, начислить → НДС 22 000,00 ₽, итого 122 000,00 ₽. Пустое поле — сообщение и никакого результата».

Даже коротко есть главное: поля, правило, пример для проверки.

Пример считайте сами до того, как отдадите ТЗ. Если вы не можете пересчитать результат на бумаге или в калькуляторе телефона, вы не сможете и проверить инструмент. Первый проект — тот, где правильный ответ вы знаете.

Проверьте себя

Чем инструмент на сайте отличается от ответа ИИ в чате?

  • Инструмент работает на более мощной модели
  • Правила записаны один раз в странице: её открывают по ссылке и вводят новые данные без ИИ, результат одинаковый
  • Инструмент сам дописывает себя, когда меняются правила

ИИ нужен, чтобы сделать или доработать страницу. Пользоваться ей можно без чата — и вам, и коллегам.

Коллега ввёл в калькулятор оклад сотрудника. Куда ушли эти данные?

  • В ваш репозиторий на GitHub
  • Агенту, который делал инструмент
  • Никуда: они остались в браузере коллеги

Страница без сервера считает всё в браузере. Публично только то, что лежит в самом репозитории, — поэтому реальных данных в коде и ТЗ быть не должно.

Какую идею нельзя сделать страницей на GitHub Pages?

  • Генератор претензии из полей формы
  • Напоминание на почту за три дня до окончания договора
  • Чек-лист онбординга с галочками, которые помнятся в браузере

Напоминание должно сработать, когда вкладка закрыта, — для этого нужен сервер. Остальное целиком живёт в браузере.

Без какой части ТЗ вы не сможете проверить инструмент?

  • Без описания цветов и шрифтов
  • Без контрольных примеров с заранее известным ответом
  • Без названия языка программирования

Пример «ввод → точный ответ» — единственный способ узнать, что инструмент считает верно, не читая код. Язык и оформление агент выберет сам.

Практика

Выберите инструмент для своей работы — из списка выше или свой — и заполните по нему шаблон ТЗ в заметках или в чате с ИИ. Оно понадобится в контрольной 6.

  • Инструмент проходит вопрос-проверку: данным не нужно встречаться на двух устройствах, ничего не должно происходить при закрытой вкладке.
  • В ТЗ есть цель одной фразой — кто и какую задачу решает.
  • Поля ввода перечислены по одному, с типом и допустимыми значениями.
  • Есть три контрольных примера с точными ответами; один я посчитал(а) сам(а).
  • В ТЗ нет реальных окладов, ФИО и реквизитов — только вымышленные числа.
  • ТЗ сохранено там, где я найду его в контрольной 6.

Вы знаете, что заказывать и как. В следующем уроке агент построит ваш первый инструмент в отдельном репозитории, а вы примете его как заказчик — на сайте, по контрольным примерам.

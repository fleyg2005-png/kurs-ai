Зачем GitHub, если сайт делает ИИ

Цель пути — свой сайт и рабочий инструмент как веб-страница по ссылке. Пишет его нейросеть, она же сохраняет все изменения. GitHub для вас — папка, где лежит сайт, и бесплатный адрес в интернете. Шесть минут — чтобы понять, кто что делает, и больше к этому не возвращаться.

Три вещи, ради которых нужен GitHub

Папка, где живёт сайт

Репозиторий — папка на GitHub с файлами сайта: страница, стили, картинки. Один сайт — один репозиторий. В курсе он называется hello-ai.

Память для нейросети

Обычный чат забывает всё, когда вы открываете новый. Агент каждый раз начинает с вашей папки: читает файлы сайта и правила для себя. Поэтому контекст не слетает: в новой сессии агент знает, какой у вас сайт и как с ним работать.

Адрес в интернете

GitHub Pages показывает папку как сайт по ссылке вида username.github.io/hello-ai. Без оплаты, домена и хостинга. Ссылку откроет любой человек с любого телефона.

Есть и четвёртая вещь, бонусом: GitHub помнит каждую версию каждого файла. Если агент испортил страницу, вы пишете ему «верни как было», и он достаёт прошлую версию из истории. Как это работает — в уроке 18.

Кто что делает

В пути «Сайт: git руками» ученик сам сохраняет версии, ведёт ветки и принимает правки кнопками на GitHub. Здесь цель та же, но вся эта работа на нейросети. Вам остаются пять разовых действий и задачи в чате.

Всё остальное — запросы в чате. Писать код не нужно, ставить программы на компьютер тоже: работа идёт в браузере.

Как выглядит работа

Задача в чате→ Агент правит файлы→ Сам сохраняет в main→ Сайт обновился→ Вы смотрите сайт

Вы пишете задачу, например «добавь на страницу раздел „Чем могу помочь“ с тремя пунктами». Агент меняет файлы, сам сохраняет их в репозиторий и пишет короткий отчёт. Через минуту-две раздел появляется на сайте. Вы открываете ссылку и смотрите: так или не так. Не так — пишете замечание в тот же чат, агент правит и снова сохраняет сам.

Проверяете вы сайт, а не код. Читать код и разбираться в нём не нужно.

Слова, которые встретятся в отчёте

Агент отчитывается языком программистов. Эти слова встретятся в его отчётах, делать с ними ничего не нужно. Достаточно понимать, о чём речь.

  • main — основная версия сайта. Что в main, то и показано по ссылке.
  • Коммит (commit) — одно сохранение с подписью: что изменилось.
  • Ветка (branch) — черновик рядом с основной версией, в нём агент делает задачу.
  • Pull request (PR) — заявка «перенеси черновик в main». Агент сам её создаёт и сам принимает.
  • Слить (merge) — перенести черновик в main. После этого изменение попадает на сайт.

Фраза агента «создал ветку, открыл pull request и слил его в main» по-человечески значит «сохранил, сайт скоро обновится».

Публичный — значит видно всем. Бесплатный сайт на GitHub Pages делается из публичного репозитория. Любой может открыть не только сайт, но и все файлы в папке. Поэтому правило на весь путь: никаких телефонов, адресов, паспортных данных, данных клиентов, паролей и ключей ни на странице, ни в файлах. Агент тоже получит это правило первым пунктом.

Вы неделю назад попросили агента сделать страницу о себе в одном чате. Сегодня открываете новую сессию и пишете: «добавь раздел с отзывами под список». Откуда агент узнает, какая у вас страница и где этот список?

Из репозитория. Страница лежит в папке hello-ai, агент открывает её в начале каждой сессии и видит список. Правила работы он берёт из CLAUDE.md в той же папке. Старый чат ему не нужен: всё важное уже в файлах.

Проверьте себя

Зачем в этом пути нужен репозиторий на GitHub?

  • Чтобы учиться сохранять версии и вести ветки руками
  • Это папка, где лежит сайт: агент берёт из неё контекст, а GitHub Pages показывает её по ссылке
  • Без репозитория нейросеть не отвечает в чате

Git здесь делает нейросеть. Вам репозиторий нужен как папка сайта и как память для агента между сессиями.

Агент пишет: «Создал ветку, открыл pull request и слил его в main». Что вам нужно сделать на GitHub?

  • Открыть pull request и подтвердить слияние
  • Удалить ветку, которую создал агент
  • Ничего: агент уже сохранил работу, через минуту-две откройте сайт и проверьте

Ветки и pull request — внутренняя кухня агента. Ваша часть работы — посмотреть на результат.

Что из этого вы делаете руками?

  • Создаёте файл index.html со страницей
  • Один раз включаете GitHub Pages в настройках репозитория
  • Пишете файлы правил для агента

Страницу и файлы правил создаёт агент по первому запросу. Pages — это настройка, а не работа с файлами, её включают один раз.

Что можно разместить на странице в публичном репозитории?

  • Скан паспорта, чтобы клиентам было проще оформить договор
  • Имя, профессию и то, чем вы можете помочь
  • Личный телефон и домашний адрес

Публичный репозиторий видят все. Можно то, что вы и так показали бы незнакомому человеку, остальное нельзя.

Практика

Подготовьте содержание первой страницы: в уроке 14 вы отдадите его агенту одним запросом. Запишите в заметках три-четыре строки.

  • Решил(а), как подписать страницу: имя или имя и фамилия, которые готов(а) показать всем.
  • Написал(а) одну строку о себе: профессия и чем занимаюсь.
  • Написал(а) три пункта для списка на странице: опыт, задачи, что хочу делать с ИИ.
  • Проверил(а): в тексте нет телефона, адреса, даты рождения и данных клиентов.
  • Проверил(а) тариф: есть Claude Pro, Max или Team, на них работает Claude Code.

Теперь понятно, кто что делает. GitHub — папка и адрес сайта, нейросеть — исполнитель, вы — заказчик, который смотрит на результат. Следующий шаг — аккаунт на GitHub: восемь минут по шагам.

Контрольная 5: две задачи и один откат

Без подсказок — полный цикл приёмки: две задачи агенту по очереди, две проверки с замечаниями и один откат просьбой. Всё это было в уроках 15–18. На GitHub вы только открываете файлы.

Задание

  1. Откройте новую сессию Claude Code: репозиторий shop, ветка main, окружение full, режим Auto. Работаете в Codex или Copilot — их pull request сливайте через Claude Code, как в уроке 16.
  2. Поставьте первую задачу (текст ниже) и дождитесь отчёта агента: что сделано, какие файлы, где результат.
  3. Проверьте результат по чеклисту урока 17: отчёт, ничего лишнего, сверка с файлами. Отправьте в сессию минимум одно замечание — ошибка или доработка — и добейтесь исправления; агент сохраняет сам.
  4. Только после этого — вторая задача: проверка, минимум одно замечание, исправление.
  5. Одну из задач отмените просьбой: «Отмени всё, что ты сделал в этой задаче». Убедитесь на github.com, что файлы вернулись.
Задача 1 — таблица жалоб
Прочитай otzyvy/otzyvy.csv и все карточки в tovary/ и создай файл zhaloby.md с таблицей: товар (имя файла карточки) — сколько отзывов с оценкой 1–3 — на что жалуются (цитаты из отзывов, до одного предложения каждая) — отвечает ли карточка на жалобу (да/нет; если да — цитата из карточки). Данные только из файлов; отзывов с оценкой 1–3 у товара нет — пиши «жалоб нет». Файлы в tovary/, otzyvy/ и README не менять. В отчёте напиши, как проверить таблицу за 5 минут.
Сохрани результат сам, как в правилах.
Задача 2 — частые вопросы в README
Прочитай otzyvy/otzyvy.csv и карточки в tovary/ и добавь в конец README.md раздел «Частые вопросы покупателей»: вопросы из текстов отзывов — товар — ответ по карточке; ответа в карточке нет — так и пиши «в карточке ответа нет», ничего не придумывай. Остальные разделы README, файлы в tovary/ и otzyvy/ не менять. В отчёте перечисли вопросы и укажи, из какой строки otzyvy.csv взят каждый.
Сохрани результат сам, как в правилах.

Критерии приёмки

Отмечайте только то, что проверили. Чеклист и квиз ниже засчитывают контрольную автоматически.

  • В обеих задачах есть «файлы в tovary/ и otzyvy/ не менять», «данные только из файлов» и последняя строка «Сохрани результат сам, как в правилах».
  • По каждой задаче агент написал отчёт: что сделано, какие файлы, где результат; изменены только zhaloby.md в первой и README.md во второй, ничего из tovary/ и otzyvy/.
  • По каждой задаче — минимум одно моё замечание в сессии; агент исправил и сохранил сам, правка видна на github.com.
  • Три значения сверены с файлами: цитаты жалоб и число отзывов 1–3 — по otzyvy.csv, ответы — по карточкам; где данных нет — «жалоб нет» или «в карточке ответа нет».
  • Результаты открыты на github.com: zhaloby.md и раздел вопросов в README на месте.
  • Одна задача отменена просьбой: агент вернул файлы как были; zhaloby.md исчез (или раздел вопросов пропал из README) — я проверил(а) на github.com.
  • Ветки, pull request и откат сделал агент: на GitHub я ничего не нажимал(а), только открывал(а) файлы.

Проверка понимания

Агент написал: «Готово. Сохранил в main: zhaloby.md». Где результат?

  • Только в чате сессии
  • В репозитории: файл открывается на github.com, агент уже сохранил его сам
  • В отдельной ветке, которую нужно слить кнопкой на GitHub

«Сохранил в main» значит «готово, лежит в репозитории». Ветки и слияние агент сделал сам.

Как убедиться, что агент не тронул лишнего?

  • Прочитать код программы
  • Прочитать в отчёте, какие файлы изменены, при сомнении спросить полный список; файлов из tovary/ и otzyvy/ там быть не должно
  • Никак: остаётся доверять

Правило 8 требует, чтобы агент перечислял изменённые файлы. Вопрос «что ты изменил в этой задаче?» снимает сомнения.

Где оставить замечание, чтобы агент исправил?

  • Комментарием к строке на GitHub
  • Сообщением в ту же сессию: файл, строка, что не так и как должно быть
  • В новом issue

Сессия хранит контекст задачи. Агент исправит и снова сохранит сам.

Результат задачи оказался плохим. Как вернуть файлы?

  • Загрузить старые версии файлов через Upload files
  • Никак: история хранится только у программистов
  • Попросить агента: «Отмени всё, что ты сделал в этой задаче» — он найдёт прошлые версии в истории и сохранит их сам

История хранит каждое сохранение. Ручная загрузка старых файлов — новые ошибки; просьба агенту — точный возврат.

Две сессии правили README одновременно; вторая пишет, что не смогла слить из-за конфликта. Что делать?

  • Найти на GitHub кнопку разбора конфликтов и выбрать строки вручную
  • Попросить Claude объединить обе версии и сохранить; дальше — одна задача за раз
  • Запустить обе задачи ещё раз одновременно

«Одна задача за раз» снимает конфликты. Если он случился, объединить версии — работа агента.

Какая ситуация — красный флаг: результат принимать нельзя?

  • Агент назвал столбец «Оценка» вместо «Средняя оценка»
  • Агент добавил в отчёт список прочитанных файлов
  • Агент пишет, что не смог разобрать otzyvy.csv, и проставил число отзывов и оценки примерно

Числа без источника — выдумка. Первые два — повод для замечания, но не опасность.

Откат вернул не то

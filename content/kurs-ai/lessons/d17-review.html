Проверить результат и оставить замечания

Агент сделал задачу и сам сохранил результат. Код читать не нужно — нужно принять работу как у помощника: прочитать его отчёт, сверить результат с первоисточником и написать замечания в ту же сессию. Разберём на README из урока 15.

Что вы проверяете на самом деле

Проверка отвечает на три вопроса: сделано ли то, что просили; не задето ли лишнее; нет ли опасного. Для задач по документам все три решаются без программирования.

  • Отчёт агента — что он сделал, какие файлы создал или изменил, где лежит результат. Это пишется в конце каждого ответа: так велит правило 8 в CLAUDE.md.
  • Сам результат против документов — таблица в README, которую вы читаете как юрист и сверяете с договорами.
  • Ничего лишнего не изменено — договоры, чеклист и шаблоны остались как были.

Ваше преимущество — вы знаете договоры. Агент не знает, что пустая строка с датой в шапке означает «не указано», а не «возьми дату из пункта о передаче».

Как замечание дойдёт до агента

Вернитесь в сессию на claude.ai/code и напишите замечание в чат. Агент поправит и снова сохранит сам, по правилам из CLAUDE.md. Сессию закрыли — откройте новую и начните сообщение с того, о какой задаче речь: «В README таблица договоров, которую ты сделал вчера…».

Пока вы не нажали Create PR в Codex, пишите замечание в ту же задачу на chatgpt.com/codex: в ней уже есть весь контекст. Результат уже слит через Claude Code — замечание пишите Claude Code, он поправит и сохранит.

Copilot принимает замечания комментариями на GitHub, а этого в нашем пути нет. Поэтому так: попросите Claude Code слить pull request от Copilot (урок 16), а замечание напишите Claude Code — он поправит и сохранит.

Три готовых запроса

Запрос к агенту — откуда значения
Объясни, что ты изменил в этой задаче и откуда взял каждое значение: для каждой строки таблицы в README — файл договора и цитата, из которой взяты стороны, предмет, дата и срок действия. Где в договоре данных нет — так и напиши. Ничего не меняй.
Запрос к агенту — самопроверка
Проверь сам свой результат как придирчивый юрист: где ты додумал, обобщил или взял значение не из текста договора? Для каждого такого места укажи строку таблицы, что написано и что в договоре на самом деле. Исправь, перечисли, что исправил, и сохрани результат сам, как в правилах.
Запрос к агенту — точечная правка
Исправь только строку про договор поставки (contracts/dogovor-postavki.md): дата и срок действия — дословно из текста договора; если в тексте их нет — «не указано». Остальные строки таблицы и другие файлы не трогай. Сохрани результат сам, как в правилах.

Чеклист проверки

Шесть пунктов на любую задачу по документам.

  • Есть отчёт агента: что сделано, какие файлы созданы или изменены, где результат.
  • Ничего из contracts/ не изменено: в отчёте только файлы, разрешённые в задаче.
  • Данные только из текста: стороны, даты и сроки сверены минимум по двум договорам; где в документе пусто — «не указано».
  • Нет ФИО, реквизитов, сумм и названий, которых не было в документах.
  • Нет внешних сервисов и отправки документов куда-либо — ни в отчёте, ни в ответах агента.
  • Замечания отправлены в сессию; агент поправил, сохранил, и я увидел(а) правку на github.com.

Красные флаги

Увидели любой — не отдавайте результат дальше, пока агент не уберёт причину.

  • Тронул документы. В отчёте рядом с README — файлы из contracts/, переименованные или удалённые договоры. Пишите: «Верни документы в contracts/ как были и больше их не трогай» (урок 18).
  • Нет отчёта. Агент ответил «готово» и не назвал файлы — или пишет, что сохранить не получилось, без объяснений. Просите отчёт по правилу 8: что сделано, какие файлы, где результат.
  • Факты не сходятся. Дата, сумма или сторона в таблице не находятся в договоре поиском. Замечание с цитатой из договора.
  • Додумал. Агент пишет: «не смог прочитать .docx, заполнил таблицу по названию файла», или в таблице правдоподобная дата там, где в договоре пусто. Это выдумка: пусть поставит библиотеку для чтения .docx и повторит — либо «не указано» по всем полям договора.
  • Предлагает отправить документы во внешний сервис — «загрузим в онлайн-конвертер». Документы не покидают репозиторий и машину агента.

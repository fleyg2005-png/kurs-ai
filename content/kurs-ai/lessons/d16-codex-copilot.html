То же в ChatGPT (Codex) и Copilot

Основной инструмент курса — Claude Code. Но ту же задачу, слово в слово, умеют выполнять ещё два агента: Codex в ChatGPT и облачный агент Copilot на GitHub. Это запасной вариант на случай, если Claude недоступен или в команде уже есть другая подписка. Одно отличие важно знать заранее: оба оставляют результат pull request'ом и сами его в main не сливают. Как и тогда ничего не нажимать на GitHub — в этом уроке.

Одна задача — любой агент

Агенты различаются кнопками, а не языком общения. Задача описывает результат — что прочитать, что написать, чего не трогать, что сообщить в отчёте — и ничего не говорит о том, кто её выполняет. Поэтому текст из прошлого урока отдаём без единой правки:

Задача агенту — та же, что в прошлом уроке
Прочитай все файлы в репозитории. Ничего в документах не меняй.
Сделай две вещи:
1. Перепиши README.md: что лежит в репозитории, список договоров таблицей (файл — стороны — предмет — дата — срок действия; данные бери только из текста, если чего-то нет — ставь «не указано»).
2. В конце README предложи 3 задачи, которые ты можешь выполнить по этим документам автоматически, с оценкой: что получится на выходе.
В отчёте напиши, какие файлы ты прочитал и что в них непонятно.
Сохрани результат сам, как в правилах.

Codex и Copilot прочитают те же правила из AGENTS.md: не трогать договоры, никуда не отправлять файлы. Задачу они сделают и результат подготовят, но последнего шага — слить его в main — не сделают.

Честно о главном отличии

⭐ Самое важное в этом уроке

Codex и Copilot результат не сливают. Они тоже работают с вашим репозиторием, но изменения оставляют pull request'ом — заявкой «перенести в main» — и ждут. Чтобы ничего не делать на GitHub руками:

  • в Codex нажмите его кнопку Create PR — это кнопка в самом Codex, а не на GitHub;
  • слить попросите Claude Code в его сессии: «Слей открытый pull request от Codex в main и удали его ветку»;
  • в Copilot задачу пишут в issue и назначают Copilot — это как написать задачу. Его pull request сливается так же, через Claude Code.

README уже переписан Claude, и это не мешает, а помогает: второй агент сделает то же по-своему, и вы впервые сравните два результата — у кого таблица полнее, кто честнее ставит «не указано». Сравнивать удобно через Claude Code: он покажет README второго агента прямо в чате.

Два агента — два пути

Нужен ChatGPT Plus ($20/мес), Pro или Business — на Free и Go агента нет. Если вы подключали Codex в уроке 14, шаги 2–5 уже сделаны. Откройте chatgpt.com/codex в соседней вкладке.

Перейдите на chatgpt.com/codex. В приложении ChatGPT тот же раздел: Codex → Work in → Cloud; на телефоне — раздел Codex.

Нажмите Connect GitHub. GitHub предложит установить приложение Codex на ваш аккаунт и спросит, какие репозитории ему открыть: Select repositories → contracts. Тот же принцип, что у Claude GitHub App: приватный репозиторий агент видит только через своё приложение.

Select environment → Create environment → выберите contracts. Окружение создаётся один раз — дальше все задачи по этому репозиторию идут в нём.

Get started

Нажмите Get started. Codex сам изучает проект и ставит зависимости. В репозитории с документами программ пока нет, так что этап короткий.

Проверьте, что выбран нужный репозиторий, и нажмите Publish. Подтверждение Environment published — окружение готово.

Нажмите Start a new task, вставьте задачу из начала урока и отправьте. Обратите внимание: вы ничего не меняли в тексте.

Задача выполняется в изолированной среде с копией репозитория, обычно от 1 до 30 минут. Codex показывает, какие файлы изменил, и записи о своих действиях — видно, как он читает папку contracts/. Построчно это читать не нужно: посмотрите только список файлов. Изменённый файл должен быть один — README.md. Есть другие — напишите замечание в ту же задачу: «Верни файлы в contracts/ как были, меняй только README.md».

Когда результат устраивает, нажмите в Codex кнопку Create PR. Это кнопка самого Codex, на GitHub идти не нужно. Codex откроет pull request в вашем репозитории и на этом остановится: в main пока ничего не изменилось.

Сверьте таблицу Codex с договорами, как в прошлом уроке. Версия Codex лучше — сливайте; лучше версия Claude — закрывайте без слияния. Одна фраза:

Закрой открытый pull request от Codex без слияния и удали его ветку. README в main не меняй.

Codex на GitHub. Codex также есть в GitHub Agent HQ: его можно назначить на issue так же, как Copilot на следующей вкладке. Результат и там приходит pull request'ом, и сливает его тоже Claude Code.

Нужен Copilot Pro — $10/мес; бесплатно для студентов, преподавателей и мейнтейнеров популярных open source-проектов. Агент живёт на GitHub: задачу ему пишут в issue — это как карточка задачи, — а результат он оставляет pull request'ом.

Вскоре Copilot создаст pull request и напишет в нём план в виде чеклиста, отмечая пункты по мере работы. Работает он в GitHub Actions — облачных машинах GitHub. Можно уйти. Закончив, Copilot попросит у вас ревью — отвечать на это на GitHub не нужно: дальше работает Claude Code.

Новая сессия на claude.ai/code: окружение full, contracts, main, Auto. Тот же порядок, что для Codex: сначала «Покажи README.md из открытого pull request от Copilot целиком прямо здесь, в чате, и скажи, чем он отличается от README в main. Ничего пока не сливай». Проверьте две вещи: в таблице столько строк, сколько файлов в contracts/, и данные совпадают с договорами. Затем одна из двух фраз:

Запрос к Claude Code — слить
Слей открытый pull request от Copilot в main и удали его ветку.
Запрос к Claude Code — не сливать
Закрой открытый pull request от Copilot без слияния и удали его ветку. README в main не меняй.

Issue после слияния закроется сама. Нашли в таблице Copilot мелкую ошибку — слейте и попросите Claude Code поправить строку в той же сессии: Copilot принимает замечания комментариями на GitHub, а этого в нашем пути мы не делаем.

Проверьте себя

Какой тариф ChatGPT нужен для Codex?

  • Любой, включая Free
  • Go и выше
  • Plus, Pro или Business

На Free и Go Codex недоступен. Минимальный тариф с агентом — Plus за $20/мес.

Как запустить облачного агента Copilot?

  • Создать issue с задачей и назначить его на Copilot в блоке Assignees
  • Написать задачу в комментарии к последнему коммиту
  • Открыть README и нажать кнопку Copilot

Назначение issue на Copilot — и есть запуск, как написать задачу. Агент сам создаст pull request с планом; слить его вы попросите Claude Code.

Что нужно изменить в тексте задачи, переходя от Claude Code к Codex или Copilot?

  • Убрать пункт про отчёт — другие агенты его не пишут
  • Ничего: задача описывает результат и границы, а не исполнителя
  • Переписать на английский

Хорошая задача говорит, что прочитать, что сделать, чего не трогать и что написать в отчёте. Всё это одинаково для любого агента.

Codex закончил задачу. Как результат попадёт в main, если на GitHub вы ничего не нажимаете?

  • Codex сам сливает результат, когда задача завершена
  • Нажать Create PR в самом Codex, затем попросить Claude Code: «Слей открытый pull request от Codex в main и удали его ветку»
  • Никак: с Codex без кнопок на GitHub не обойтись

Codex оставляет результат pull request'ом и сам его не сливает. Кнопка Create PR — в интерфейсе Codex, а слияние одной фразой делает Claude Code.

Как сравнить README от Codex с версией Claude, не открывая pull request на GitHub?

  • Скачать репозиторий на компьютер
  • Попросить Claude Code показать README из pull request прямо в чате и сказать, чем он отличается от main
  • Сравнить нельзя, можно только сразу слить

Агент может показать любой файл текстом в чате. Вы сверяете результат с договорами и решаете: слить или закрыть без слияния.

Практика

Пройдите один из двух путей до pull request и сравните README второго агента с версией Claude: у кого таблица полнее, чьи три предложенные задачи вы бы поручили.

  • Я выбрал(а) агента под свою подписку и прошёл(ла) по степперу до pull request.
  • Агент получил задачу слово в слово — ту же, что Claude Code в прошлом уроке.
  • По отчёту агента изменён только README.md.
  • Claude Code показал мне README второго агента в чате, и я сверил(а) таблицу с файлами в contracts/.
  • По моей просьбе Claude Code слил pull request в main или закрыл его без слияния — и я могу назвать одну причину своего решения.

Теперь вы умеете работать с любым из трёх агентов и ни разу не нажали на GitHub кнопку слияния. Следующий урок — как проверять результат и писать замечания так, чтобы агент понял с первого раза.

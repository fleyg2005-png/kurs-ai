Репозиторий с контентом и отчётами для ИИ

Восемь минут — и у вас есть приватный репозиторий marketing с вашими постами. Вы делаете три вещи: создаёте репозиторий, готовите посты (и, если есть, выгрузку кампаний) и загружаете их кнопкой Upload files. Служебные файлы — чеклист, шаблон отчёта, правила для агента — создаст сам агент в следующем уроке. Войдите на github.com в соседней вкладке и идите по шагам.

Что получится

Это сквозной проект курса: все задачи агентам в следующих модулях — про этот репозиторий. Часть файлов кладёте вы, часть по первому запросу создаст агент:

Кладёте вы, в этом уроке: README.md — описание (его создаст GitHub) posts/ — 3–5 постов (.md): anons-vebinara.md, post-keis.md, post-akciya.md… в каждом — шапка (дата, площадка, цель) и текст campaigns/campaigns.csv — своя выгрузка кампаний, если есть Создаст агент, в уроке 14: AGENTS.md, CLAUDE.md — правила для агента: персональные данные, что не трогать, как сохранять работу checklist.md — чеклист поста (10 пунктов проверки) templates/otchet.md — шаблон отчёта за месяц campaigns/campaigns.csv — учебная выгрузка, если своей нет posts/post-rassylka.md — письмо рассылки, контрольный пример для модуля 6

В постах не раз встретится UTM-метка — хвост ссылки вида ?utm_source=…, по которому в статистике видно, откуда пришёл человек: из поста в Telegram, из письма или из рекламы. Пока достаточно знать, что ссылка в посте должна нести метку; проверять это будет инструмент в модуле 6.

Папку reports/ и сводную таблицу summary.md позже тоже создаст агент — в модуле 6. Сейчас нужны только ваши посты.

Commit changes — это просто «сохранить»

Нажатие Commit changes создало коммит — сохранённую порцию изменений с подписью, которую вы видите в истории. Ничего больше за этим словом нет: «сохранить файлы и подписать, что сделано». Подпись годится любая понятная.

Загрузка через Upload files — единственное, что вы сохраняете на GitHub сами: новые посты и свежие выгрузки вы и дальше будете класть так же. Всё остальное с урока 14 сохраняет агент: получает задачу, делает работу и сам записывает результат в репозиторий с подписью.

Почему Private и что это значит для агента

Приватный репозиторий видят только вы и те, кого вы добавили. Для рабочих файлов — несогласованных постов и клиентских выгрузок — единственный разумный выбор. Следствие: ИИ-агенту он тоже не виден, пока вы не дадите доступ. Публичные репозитории Claude Code видит сразу после входа через GitHub, а для приватного нужно установить приложение Claude GitHub App и выбрать в нём ваш аккаунт и репозиторий marketing; у Codex для этого своё приложение. Как это сделать — в следующем уроке.

Что убрать перед загрузкой. Файлы будет читать агент на своей облачной машине. Посты и статистику кампаний можно загружать как есть, а персональные данные людей — нет: имена, почты и телефоны клиентов и подписчиков из CRM. Если договор с клиентом запрещает передавать его данные сторонним сервисам — уберите и название клиента с бюджетами. Перед загрузкой пройдитесь поиском по каждому файлу. Если данные всё же попали в репозиторий, удалить файл мало: старая версия остаётся в истории. Проще удалить репозиторий целиком — Settings → внизу страницы Delete this repository — и создать заново.

Проверьте себя

Почему репозиторий marketing сделан приватным?

  • Приватные репозитории агент обрабатывает быстрее
  • В нём рабочие файлы — несогласованные посты и выгрузки: приватный репозиторий видят только вы и те, кого вы добавили, а агенту доступ даётся отдельно через приложение
  • Публичные репозитории на бесплатном тарифе недоступны

И публичные, и приватные репозитории бесплатны. Разница — кто видит файлы: публичный — все, приватный — только вы и те, кому открыт доступ.

Что делает кнопка Commit changes при загрузке постов?

  • Отправляет посты ИИ-агенту на проверку
  • Публикует посты на площадке
  • Сохраняет файлы в репозиторий и записывает это в историю с подписью

Здесь коммит — просто «сохранить с подписью». Публиковать посты из репозитория никто не будет: это ваша работа за его пределами.

Зачем в ссылке поста UTM-метка?

  • По метке в статистике видно, откуда пришёл человек; без неё переходы из поста не отличить от остальных
  • Метка делает ссылку короче и аккуратнее
  • Без метки ссылка не откроется у части подписчиков

UTM-метка — хвост ссылки вида ?utm_source=…. Ссылка работает и без неё, но статистика перестаёт отвечать на вопрос «откуда пришли люди».

Как в репозитории появилась папка posts?

  • Через кнопку New folder в меню Add file
  • Вы перетащили папку posts целиком в окно Upload files, и GitHub сохранил её вместе с файлами
  • Папки в репозитории может создавать только ИИ-агент

Upload files принимает и файлы, и папки целиком. Если файлы легли не туда, разложить их по папкам можно поручить агенту.

Кто создаст checklist.md, шаблон отчёта и правила для агента AGENTS.md и CLAUDE.md?

  • Вы, через Add file → Create new file
  • Агент, по первому запросу в уроке 14: тексты этих файлов уже вписаны в запрос
  • GitHub создаёт их автоматически вместе с README

Ваша часть — посты и выгрузки. Служебные файлы агент создаст сам и сам сохранит их в репозиторий.

Практика

Если шли по степперу — всё сделано. Проверьте результат по списку и добавьте то, чего не хватает.

  • Репозиторий marketing существует, рядом с именем значок Private, адрес — github.com/мой-username/marketing.
  • В корне есть README.md, созданный GitHub.
  • В папке posts/ 3–5 постов с шапкой «дата, площадка, цель», каждый открывается в браузере как текст.
  • Если у меня есть своя выгрузка — в campaigns/ лежит campaigns.csv с колонками «кампания; показы; клики; расход». Нет — учебную создаст агент.
  • Ни в одном файле нет персональных данных людей — имён, почт и телефонов клиентов и подписчиков. Я проверил поиском по каждому файлу.

Рабочая папка готова, посты на месте. В следующем уроке вы подключите репозиторий к Claude, и агент первым же запросом создаст в нём чеклист, шаблон отчёта и свои правила.

Финальная контрольная: ваш инструмент в работе

Без степперов, подсказок и готовых ТЗ: сделайте сами второй инструмент для своей работы с маркетплейсом — не тот, что в модуле 6. Вы одновременно заказчик, проверяющий и приёмщик. Закладывайте около часа без учёта ожидания агента.

Задание

  1. Выберите инструмент — другой, чем проверка карточек по чеклисту (идеи — в таблице урока 23). Убедитесь вопросом из урока 23, что ему не нужно работать без вашего сообщения агенту и хранить данные от нескольких людей.
  2. Создайте новый приватный репозиторий с README и загрузите в него 3–5 своих рабочих файлов без персональных данных покупателей — карточки товаров, выгрузку отзывов или продаж — через Add file → Upload files. Дайте агенту доступ: для Claude — установите Claude GitHub App на этот репозиторий, для Codex — выберите его при подключении GitHub.
  3. Первый запрос — как в уроке 14: попросите агента создать в новом репозитории AGENTS.md и CLAUDE.md. Возьмите текст из CLAUDE.md репозитория shop, поправьте имена папок под свои и оставьте блок «Как сохранять работу» целиком. В запросе обязательна строка: «Ветки и pull request создавай сам и сразу сливай в main — я на GitHub ничего не нажимаю».
  4. Напишите ТЗ по шаблону урока 23 своими словами: что есть, что сделать (программа, запуск, результат в репозитории, README), ограничения, критерии готовности с проверяемым примером по конкретной карточке или строке выгрузки. Сохраните ТЗ в заметках. Последняя строка ТЗ — «Сохрани результат сам, как в правилах».
  5. Отдайте ТЗ агенту в новой сессии Claude Code — окружение full, режим Auto. Дождитесь отчёта, откройте результат на github.com и сверьте его с файлом из критерия готовности. Codex или Copilot тоже подойдут — их pull request слейте просьбой к Claude Code (урок 16).
  6. Проведите минимум две итерации с замечаниями по чеклисту урока 22: каждое — сообщением в сессию, конкретный пример «карточка → ожидал → получил» плюс фраза «ничего другого не меняй». Агент исправляет и сохраняет сам; проверяйте каждую правку на github.com.
  7. Загрузите 1–2 новых файла через Upload files и попросите агента запустить инструмент снова. Проверьте, что по новым файлам результаты появились, а старые не изменились по содержанию.
  8. Приведите README в порядок — задачей агенту: разделы «что делает», «как пользоваться», «чего не учитывает».
  9. Напишите «защиту» из пяти предложений: что делает инструмент, кому полезен, что агент сделал плохо, как вы это исправили, что проверили вручную. Отправьте коллеге вместе с доступом к репозиторию или с выгрузкой результата — скачанной таблицей или отчётом.

Проверка понимания

Чего не хватает в запросе «Проверь эту карточку»?

  • Вежливого обращения к ИИ и благодарности в конце
  • Названия модели, которая должна отвечать
  • Роли и контекста (что за товар, для чего готовится карточка), задачи (что именно проверить), формата ответа и ограничений: цитировать, не додумывать

Без контекста и формата ИИ сам решит, что считать проблемой, и ответит общими словами. Запрос из роли, задачи, контекста, формата и ограничений даёт проверяемый ответ.

В summary.md инструмент пишет для термокружки: «32 отзыва, средняя оценка 4,9». Что вы делаете перед тем, как отправить таблицу владельцу магазина?

  • Открываю otzyvy/otzyvy.csv, отбираю строки термокружки и сверяю число отзывов и среднюю оценку
  • Доверяю: программа читала выгрузку целиком, а я нет
  • Спрашиваю агента «ты уверен?» и отправляю, если он подтвердит

Программа может взять не те строки или посчитать среднюю оценку по всем товарам вместо одного. «Ты уверен?» — не проверка. Первоисточник — выгрузка.

В отчёте агента: «Создал ветку, открыл pull request и слил его в main». Что вам с этим делать?

  • Найти на GitHub этот pull request и подтвердить слияние кнопкой
  • Ничего: так агент сохраняет работу. Я открываю результат в репозитории и сверяю его с файлами
  • Попросить агента удалить ветку, иначе результат не появится

Ветки, pull request и слияние — слова из отчёта нейросети. Всё это она делает сама, от и до, по правилам 6–9 из CLAUDE.md; ваша часть — проверка результата.

Вы делаете свод продаж и хотите загрузить в репозиторий выгрузку заказов с ФИО, телефонами и адресами доставки покупателей. Почему нельзя, даже если репозиторий приватный?

  • GitHub не принимает файлы .csv
  • Это персональные данные покупателей: они не должны уходить ни на GitHub, ни в машину агента, приватность репозитория этого не меняет. Карточки, цены и остатки загружать можно
  • Агент не умеет читать выгрузки, в которых есть адреса

Приватность защищает от посторонних на GitHub, но файлы всё равно покидают вашу компанию: лежат на серверах GitHub и обрабатываются в машине агента. Правило урока 09 действует и здесь.

Где выполняется программа, которую агент написал для вашего репозитория?

  • На вашем компьютере — поэтому сначала там нужен Python
  • На серверах GitHub при каждом открытии репозитория
  • В облачной виртуальной машине агента: он ставит там библиотеки, запускает программу на файлах репозитория и сам сохраняет результат в репозиторий

Вы ничего не устанавливаете. Агент забирает копию репозитория в свою машину, запускает программу там и сохраняет результат. Файлы уходят только в эту машину и в ваш репозиторий.

Агент добавил в программу отправку текстов карточек на внешний сервис «для более точного подбора слов» и заодно переделал формат summary.md, хотя вы просили только добавить свод остатков. Ваши действия?

  • Не принимать: отправка файлов на чужой сервис — красный флаг; попросить убрать её и вернуть прежний формат summary.md как был, а свод сделать отдельной задачей
  • Оставить: точный подбор слов полезен, а к новому формату можно привыкнуть
  • Принять свод, а про сервис спросить потом

Файлы не должны уходить никуда, кроме машины агента и репозитория. Изменения вне задачи ломают то, что работало. Одна задача — одна сессия: так понятно, что проверять и что возвращать.

Если не получается

Программа есть, результатов в репозитории нет

Обычно в ТЗ не было слова «запусти». Напишите в ту же сессию: «Запусти программу у себя на всех файлах из папки … и положи результаты в …; в отчёте напиши, как проверить. Сохрани результат сам, как в правилах». Сессия закрыта — новая сессия с той же фразой и уточнением «программа уже лежит в репозитории, не переписывай её».

Результат не сходится с карточкой

Не чините сами и не пишите «работает неправильно». Опишите агенту пример: карточка, поле, что ожидали, что получили, — и добавьте «ничего другого не меняй». Перед этим убедитесь, что смотрите свежий результат: агент написал «сохранил в main», страница файла обновлена.

Агент не видит файлы

Проверьте три вещи: файлы загружены и видны на github.com; Claude GitHub App или приложение Codex установлено на новый репозиторий, а не только на shop; в селекторе репозитория выбран именно он, окружение — full. Агент видит только то, что лежит в репозитории, к которому у него есть доступ.

Если непонятно, где именно ошибка, — не угадывайте, спросите ИИ в обычном чате. Готовый запрос на примере свода цен и остатков:

Запрос к ИИ
Я менеджер маркетплейсов, не программист. Мой инструмент — программа на Python в приватном репозитории на GitHub; её написал и запускает ИИ-агент, я только ставлю задачи и проверяю результат. Инструмент собирает свод цен и остатков: читает карточки товаров из папки tovary/ и пишет таблицу svod.md с ценой и остатком по каждому товару.
Проблема: для карточки tovary/termos.md в столбце «остаток» стоит «не указано», хотя в карточке есть строка «Остаток: 8 шт.», а у остальных товаров остаток определился правильно.
Задача:
1) объясни, в чём, скорее всего, причина — простыми словами, без программистских терминов;
2) напиши текст замечания для ИИ-агента, чтобы он исправил только это и ничего другого не трогал;
3) предложи ещё два контрольных примера записи остатка, которые поймают ту же ошибку, если она вернётся.
Файл программы и карточку я прикрепил к этому сообщению из репозитория.

Поздравляем — это финал. Два инструмента для маркетплейса, сделанных по вашему заданию, и навык, который теперь не отнять: поставить задачу, проверить, принять. Остался один короткий урок — и сертификат: он появится на странице сертификата, когда все уроки отмечены пройденными.
